## 2. 목표와 비목표

**목표 (v4.0)**
1. v4a 의 처리 로직(적용 큐 직렬 쓰기 · reconcile 범위 · 관리 페이지 · 텔레그램 비상 명령 · 그룹 영상 근거 규칙 · 프리미어 제외 · LLM 판단 기록/반려 · 이벤트 배너)을 정식 배포판으로 만든다.

| B1 | 적용 큐 · 가공 큐를 **Cloud Tasks** 로 — `apply.py` 의 쓰기 스레드 대신 `/apply`, `enrich.py` 대신 `/enrich`(앱 안 OIDC 검증, 기존 `oidc.py` 재사용 가능 여부 [확인 필요]) | `max-instances=1` · `concurrency=1` 로 직렬 유지. **Cloud Run 은 초과 요청을 버퍼링하지 않고 429 를 낸다**(v3.9 사고) — 적재 쪽은 Cloud Tasks 가 재시도하므로 문제없지만, `/apply` 가 **한 번에 한 작업만** 받도록 설정이 맞는지 배포 후 실측 |

## 6. 운영자 결정 대기

1. **배포 형태**(A1) — ⓐ Cloud Run 으로 이전(설계 의도, 위 B 전부 필요) / ⓑ 로컬 PC 러너를 정식 운영으로 유지(B 생략, 대신 PC 24시간 가동 · Tailscale 단절·절전 위험을 감수). 문서 기록상 시험 기간의 "유실 허용"은 "배포하면 Tailscale 없이 GCP 에서 돌아가므로"가 전제였다(`pending_checks` §1) → ⓐ 가 원래 계획. **ⓑ 를 택하면 이 문서의 B·C 가 크게 줄고 위험의 성격이 달라진다.**
