## 5-1. 트윗 수명 = X 게시 시각 + 48h (10-01 운영자 결정) — **러너 재시작 뒤**

`xtweet.parse` 가 `posted_at`(Snowflake) 를 저장하고 `expires_at = posted_at + 48h`(게시 시각 모르면 받은 시각 + 48h).
관리 페이지 트윗 투입(자동 URL · 수동)은 게시 48h 지난 트윗이면 경고창 「게시된지 48시간이 지난 트윗입니다.」 후 거절(`admin_api._tweet_too_old`).
팬 화면 말풍선 아래 시각 = 게시 시각(게시 시각을 못 얻으면 「HH:MM 등록」), 정렬 · 묶음도 게시 시각. 하네스 B17 로 확인됨.

| 확인 | 기대 | 상태 |
|---|---|---|
| 재시작 뒤 새로 들어온 트윗의 `tweets.json` | `posted_at` 있음, `expires_at` − `posted_at` = 48h | **확인(10-01)** — 러너 `/data/tweets.json` 최근 8건(19:59~22:58 KST 수신) 모두 `posted_at` 있음 · 차이 48.0h |
| 관리 페이지에 48h 지난 트윗 URL | 경고창(브라우저 기본 alert) — 재시작 전엔 서버가 옛 코드라 안 뜬다 | 미확인 |
| 팬 화면 말풍선 아래 시각 | X 카드의 게시 시각과 같은 HH:MM (정적 파일이라 재시작 없이 새로고침으로 반영) | 미확인 |
| 유실 원문 재투입 — 게시 48h 지난 멤버 트윗 | 방송이 예정 · 라이브 · end 창(종료 + 30분) 안이면 재투입, 아니면 경고창 + 큐에 남김(`admin_api._lost_tweet_stale`, 하네스 B18). 커밋 이후 **러너 재시작 필요** | 미확인 |
