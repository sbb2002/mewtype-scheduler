# LLM 판단 반려 · 재판단 · 사용자 판단 — 7가지 판단별 시나리오 (2026-10-02)

관리 페이지 작업 탭 「최근 흐름 → LLM 판단」의 되돌리기를 **반려**로 바꾸고, 반려된 판단은 **LLM 재판단** 또는 **사용자 판단**으로 이어 가는 설계다.
운영자 결정(10-02): 재판단 프롬프트에 「반려됐다」 힌트를 넣는다 · 재판단 횟수 무제한(새 판단도 다시 반려 가능) · 7가지 전부 구현 ·
입력 원문이 기록되지 않은 옛 기록은 **재판단 불가**(사용자 판단만 허용).

## 0. 공통 규칙

| 단계 | 일어나는 일 |
|---|---|
| **반려** | 그 판단이 데이터에 한 변경이 있으면 **그것만** 원래대로 돌린다(롤백). 변경이 없는 판단(검토용 「아님」 판정)은 롤백할 것이 없고 표시만 「반려됨」으로 바뀐다. 그 뒤 다른 이유로 바뀐 항목은 건너뛴다. 같은 글을 자동으로 다시 판정하지는 않는다. |
| **LLM 재판단** | 기록해 둔 **입력(원문 · 태그 · 이미지 등)** 으로 같은 판정 함수를 다시 돌린다. 프롬프트 맨 앞에 「앞서 <판단 요약 · 근거> 로 판단했으나 운영자가 반려했다. 같은 결론을 반복하지 말고 다시 꼼꼼히 읽고 판단하라」를 붙인다. 결과는 평소 인입과 같은 경로로 반영하고, 새 LLM 판단 기록(`parent_id` = 반려한 기록)으로 남는다 — 새 기록도 다시 반려할 수 있다. DM · 모니터 로그는 재판단 표시가 붙은 채 남는다. |
| **사용자 판단** | LLM 대신 운영자가 결과를 고른다. 선택한 결과는 LLM 답을 **강제로 덮어쓴** 채 같은 반영 경로를 타고, 판단 종류 `user_review`(「사용자 판단」)의 새 기록(`parent_id`)으로 남는다. 마찬가지로 다시 반려할 수 있다. |
| **상태 표시** | 미처리 → `[반려]` · 반려됨 → `[LLM 재판단] [사용자 판단]` · 재판단됨/사용자 판단됨 → 결과 문구 + 새 기록 링크. 한 기록에서 재판단/사용자 판단은 **한 번**(다시 하려면 새 기록을 반려). |
| **재판단 불가** | 입력 스냅샷이 없는 옛 기록 · LLM 키 없음 · 원문이 필요한데 없음 → 버튼 비활성 + 이유 툴팁. 사용자 판단은 가능한 종류에서 허용. |
| **안전장치** | 롤백은 그 판단이 바꾼 항목만 · 상태 전이는 1회만(중복 클릭 방지) · 외부 호출(LLM · videos.list · vision)이 실패하면 데이터를 안 바꾸고 「실패」를 표시(반려됨 상태 유지, 다시 시도 가능). |

각 판단 기록은 `input`(재실행에 필요한 최소 입력)을 함께 저장한다. 7가지 판단은 두 방식으로 나뉜다:
**파이프라인 재실행**(banner · broadcast_change · notice · own_broadcast · participation)과 **전용 적용기**(collab_guest · ocr_members).

---

## 1. `banner_judge` — 행사 배너 판정 (게임 계정 글)

- **입력**: 원문 · 트윗 태그 · 첨부 이미지 · 작성자(게임 계정) · 글 게시 시각.
- **반려 시나리오**
  - `added`(새 행사) → 새 행사 배너 삭제. `updated` → 그 행사를 변경 전 상태로. `held` → 보류 해제(변경 전). `cancelled` → 보관에서 꺼내 되살림.
  - `none`/`dup`/`invalid`(검토용) → 롤백 없음, 표시만 반려됨.
- **LLM 재판단**: `banner_judge`(+ 이미지 있으면 비전 2단계)를 같은 입력 + 반려 힌트로 다시 → `apply_judgement` → 새 기록. 예) `none` 반려 → 이번엔 `upsert` 로 행사가 올라감 / `added` 반려 → 이번엔 `none` 으로 안 올라감.
- **사용자 판단**: 선택지 = **올리지 않음** / **직접 입력**(행사 이름 · 시작 · 종료 · 가챠를 쓰는 창, 반려된 LLM 값이 미리 채워짐). 직접 입력은 `upsert` 판정을 강제로 만들어 `apply_judgement`(검증 포함)를 탄다.
- **예외**: 비전 호출 실패 → 1단계 판정으로 진행 · 종료일 없음 → 대기(`pending`)로 저장되고 안 보임(기존 규칙 그대로).

## 2. `broadcast_change` — 방송 취소 · 일정 변경 판정 (멤버 개인 트윗)

- **입력**: 원문 · 멤버(channel_key) · 트윗 태그 · 판정 당시 후보 예고 목록(재판단 때는 롤백 뒤 현재 활성 예고로 다시 뽑는다).
- **반려 시나리오**
  - 취소(`restore_items`) → 지운 예고 되살림 + 재등록 차단 해제. 일정 변경(`restore_fields`) → 시각을 원래 값으로.
  - 「취소 · 변경 아님」(검토용) → 롤백 없음.
- **LLM 재판단**: `_maybe_broadcast_change` 를 같은 입력 + 힌트로 다시. 롤백으로 되살아난 예고가 후보가 되므로 「대상 재선택」이 된다.
- **사용자 판단**: **취소 적용**(대상 예고 체크) / **일정 변경 적용**(대상 체크 + 새 시각 KST) / **해당 없음**. 선택값이 LLM 계획(`plan`)을 대신해 같은 반영 코드(삭제 + 재등록 차단 · `apply_preview_edit`)를 탄다.
- **예외**: 후보 예고가 없음 → 「대상 없음」으로 끝(변경 없음) · 시각을 해석 못함 → 미반영(기존 규칙).

## 3. `collab_guest` — 합동 게스트 판정

- **입력**: 원문(또는 공식 스케줄 줄) · 호스트 멤버 · 게스트 후보 멤버 · 대상 예고(영상 id 또는 호스트 + 예정 시각).
- **반려 시나리오**
  - 게스트를 **더한** 판정(`remove_guests`) → 그 게스트를 뺌. 게스트 아님으로 **뺀** 판정(검토용) → 롤백 없음.
- **LLM 재판단**: `collab_partners` 를 같은 원문 · 후보 + 힌트로 다시 → 결과로 대상 예고의 `collab_with` 를 설정/해제(예고 수정과 같은 커밋). 대상 예고를 못 찾으면 「대상 예고 없음」으로 끝.
- **사용자 판단**: 후보 멤버 체크박스(체크 = 같이 나오는 게스트) → 대상 예고의 `collab_with` 를 그 값으로 확정(`kind` 도 합동/해제 동기화).
- **예외**: 대상 예고가 이미 내려갔거나 끝남 → 「대상 예고 없음」 안내, 변경 없음.

## 4. `duplicate_notice` — 소식 같은 행사 판정

- **입력**: 원문 · 트윗 태그 · 제목(표시명) — 롤백 뒤 후보는 현재 소식에서 다시 계산.
- **반려 시나리오**: 「기존 소식과 같음」으로 **병합**된 판정을 반려 → 병합된 기존 소식 행을 병합 전 모습으로 복원(들어온 글의 `seen_ids` · 갱신 필드가 빠짐). 들어온 글은 아직 별도 소식으로 안 올라간 상태.
  (판정 때 병합 전 행 스냅샷을 `undo`로 저장하도록 추가 — 지금은 undo 데이터가 없는 검토용이었다.)
- **LLM 재판단**: `_prepare_notice` + `_commit_notice` 를 같은 입력 + 힌트로 다시 → 이번엔 별개 소식으로 추가되거나 다른 기존 소식에 병합.
- **사용자 판단**: **기존 소식과 같음**(병합할 소식 선택) / **별도 소식으로 등록**.
- **예외**: 병합 대상 소식이 이미 만료 · 삭제됨 → 병합 선택지에서 빠짐, 별도 등록만.

## 5. `ocr_members` — 그룹 영상 출연 멤버 이미지 OCR 판정

- **입력**: 영상 id · 제목 · 첨부 이미지 링크 · 출처(작성자 채널 / 공식).
- **반려 시나리오**: OCR 판정으로 올린 그룹 영상 예고를 예고에서 빼고 **「참여 멤버 확인 대기」**로 옮김(기존 undo 그대로, LLM 제안 멤버는 대기 항목에 남음).
- **LLM 재판단**: 비전으로 이미지를 다시 읽어(힌트는 비전에 적용되지 않음 — 텍스트 LLM 이 아니라서) 멤버를 판독 → 판독되면 `resolve_group_pending` 으로 확정(예고 등록), 판독 실패면 대기에 그대로 둠.
- **사용자 판단**: 멤버 칩 선택(기존 「참여 멤버 선택」 팝업과 같은 UI) → `resolve_group_pending` 으로 확정. 「올리지 않음」 = 대기에서 뺌.
- **예외**: 비전 모델 한도(429)로 실패 → 대기 유지 + 「다시 시도」 안내.

## 6. `own_broadcast` — 본인 방송 예고 최종 확인 (URL 없는 텍스트 예고)

- **입력**: 원문 · 멤버 · 트윗 태그 · 인용 · 인입 경로.
- **반려 시나리오**
  - 「본인 예고로 등록」 → 등록한 예고를 지움(새 예고) 또는 합치기 전으로(기존 예고에 합쳤으면).
  - 「본인 예고 아님」(검토용) → 롤백 없음.
- **LLM 재판단**: `_maybe_personal_schedule` 를 같은 입력 + 힌트로 다시(정규식 후보 → LLM 최종 확인 → 등록).
- **사용자 판단**: **예고로 등록**(LLM 확인 단계를 건너뛰고 파서가 뽑은 날짜 · 시각으로 등록) / **등록 안 함**.
- **예외**: 정규식이 날짜 · 시각을 못 뽑음 → 「등록할 일정을 읽지 못함」(변경 없음, 예고 수정 창 안내).

## 7. `participation` — 외부 채널 영상 참여 판정

- **입력**: 원문 · 멤버 · 트윗 태그 · 인용 · 이미지 · 인입 경로 · 영상 URL(videos.list 로 다시 조회).
- **반려 시나리오**
  - 「참여로 판정 → 예고 등록」 → 등록한 예고를 지움(또는 합치기 전으로).
  - 「참여 아님」(검토용) → 롤백 없음.
- **LLM 재판단**: `_maybe_url_confirmed_schedule` 를 같은 입력 + 힌트로 다시(영상 정보 재조회 → 참여 판정 → 등록).
- **사용자 판단**: **참여로 등록** / **참여 아님**. 등록은 LLM 확인만 건너뛰고 나머지 검증(채널 · 영상 정보)은 그대로.
- **예외**: 영상 정보 조회 실패(`videos.list` 오류 · 삭제된 영상) → 「영상을 확인하지 못함」(변경 없음).

## 8. 구현 구조 (요약)

- 판정 기록 `input` = 파이프라인 진입 인자 스냅샷(원문은 2000자까지). 5개 파이프라인 함수에 진입 데코레이터 → `_llm_record` 가 자동으로 붙인다. collab_guest · ocr_members 는 전용 입력을 직접 넣는다.
- `llm_review` 컨텍스트(재판단 힌트 · 사용자 판단의 강제값 · DM 억제)를 두고, 7곳의 LLM 호출부가 강제값을 먼저 보고 없으면 LLM(+힌트)을 부른다.
- 새 API: 반려(`reject_llm_action`, 기존 undo) · `rejudge_llm_action` · `decide_llm_action`. 상태 전이는 한 번만.
- 시험: 7가지 각각 {반려 → 재판단 → 사용자 판단} 을 격리 하네스(`ref/v4a/verify/harness_c.py`)에서 가짜 LLM 으로 돌려 상태 · 기록 · 롤백 범위를 확인.
