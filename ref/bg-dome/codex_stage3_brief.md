## 1. 달 겉보기 크기 = 사람 눈의 실제 시야각 (운영자 지시)

> 달은 실제 시야각을 반영했지만 너무 작아. 실제 사람이 하늘을 봤을 때 보이는 시야각을 어느 기기에서든 똑같이 보여주도록, 왜곡되더라도 실제 시야각과 똑같이 보이도록 보정해야 해. 마찬가지로 확대 시 실제 육안을 배율 확대했을 때의 시야각을 바탕으로 확대해야 해.

- 지금은 원반 0.53° 를 화면 시야각(가로 약 43.6°)에 그대로 투영해 폰에서 지름 약 5 CSS px — 화면 자체가 눈에서 차지하는 각도가 43.6° 보다 훨씬 작아 실제보다 작게 보인다.
- **기준 = CSS 기준 픽셀의 정의**: CSS px 은 각도로 정의된 단위다(96dpi 를 팔 길이 28인치에서 본 1px ≈ **0.0213°**). 기기들은 devicePixelRatio 를 그 기준에 맞춰 둔다 → **원반 지름(CSS px) = 0.53° × 배율 / 0.0213° ≈ 24.9 px × 배율**. 화면 시야각 · 기기와 무관하게 이 크기로 그린다(하늘 투영과 어긋나는 「왜곡」은 허용 — 운영자 명시). 근거가 더 나은 기준이 있으면 쓰되 보고.
- **배율 ×N** = 육안 시야각 × N: 원반 지름 = 24.9 px × N. ×30 이면 약 747 px 로 화면보다 커진다 — 달 원반이 화면을 넘을 때의 처리(배율 상한 · 원반 채움 시 노출 · 질감 해상도 `moon-near.webp` 128px 로 부족하면 256/512 필요 여부)를 정해 보고. 지금 망원 줌 하늘 투영(시야각 좁히기)과 원반 크기가 따로 놀게 되므로, 달 위치 · 가림(지평선 · 산 · 건물) · 구름 · 광륜 · 고스트가 커진 원반에 맞게 따라가야 한다.
- **해는 지금 그대로**(운영자: 괜찮음). 달만.
- 1배 낮은 달(고도 0 ~ 10°)이 점으로만 보이던 문제는 이 보정으로 같이 풀리는지 2단계 결과와 함께 판단.
- `bgsize` 디버그 시안(now · real · double · window)은 정리하지 말고 둔다 — 새 기본을 넣고 시안은 비교용으로.

## 3. 테마 전환 효과 (새 요소)

> 테마 전환 시, 격자 천정부터 반시계방향으로 사이버펑크 느낌 나게 순서대로 빠르게 전환되는 효과를 넣어줘.

- 밝게 ↔ 어둡게를 누르면 돔 유리 격자가 **천정(꼭대기)부터** 시작해 **반시계방향으로 쓸면서** 칸(격자 면 · 선)이 차례로 새 테마 색으로 바뀐다. 사이버펑크 느낌 = 네온 빛 번쩍임 · 짧은 글리치/스캔 선 · 전환 가장자리의 밝은 띠 등. **빠르게**(전체 약 0.6 ~ 1초 안 — 값은 제안하고 근거).
- 반시계방향의 기준 = 위에서(천정 쪽을) 올려다본 화면 기준인지, 위에서 내려다본 기준인지 애매하면 **화면에 보이는 대로 반시계**로 하고 보고.
- 기존 테마 전환 경로: `theme.js` `_apply` · `THEME_EVENT`, `bgdomegl.js` 의 `data-theme` MutationObserver(`THEMES[theme]`). 돔 바깥 화면 요소(카드 · 시트)의 테마 전환 방식은 바꾸지 말 것 — 효과는 배경 돔에만.
- `prefers-reduced-motion` 이면 효과 없이 바로 바뀐다. 실내 · 바깥 보기 둘 다. 전환 중 다시 누르면 자연스럽게 이어지거나 끊기게.
