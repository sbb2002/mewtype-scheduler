**1.1초로 늘리고 패널을 ‘송신 중’ 상태로 만드는 수정에 동의한다. 다만 4번의 “지구에서는 바닥까지 바뀐다”는 전제는 현재 코드와 다르다.** 이번에는 공통 바닥·조종대를 유지하는 안으로 정리하겠다. 파일은 수정하지 않았다.

1. **패널 투명화: 동의하되, 칸 배경과 흐림도 함께 조절하자.**

   현재 `.ufo-card`는 배경 불투명도 `.78`에 뒤쪽 흐림 `10px`, 일반 칸은 별도로 배경 불투명도 `.55`를 가진다. 판만 `.35`로 낮춰도 칸 안에서는 두 배경이 겹쳐 약 `.71`의 배경 불투명도가 남는다. 흐림도 그대로면 가느다란 스캔 선을 알아보기 어렵다. [현재 패널 CSS](C:/Users/user/Documents/myprojects/mewtype-scheduler-worktrees/v4/feat-bg-dome/src/frontend/css/bgpanel.css:128)

   따라서 송신 중에는 **판 `.35`, 칸 배경 `.12~.18`, 글자·아이콘 불투명도 `1`**을 초깃값으로 제안한다. 뒤쪽 흐림은 전환 동안 끄고, 흐림 수치 자체를 매 프레임 바꾸지는 않는다. 밝은 구름 앞에서 작은 글자가 묻히면 글자 주변의 좁은 어두운 받침으로 보완한다.

   선택 칸의 **분홍 테두리는 유지**하고, 그 위로 짧은 시안 선이 한 번 이동하게 하자. 별도 반복 애니메이션보다 하늘 전환 진행률에 연결하면 둘이 같은 명령의 결과로 읽힌다. 패널 위치·크기·내용은 고정한다.

2. **900ms 하강 + 200ms 잔광: 동의한다.**

   이번 동작은 배경을 감상하는 중에 사용자가 의도적으로 일으키는 큰 장면 변화다. 선택 피드백이 즉시 보인다면, 장면 형성에 1.1초를 쓰는 것은 납득할 만하다. 기존 1.6초보다도 짧다. 패널 뒤에서 가려지는 구간을 고려하면 내 720ms안보다 변화의 시작과 끝을 확인하기 쉽겠다.

   단, **예열·패널 복귀 시간을 추가해 총시간을 늘리지는 말자.** 예열은 첫 80ms에, 패널 복귀는 마지막 200ms에 겹친다. 200ms 잔광은 정지한 빛이 약해지는 구간이며, 두 번째 광선이나 번쩍임은 넣지 않는다. S23에서 확인할 초깃값으로 1.1초에 합의한다.

3. **화면 좌표 Bayer 점무늬: 동의한다. 다만 이유는 바로잡겠다.**

   옛 사진이 화면 좌표라고 해서 돔 좌표의 점무늬가 반드시 어긋나는 것은 아니다. 사진을 읽는 좌표와 두 장면을 선택하는 무늬의 좌표는 달라도 된다. **곡선 경계는 돔 좌표, 작은 점무늬는 화면 좌표**로 나누는 것이 가능하다.

   화면 좌표를 추천하는 이유는 점의 크기와 위치가 일정해서, 카메라 각도에 따른 늘어짐과 반짝임이 적기 때문이다. **4×4 Bayer 배열의 각 칸을 3 CSS px로**, 즉 전체 무늬의 반복 주기를 **12×12 CSS px**로 명확히 정하자. 캔버스 좌표는 기기의 원래 배율이 아니라 실제 렌더링 배율인 `uDpr`로 나눈다.

   무늬는 경계 근처에만 보이고, 각 점은 한 번 교체된다. 경계와 함께 무늬 전체가 미끄러지거나 매 프레임 다시 뽑히지 않는다.

4. **실내끼리 고리에서 정지: 동의. 지구에서 바닥까지 교체: 현재 범위에서는 반대한다.**

   현재 지구 프로그램도 마지막에 **공통 무대 원판 바닥을 합성**한다. 조종대 표시도 실내·지구 구분 없이 배경 보기 상태를 따른다. 바뀌는 바깥 지형과, 발아래의 UFO 무대 바닥은 서로 다른 부분이다. [공통 바닥 합성](C:/Users/user/Documents/myprojects/mewtype-scheduler-worktrees/v4/feat-bg-dome/src/frontend/js/bgdomegl.js:782), [조종대 표시 조건](C:/Users/user/Documents/myprojects/mewtype-scheduler-worktrees/v4/feat-bg-dome/src/frontend/js/bgdomegl.js:1566)

   따라서 이번에는 지구도 **돔과 무대가 만나는 고리에서 전환을 끝내고 공통 바닥·조종대를 유지**하자. 실제 산 능선 같은 지형의 윤곽을 따라 멈추는 것은 아니다.

   내 1차의 ‘돔이 벗겨짐’이라는 표현도 **‘돔의 투영 영상이 걷혀 바깥이 보임’**으로 수정하겠다. 바닥까지 없어지는 야외 장면을 원한다면 그것은 전환 효과를 넘어 목적지 장면 자체를 바꾸는 별도 결정이다.

5. **6° 초과 시 150ms 안에 완료: 동의한다.**

   시작 시점 대비 **실제로 화면에 적용된 수평 회전각·상하 회전각 변화의 절댓값 합**으로 판정하자. 수평 각도는 ±180° 경계를 넘을 때에도 짧은 쪽 차이를 사용한다.

   문턱을 넘으면 곡선 경계를 급가속시키기보다, **남은 옛 화면과 발광을 최대 150ms 동안 약하게 지워 완료**한다. 원래 남은 시간이 더 짧으면 그 시간 안에 끝낸다. 판정은 한 번만 하며, 계속 움직인다고 완료 시각을 뒤로 미루지 않는다.

   두 손가락 확대·축소가 시작돼도 같은 단축 완료를 적용하고, 화면 크기가 바뀌면 즉시 완료한다. 각도 변화만으로는 이 두 가지 어긋남을 잡을 수 없다.

6. **테마 팝업의 CSS 전환 통일: 가치는 있지만 이번에는 패널의 하늘 선택까지만 하자.**

   UFO 안에서 하늘을 바꾸는 동작과 기본·UFO·생일이라는 시각 세계 전체를 바꾸는 동작은 규모가 다르다. 모든 테마 변경에 시안 송신 효과를 붙이면 UFO의 특징이 다른 테마에도 따라붙는다.

   구현상으로도 CSS 반복 그라데이션으로 만든 점무늬가 셰이더의 4×4 Bayer와 같아지려면 추가 설계가 필요하다. CSS 방식이라는 이유만으로 전체 화면 합성 비용이 작아지는 것도 아니다.

   **이번에는 기존 테마 팝업 전환을 유지**하고, 다음에 UFO 진입·이탈까지 함께 검토하는 편을 추천한다.

7. **8ms 진동 한 번·소리 없음: 동의한다. 시점은 선택을 수락한 클릭 순간으로 하자.**

   사진·위치를 기다린 뒤 진동하면 버튼을 눌렀다는 피드백으로는 늦다. 다른 목적지 선택을 수락했을 때 8ms 한 번, 준비 완료 때는 추가 진동 없이 화면 연출만 시작한다. 이미 선택된 칸을 다시 누르는 경우에는 진동하지 않는다.

   소리는 넣지 않는다. 이후 기어 조작의 ‘딩’과 역할도 분명해진다.

8. **초행성X 전환 완료 뒤 10% 판정·기어 1단: 동의한다.**

   여기서 완료는 **잔광과 패널 복귀까지 끝난 시점**, 기본적으로 1100ms다. 그전에는 우주를 정지 상태로 보여준다.

   현재 코드는 우주가 처음 그려질 때 `spaceT0`를 시작한다. 앞으로의 출발 시계와 확률 판정은 그 지점이 아니라 **하늘 전환 완료 처리**에 연결해야 한다. 또한 `BGINDOOR_EVENT`만 사용하면 실내 배경 값이 이미 우주인 상태에서 **지구 → 우주**로 돌아오는 경우를 놓칠 수 있다. 실제 우주 진입 완료를 공통 기준으로 삼자.

   판정은 진입당 한 번만 한다. 다른 목적지로 바뀌어 취소된 전환과 같은 칸 재선택에서는 실행하지 않는다. 시점 이동으로 단축 완료된 경우에는 완료 후 실행하되, 움직임 줄이기 설정에서는 자동 성간 이동을 시작하지 않는다.
