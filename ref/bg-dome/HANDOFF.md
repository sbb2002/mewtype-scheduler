## 동작 요약 (코드 = 정본, 여기는 지도)

**실내 보기**(기본)
- 처음 폰 자세가 정면. 평소 35% · 30fps 로 따라 돌고, 레인을 위로 튕겨 걷은 「배경 보기」(html.bg-peek) 중엔 100% · 60fps.
- 흔들면 무늬가 섞이고, 다 가라앉은 순간의 자세가 새 정면(그동안 화면이 천천히 정면으로 돌아온다).
- 하늘 = 분홍 구름 사진 한 벌(`dome-sky.webp` · `dome-clouds.webp`). 테마별 색 보정.

**바깥 보기**(테마 버튼 0.5초 길게 → 팝업)
- 고르는 순간 위치 권한 요청(iOS 는 방향 센서 권한도 같은 터치에서). 거절 → 실내로 되돌리고 「권한을 허용해야 쓸 수 있다」 안내, 이미 거절된 상태 → 「브라우저 설정에서 허용」 안내, 위치 실패(신호 없음 · 시간 초과) → 실내로 되돌림.
- 위치 = 저정밀 요청, 소수 1자리로 줄여 계산에만. 기기 밖 전송 · 저장 없음. 다음 방문엔 권한이 그대로일 때만 조용히 바깥 보기로 연다.
- 카메라 = 실제 방위 · 기울기 그대로(AR 방식 — 운영자 결정: 「실제 태양이 보이는 방향으로 보면 동일하게 보이길」). 기준점은 화면 정가운데(실내는 위쪽 40%). 35% 축소 없음, 흔들어도 정면 안 옮김. 나침반이 없으면 남쪽. (커밋 `8496f10` — 그 전엔 폰을 비스듬히 들면 해가 화면 맨 위 UI 밑에 가려졌다. 폰 실측으로 방위는 해와 5° 이내였다)
- 하늘 = 해 고도로 이미지 한 벌씩 섞음: 실제 낮 `daylight` 12° → 노을 `twilight` 0°(해가 올라가는 중이면 여명 `dawn`) → 박명 `bluehour` -6° → 밤 `night` -12°.
- 해 · 달 · 별: 1초마다 위치 계산. 달 위상 · 기울기는 해 방향으로 자동. 해 · 달 색은 고도 · 뜨는/지는 중 · 남중 근접으로 이어서 바뀐다(색 설계 = Codex, `codex_grade_result.md`). 보름달이 높으면 밤하늘이 밝아지고 별이 준다. 별은 항성시로 돈다.

**성능 장치**: 카메라가 멈춰 있으면 구름 흐름만 초당 6번 다시 그림, 해상도 기기 배율 1.5 까지, 탭 숨김 · 생일 장면 · 움직임 줄이기에서 정지. WebGL2 실패 시 SVG 장면으로 물러나 페이지는 계속 동작.

## 확인 방법

```bash
cd mewtype-scheduler-worktrees/v4/feat-bg-dome
python scripts/serve_local.py 8102                  # http://localhost:8102/src/frontend/?bg=d
```

- **폰 센서는 HTTPS 에서만 온다.** Tailscale IP 의 HTTP 주소로는 둘러보기 · 흔들기 · 나침반이 전부 죽는다.
  desktop-68v1g6c 는 Tailscale Serve 로 `https://desktop-68v1g6c.taila8a0a6.ts.net/` → `127.0.0.1:8102` 를 열었다(`tailscale serve --bg --https=443 http://127.0.0.1:8102`, 끄기 = `tailscale serve reset`).
  다른 PC 는 그 PC 에서 Serve 를 켜거나, 안드로이드 크롬의 `chrome://flags` 「Insecure origins treated as secure」에 주소를 넣는다. Serve 주의: Funnel(인터넷 공개)은 켜지 않는다, 기기 · 테일넷 이름이 인증서 공개 기록에 남는다.
- `serve_local.py` 대기열을 128 로 올린 이유: Serve 가 HTTP/2 로 파일을 한꺼번에 요청하면 기본 대기열 5 가 넘쳐 `main.js` 를 못 받고 화면이 하단 바만 남았다(11-04 실제 발생).
- 주소 옵션(`?bg=d` 와 함께): `&bgdebug` = 콘솔 경고(3초마다 센서 · 방향 · 해 위치 — 오류 비콘 서버로 폰 값을 PC 에서 받을 수 있다) · `window.__bgdome.state`(보는 방향 · 하늘 벌 · 해 · 달 고도). `&bgdebug&bgtime=2026-11-04T17:25:00%2B09:00` = 시각 지정, `&bgspeed=600` = 배속.
- 시험 시각(서울 37.57 · 126.98): 11-04 12:20 남중(남) · 17:25 해 질 녘(서 ≈ -111°) · 17:52 박명 · 11-05 02:44 달 뜸(동 ≈ 86°) · 05:30 밤(달 113° · 31°) · 06:50 여명(동 ≈ 107°).
- PC 에서 폰 흉내: 390px iframe 에 같은 출처로 띄우고 `DeviceOrientationEvent` · `deviceorientationabsolute` 이벤트를 보낸다(방위 az 를 보려면 alpha = -az, beta = 90 + 올려 보는 각). 위치는 iframe 의 `navigator.geolocation` · `permissions.query` 를 덮어쓰고 `bgview.js` 의 `setBgView("outdoor")`. Chrome 156 은 `DeviceMotionEvent.requestPermission` 이 있어 흔들기는 화면을 한 번 누른(pointerup) 뒤에 켜진다.
  자동 조작 브라우저는 rAF 가 크게 느려져 **움직임의 부드러움은 판단할 수 없다** — 최종 상태만 본다.
- 폰 오류를 PC 로 받는 법(11-04 사용): serve_local 과 같은 동작에 index.html 응답에 오류 비콘 스크립트를 끼우고 `/__err?m=` 요청을 출력하는 임시 서버를 세션 임시 폴더에 만들어 같은 포트로 띄웠다(저장소 파일은 안 건드림). 필요하면 같은 방식으로 다시 만든다.
