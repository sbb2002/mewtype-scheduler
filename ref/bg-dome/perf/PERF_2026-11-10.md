# bg-dome 기기별 성능 측정 (2026-11-10)

대상 = 브랜치 `feat/bg-dome` 커밋 `e9c80cc`(시선 HUD 개편까지 들어간 상태). 운영에는 아직 없는 코드다.

## 결론

- **CPU 가 측정 PC 보다 약 1.5배 느린 기기부터 저하가 시작**된다(버츄얼 스페이스 둘러보기가 먼저 60fps 를 못 지킨다).
- **3배 느린 기기**에서는 배경 보기의 모든 장면이 40 ~ 48fps.
- **4배 느린 기기**에서는 배경 보기가 30fps 안팎, 성간 이동 5단은 23fps.
- **메인 화면(예고 보드)은 6배 느린 기기까지** 거의 60fps 를 지키고, 8배에서 30fps 아래로 떨어진다.
- 메인 화면의 대기 비용은 돔과 무관하다 — 옛 배경과 돔의 메인 스레드 점유율이 같다.

## 측정 방법

- 측정 PC: AMD Ryzen 3 PRO 5450U(4코어 8스레드) · 내장 Radeon · 60Hz · Chrome 156.
- 창 없는 크롬(`--headless=new`)을 따로 띄워 CDP 로 제어했다. 그리기는 실제 GPU(ANGLE D3D11, 내장 Radeon)로 했다.
- 기기 흉내 = `Emulation.setDeviceMetricsOverride`(뷰포트 · DPR · 모바일) + `Emulation.setCPUThrottlingRate`(CPU 제한 배율).
- 페이지에 기록기를 심어 잰 값:
  - **fps** = `requestAnimationFrame` 이 1초에 불린 횟수(목표 60).
  - **GL 그리기/초** = WebGL `drawArrays` · `drawElements` 가 일어난 프레임 수.
  - **점유율** = CDP `Performance.getMetrics` 의 `TaskDuration` 증가분 ÷ 경과 시간(메인 스레드가 일한 비율).
  - **긴 작업** = 50ms 넘는 작업(`PerformanceObserver longtask`).
- 장면마다 6초씩. 둘러보기는 디버그 훅 `__bgview(방위, 고도)` 를 16ms 마다 바꿔 자이로 대신 시선을 움직였다. 성간 이동은 `__bggear(단)`.
- 주소: `?bgdebug&bgunlock=all`(+ `bgindoor=space`, `bgground=city|mountain|sea`). 서버 = `python scripts/serve_local.py 8102`.
- 스크립트 · 원자료(이 폴더): `perf.mjs`(전체) · `perf_earth.mjs`(지구만) · `cdp.mjs`(공통 도구) · `result.json` · `result_earth.json`.

## 관찰

1. **버츄얼 스페이스 둘러보기가 가장 무겁다.** 초행성X · 지구보다 스크립트 시간이 약 2배(×1 에서 15% 대 7%)다.
2. **메인 화면 대기 비용은 스크립트가 아니다.** ×1 에서 점유율 16% 가운데 스크립트는 1% 미만이고, 스타일 · 레이아웃이 5%, 나머지는 그리기 쪽이다. 무엇이 매 프레임 다시 그려지는지는 찾지 않았다(확인 필요).
3. **두 손가락 줌은 CPU 여유가 있는데도 fps 가 낮다**(×1.5 에서 점유율 45% · 38fps, 큰 화면 ×1 에서 44fps). GPU 한계인지 가짜 터치 입력(CDP)의 영향인지 가리지 못했다 — 줌 열은 참고만.
4. 배경 보기 대기에서 GL 그리기 횟수는 ×1 에서 60/초, ×2 부터 30/초 안팎으로 줄지만 fps 는 60 을 유지한다(그리기 조건이 「바뀐 것이 있을 때」 라서).

## 기기 대응 (추정 — 실측 아님)

CPU 제한 배율을 실제 기기에 대응시킨 것은 단일 코어 벤치마크 비율로 어림한 값이다. 벤치마크 점수는 기억에 의존했고 따로 확인하지 않았다.

| CPU 제한 | 비슷한 기기 |
|---|---|
| ×1 이하 | Galaxy S23 · 최근 아이폰(측정 PC 보다 빠름) |
| ×1.5 | Galaxy A54 · A34 급 중급기 |
| ×2 ~ ×3 | Galaxy A15 · A25 급, 6 ~ 7년 된 플래그십 |
| ×4 | Galaxy A14 · A13 급 보급기 |
| ×6 이상 | 최저가 라인 |

## 한계

- **GPU 는 제한하지 못한다.** 모든 수치는 측정 PC 의 내장 Radeon 으로 그린 결과다. GPU 가 약한 폰은 표보다 나쁠 수 있고, 강한 폰은 줌처럼 GPU 가 걸리는 장면이 더 나을 수 있다.
- 측정하는 동안 같은 PC 에서 다른 작업이 돌고 있었다. ×1.5 가 ×2 보다 낮게 나온 칸(둘러보기 버츄얼 48 대 52)처럼 한두 단계는 흔들렸다.
- 발열로 인한 속도 저하, 실제 폰 크롬의 부담, 자이로 센서 처리 비용은 들어 있지 않다.
- 실기기(S23 등) 확인은 하지 않았다.
- 측정 중 운영 데이터 저장소 raw 주소가 429(요청 과다)를 돌려준 구간이 있었다 — 로컬 서버가 데이터를 그대로 넘겨받는 구조라, 짧은 시간에 페이지를 많이 열면 생긴다. 다음에 잴 때는 fixture 데이터로 바꿔 재는 편이 낫다.

## 다시 재는 법

```bash
# 워크트리에서 로컬 서버
python scripts/serve_local.py 8102
# 다른 터미널 — 전체(약 25분) / 배율만 골라서 / 지구만(약 7분)
node perf.mjs
node perf.mjs out.json "1,4"
node perf_earth.mjs
```

`perf.mjs` 의 `BASE` · 크롬 경로(`CHROME`)는 PC 에 맞게 고친다.
