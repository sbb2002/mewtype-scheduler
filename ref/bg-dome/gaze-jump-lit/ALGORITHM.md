# 움직임 연동 방위 보정 — 동작 설명 (데이터 흐름 순서, 2026-11-13, Claude)

움직임 연동 방위 보정* = 절대 방위와 상대 방위의 차이(보정량)를 화면에 섞되, 사용자가 폰을 돌리는 동안에만 돌린 양에 비례해 섞는 방식.

- 재생 시험 = `replay/RESULT.md`, 폰 시험(**운영자 합격 11-13**) = `phone-2026-11-13/RESULT.md`
- 코드 = 브랜치 **`bg-dome-claude-test` `b73ed99`** 기준(`feat/bg-dome` `f9eb7e4` 위 실험 브랜치)
  - `src/frontend/js/bgyawfix.js` — 보정기(순수 로직, DOM · 센서 없음) · self-check `bgyawfix.selfcheck.mjs`
  - `src/frontend/js/bggyro.js` — 상대 방위 센서 추가 · 보정기 연결 · `gyroAbs()` 출력 교체
  - `scripts/replay_yawfix.mjs` — 기록 CSV 재생기

## 0. 흐름 한눈에

```
상대 센서 ─┬─▶ ① 회전 속도 ─▶ ② 정지 판정 ─┬─(정지)─▶ ③ 보정량 측정 → 목표
          │                              └─(회전)─▶ ④ 반영량을 목표 쪽으로 (돌린 각 × 0.2, ≤ 15°/초)
          └──────────────────────────────▶ ⑤ 상대 + 반영량 ─▶ ⑥ 선택 ─▶ ⑦ 편각 ─▶ ⑨ 감쇠 ─▶ 화면
절대 센서 ─┬─▶ ③ (보정량 측정에만)
          └─▶ ⑧ 고도 ─────────────────────────────────────────▶ ⑨
```

## 1. 센서 두 개 — `bggyro.js`

| 센서 | 성질 | 쓰는 곳 |
|---|---|---|
| `AbsoluteOrientationSensor`(절대, 기존) | 가속도 + 자이로 + 자력계(OS 융합, Android `TYPE_ROTATION_VECTOR`). 북쪽 기준이 맞지만 정지 중 계단이 있다 | 보정량 측정 · 고도 |
| `RelativeOrientationSensor`(상대, **추가**) | 가속도 + 자이로(Android `TYPE_GAME_ROTATION_VECTOR`). 매끄럽지만 방위 기준이 임의, 켤 때마다 새로 잡힌다 | 화면 방위 구동 |

- 둘 다 `{ frequency: 60, referenceFrame: "device" }`. 실측 판독은 약 36Hz(11-12 기록).
- 판독마다 쿼터니언 → 「폰 뒷면이 향하는 방향」(기존 `forwardOfQuat`) → 방위 `atan2(f[0], f[1])` · 고도 `asin(f[2])`.
- 고도가 78° 이상(`YAW_FREEZE`, 기존 값)이면 방위가 정의되지 않으므로 「얼림」 표시를 붙여 넘긴다. 얼린 판독은 보정 계산에 쓰지 않는다.
- 시각 = 센서 `timestamp`(없으면 `performance.now()`). 상대 → `yawFix.onRel(t, 방위, 얼림)`, 절대 → `yawFix.onAbs(t, 방위, 얼림)`.
- 상대 센서는 `?yawfix=0` 이 아닐 때 절대 센서와 같이 켠다(`startSensor` → `startRelSensor`).

## 2. 보정기 — `bgyawfix.js` (상대 판독마다)

| 단계 | 하는 일 | 인자(기본값) |
|---|---|---|
| ① 회전 속도 | 직전 상대 판독과의 방위 차 ÷ 시간을 평활(1차 감쇠). **절대 방위는 쓰지 않는다** — 계단을 움직임으로 오판하지 않게 | `tauW` 120 ms |
| ② 정지 판정 | 회전 속도가 문턱 미만이면 정지. 손떨림은 정지에 들어간다 | `wStill` 8°/초 |
| ③ 보정량 측정 (정지일 때만) | 보정량 `e = wrap(절대 − 상대)`. 두 판독 시각 차가 `pairMs` 이내일 때만 잰다. 회전 중 값은 버린다(두 센서 시각 차 · 융합 지연으로 크게 흔들림 — `replay/plot_replay_g4wz.png` 회색 선). 정지가 `tStill` 이상 이어지면 그 정지 구간 표본의 **중앙값**(최대 `bufMax` 개, ±180° 넘김 고려)을 **목표 보정량** `ê` 로 | `pairMs` 40 ms · `tStill` 500 ms · `bufMax` 64 |
| ④ 화면에 반영 (회전일 때만) | 회전 속도가 문턱 이상일 때만 반영 보정량 `b` 를 `ê` 쪽으로 옮긴다. 한 판독에 옮기는 양 = min(이번에 돌린 각 × `k`, `vMax` × 경과 시간). 예: 9° 차이는 다음에 약 45° 돌리는 동안 다 맞는다 | `wMove` 8°/초 · `k` 0.2 · `vMax` 15°/초 |
| ⑤ 출력 | 화면 방위 = `wrap(상대 + b)` | |
| 예외: 바로 맞추기 | 첫 판독, 그리고 상대 판독이 `gapMs` 넘게 끊겼다 다시 올 때(탭 전환 · 센서 재시작): `b = ê = e`. 상대 기준이 새로 잡혀 이어 붙일 이전 값이 없기 때문. **이 순간은 화면이 튈 수 있다** | `gapMs` 1000 ms |

정지 중에는 ③ 만 돌고 ④ 가 돌지 않으므로 `b` 가 그대로다 → **화면이 혼자 움직이지 않는다.** 대신 정지 중 생긴 차이는 다음 회전까지 남는다(재생 g4wz: 정지 프레임 26% 에서 5° 초과, 최대 14.6° — 이 차이는 흔들리는 절대 방위와의 차이다).

## 3. 화면까지 — `bggyro.js` → `bgdomegl.js`

| 단계 | 하는 일 |
|---|---|
| ⑥ 선택 `yawFixActive()` | 넷이 모두 맞을 때만 보정기 출력을 쓴다: `?yawfix=0` 아님 · 절대 원천이 `sensor`(AbsoluteOrientationSensor) · 상대 판독이 1초(`FRESH_MS`) 안에 옴 · 보정기가 맞춰짐. 아니면 지금 방식(절대 방위 그대로). iOS · PC · 센서가 막힌 기기 = 지금 방식 |
| ⑦ 진북 보정 | `gyroAbs()` 가 편각을 더한다(위치가 있을 때, 기존과 같음) |
| ⑧ 고도 | 절대 센서 고도 그대로. 계단 순간 고도 변화 ≤ 0.14°, 두 센서 고도 차 95% 0.12°(`METHOD.md` 4장) |
| ⑨ 화면 감쇠 | `updateView` 기존 감쇠 그대로(배율 1 = 0.08 초, 망원일수록 최대 0.44 초). 바뀐 것은 감쇠에 들어가는 목표 방위뿐 |
