## 1. UX 어색함 (처음 사용자 체험 시간 순서)

### ① 첫 진입 · 테마 전환 (`bgview.js` · `bgdeco.js` · `bgpeek.js`)
- **4종의 첫 방문 온보딩 안내가 같은 1~6초 창에 동시 충돌**
  - `t = 0.9s`: 캐러셀 좌측 44px 슬라이드 힌트(`render.js:930-939`) + 카드 위 「길게 누르면 주소가 복사돼요」(`longcopy.js:13, 258`, 6초 유지)
  - `t = 1.2s`: 배경 보기 손끝+꺾쇠 안내(`bgpeek.js:28-29, 184`, 15초 유지, `?bg=normal` 또는 UFO 전환 시)
  - `t = 2.6s`: 테마 버튼 반짝임 + 「길게 눌러 배경 변경」(`bgview.js:97, 319`, 4.2초 유지)
  - `bgview.js:92` 주석은 플릭 안내와 겹치지 않게 `HINT_DELAY_MS = 2600` 으로 미뤘다고 적었지만, 플릭 안내는 `1.2s~16.2s` 간 떠 있어 `2.6s~6.8s` 구간이 완전히 겹침(헤드리스 390×800 실측 `t=3.4s` 시점 `peekCueOn: true` 와 `holdHintVis: "visible"` 동시 노출 확인). 또한 **카드 길게 누르기(복사) · 테마 버튼 길게 누르기(배경 변경) · 레인 빈 곳 길게 누른 뒤 플릭(배경 보기)** 이라는 서로 다른 길게 누르기 3종이 동시에 제시되어 초심자가 혼란스러움.
- **테마 전환(`wipeDown`) 중 SVG → WebGL2 2단 교체 및 안내 조기 출현**
  - 기본 → UFO 전환 시 `bgview.js:70-74` `wipeDown`(1.6초, `bgdeco.css:56`) 중에 `bgdeco.js:120-121` 이 먼저 SVG 대체 돔(`bgdome.js`)을 그린 뒤 동적 `import("./bgdomegl.js")` 완료 시점에 WebGL2 캔버스로 교체(`bgdeco.js:97-101`). 바닥·조명·구름 배치가 한 번 툭 바뀔 수 있고, `bgpeek.js:191` 은 전환 시작 1.2초 뒤(`wipeDown` 1.6초 종료 전) `#bg-peek-cue` 를 띄움.
- **PC(≥768px) 사용자의 UFO 테마 막다른 길**
  - PC에서도 테마 버튼 길게 누르기로 UFO 테마 선택(`NEW` 배지 포함)이 가능하지만(`bgview.js:56-63`), `bgpeek.js:9, 46, 64` 가 `max-width: 767px` 전용으로 막혀 있어 배경 보기 · 조작 패널 · 해금 · 성간 이동 · 지구 모두 진입 불가(`HANDOFF.md` 남은 일 9번에도 미결로 남아 있음). 테마 팝업 설명에 모바일 전용임을 밝히거나 PC 진입 경로를 정해야 어색함이 없음.
- **iOS 센서 권한 요청 타이밍의 갑작스러움 (확인 필요 — 실기기 미검증)**
  - `bgdeco.js:238-250` 은 UFO 테마 상태에서 문서 전체 첫 `pointerup` 에 `DeviceMotionEvent` 와 `DeviceOrientationEvent` 권한을 한꺼번에 묻고 `sensorAsked = true` 로 고정. 사용자가 배경 보기를 시도한 것도 아닌데 방송 카드를 탭한 순간 권한 팝업이 뜨고, 여기서 거절하면 이후 배경 보기에 들어가도 자이로 권한을 재요청할 UI가 없음(`bgview.js:160` `askOrientation()` 은 지구 선택 시에만 재호출).

### ② 배경 보기 진입 · 해제 (`bgpeek.js` · `bgpeek.css`)
- **「빈 공간 길게 누른 뒤 위로 플릭」의 발견성 · 성공률 문제**

- **15초 타임아웃으로 미체험 사용자의 안내 영구 소멸**

- **배경 보기 안에서의 탭 실수(복귀 오작동)**
  - 배경 보기에서 화면을 되돌리는 방법(빈 곳 탭)에 대한 안내가 전혀 없는 반면, 처음 사용자가 하늘의 토성 표식·성운을 **손가락으로 탭해 선택**하려 하면 `#bg-peek-catch` 의 `click` 리스너(`bgpeek.js:172-175`)가 발동해 즉시 배경 보기가 닫혀 예고 화면으로 튕겨 나감.
- **[치명 버그] `low` 등급 전환 후 배경 보기 먹통**
  - `bgdomegl.js:2733` 에서 `peekObs.observe(document.documentElement, { attributes: true, attributeFilter: ["class"] });` 가 줄 끝 `//` 주석 안에 들어감.

(헤드리스 실측: `bgtier=low` 진입 시 `hud1: false, cs1: false, zoom1: 0` 재현).

### ③ 조작 패널 · 바닥 콘솔 (`bgpanel.js` · `bgconsole.js` · `bgdomegl.js`)
- **[버그] `seen.pinchHint` 가 새로고침마다 초기화됨**
  - `bgdomegl.js:2559` 는 핀치 후 `unlockS.seen.pinchHint = true; persistUnlock()` 을 저장하지만, `bgunlock.js:44` `parseState()` 는 `["holdNotice", "locAsked", "ymmtShown", "lightOff"]` 4개 키만 복원함.
  - 헤드리스 실측: 저장 직후 `localStorage["bgunlock"]` 에 `"pinchHint":true` 가 들어 있으나, 새로고침 후 `__bgunlock.state.seen` 은 `{}` 이며 `.ufo-hint` 가 `opacity: 0.98, visibility: visible` 로 다시 표시됨(`SPEC.md:436` 「이 기기에서 최초 1회」 위반).
- **「줌인하여 가까이 다가가보세요.」 안내 시점에 콘솔이 시야 밖일 수 있음**
  - 배경 보기 시작 시 눈이 `PEEK_START_R = 0.4` 로 물러나지만(`bgdomegl.js:45, 2510`), 기본 피치(`BASE_PITCH = 28°`)나 폰을 정면 수평(`0°`)으로 든 자세에서는 바닥 중심(`y = 0`, 눈 아래 약 `-31°`)의 UFO 콘솔이 화면 아래로 벗어나 보이지 않을 수 있음. 콘솔이 안 보이는데 "가까이 다가가보세요"만 떠서 대상이 모호함.
- **하늘 확대 핀치 ↔ 조작 패널 강제 개방 충돌**
  - 배경 보기는 `zoomR = 0.4` 에서 시작하고, 망원 확대(`tele > 1`)는 `zoomPath < 0` 구간(`bgdomegl.js:2514-2515`). 사용자가 하늘의 토성/성운/별자리를 크게 보려고 **두 손가락을 벌리면 반드시 `zoomR < PANEL_ON_R (0.24)` 구간을 통과**하게 되고, 이때 `bgdomegl.js:2539` 조건에 시선 고도(콘솔을 보고 있는지 여부) 검사가 없어 **하늘을 올려다보는 중에도 화면 중앙에 조작 패널이 튀어나와 HUD 와 대상을 덮고 `resetDwell()` 로 조준을 초기화함**(`bgdomegl.js:2566`).
- **조작 패널 닫기 안내와 `panelSuppressed` 불일치**
  - 패널 하단에는 「오므리면 닫힘」(`bgpanel.js:155`)만 적혀 있으나 바깥 탭(`bgpanel-dismiss`, `bgpeek.js:173`)으로도 닫힘. 바깥 탭으로 닫으면 `panelSuppressed = true`(`bgdomegl.js:1706`)가 걸려 `zoomR >= 0.36` 까지 오므렸다 다시 벌려야만 패널이 다시 열림(`bgdomegl.js:2535`). 바깥 탭 후 제자리에서 다시 벌려도 패널이 안 열려 반응이 끊긴 느낌을 줌.
- **하늘 전환 직후 조작 패널이 자동으로 다시 올라와 새 하늘을 가림**
  - 조작 패널에서 `초행성X` 나 `지구` 를 선택해 `beginSky()` 재투영 전환(1.65초)이 끝나면, `panelResume = true`(`bgdomegl.js:2296, 2539`) 때문에 **사용자가 막 도착한 새 하늘을 감상하려는 순간 조작 패널이 화면 한가운데에 다시 등장해 시야를 가림**. 사용자는 매번 목적지를 고른 뒤 추가로 오므리거나 바깥을 탭해 패널을 또 닫아야 함.

   - **원인**: 고도(`pitchDeg`)가 0.01°, 줌(`zv`)이 0.001, 방위가 0.1°만 바뀌어도 매 프레임 `while (el.firstChild) el.removeChild(...)` 로 수십 개 `<line>`/`<rect>` SVG 노드를 삭제하고 `createElementNS` 로 다시 붙임. 동시에 `pulse` 요소에 매 프레임 `style.setProperty("--pc", ...)` 를 써서 스타일 재계산 유발.
   - **영향**: `peek_pinch_zoom` CPU ×4 `73.0fps / mean 13.7ms / p95 25.1ms`, `peek_virtual_sweep` CPU ×4 `92.5fps / mean 10.8ms`. 이것이 `PERF_2026-11-10.md` 에서 보고된 "두 손가락 줌 저하(×1.5 38fps, ×4 17fps)" 및 "×6 프로파일에서 HUD DOM 갱신 `setAttribute · append/remove` 가 최대 스크립트 비중"의 직접 원인. `tape` 처럼 눈금 묶음을 한 번 만들어 `transform: translateY(...)` 로 밀고, `--pc` 는 `hue` 가 정수 단위로 바뀔 때만 갱신하면 매 프레임 DOM 생성을 0으로 줄일 수 있음.

6. **모바일 `classic` 테마까지 적용되는 `backdrop-filter: blur(16px)` (실측 확인 + 배터리/GPU 추정)**
   - **근거**: `bgpeek.css:36-49` (`#board .lane`, `.lane__header`).
   - **실측**: `?bg=classic` (`bgThemeAttr: null`)에서도 `laneBlur: "blur(16px) saturate(1.45)"`, `headBlur: "blur(16px) saturate(1.45)"` 가 그대로 적용됨.
   - **영향 (추정)**: UFO 돔(30fps SVG 조각 이동 + 160ms WebGL 갱신)과 기본 테마(CSS float 도형 11개) 뒤에서 화면 대부분을 덮는 레인 전체에 `blur(16px)` 백드롭 합성이 상시 유지되어, `PERF_2026-11-10.md` 「관찰 2 / 11-10 후속」에서 미해결로 남은 메인 화면 대기 그리기 점유율의 핵심 요인 중 하나로 추정됨. `classic` 테마에서는 블러를 끄거나, `low` 등급에서도 블러 반경을 줄이는 것이 유리.

7. **기타 모바일 GPU 드랍 우려 구간 (코드 기반 추정 — 실기기 확인 필요)**

## 3. 효과 · 연출 개선 여지 (SE · BGM · 화면 연출)

### ① 효과음 (SE, `bgsound.js`)
- **오디오 컨텍스트 선제 초기화 (`wake()`) 경로 확장 (필수)**
  - 현재 `bgpeek.js` 플릭 진입 · 첫 핀치 · 잠긴 타일 탭에서 `sound.wake()` 를 호출하지 않아 첫 해금(토성 표식) 팡파르가 무음으로 날아감. 배경 보기 진입(`bgpeek.js:hide()`)과 첫 `touchstart`(핀치) 시점에 `sound.wake()` 를 연결해야 첫 해금부터 정상 출력됨.
- **핵심 상호작용의 청각 피드백 공백 채우기**
  - 현재 SE는 `ding`(좌석벨트) · `alarm`(5단 경보) · `jump`(워프 점프) · `unlock`(해금 팡파르) 4종뿐(`bgsound.js`).
  - 아래 순간에 짧은 Web Audio 합성음(추가 파일 0KB)을 넣으면 손맛이 크게 올라감:
    1. **시선 링 스캔 진행(`SCANNING`) & 잠금(`LOCKED`)**: 2초 응시 중 은은하게 피치가 오르는 극소량 틱(또는 잠금 순간 맑은 짧은 락온 차임) — 해금이 아닌 재방문/일반 별자리 잠금에서도 "잡혔다"는 즉각적 쾌감 제공.
    2. **조작 패널 등장/퇴장 · 홀로그램 타일 클릭 · 잠긴 칸 거부**: 홀로그램 열림의 가벼운 고주파 스윕, 잠긴 칸 `.is-nope` 흔들림 시 짧은 저음 띡(거부음).
    3. **돔 재투영(하늘 전환)**: 1.4초 스캔 라인 하강과 맞춘 부드러운 필터 스윕 — 지금은 시각적으로 거대한 전환인데 완전 무음.
    4. **기어 변속 클릭(N~5단)**: 스로틀 레버를 끌 때 단마다 짧은 기계식 디텐트 클릭 + 진동(현재 `buzz()` 8ms 만 있고 소리는 4~5단 벨트 `ding` 까지 무음).
    5. **성간 이동 1초 길게 누르기 충전(`chargeLoop`)**: 0% → 100% 충전 중 피치가 올라가는 차지음.
- **워프 점프 B 연출의 음원 싱크 미세 보완**
  - `bgsound.js:91, 95` 에서 `B` 는 `JUMP_ARRIVE.B = 0` 이라 파일의 `1.2s`(절정 지점)부터 `0.12s` 페이드인으로 시작. 절정 직전의 짧은 빌드업이 잘려 `A`/`C` 대비 임팩트가 덜하고, `120ms` 페이드인 동안 붉은 섬광(`t=0~132ms`, `bgwarp.js:107`)이 이미 지나가 버림. `off = 1.05s` 정도로 살짝 앞당기면 타격감이 맞아떨어짐.
- **5단 경보음(`alarm.wav`) 피로도 완화**
  - `WARP` 활성화까지 약 10초 가까이 동일한 `0.242초` 단음 비프가 최대 음량(`ALARM_GAIN = 1.6`)으로 반복되어 청각 피로가 큼(`bgsound.js:71-85`). 5단 진입 초기 3~4초는 강하게 울리다 속도가 안정화(`amp` 감소)될수록 음량·필터를 자연스럽게 낮추고, `WARP` 준비 완료(`ding("off")`) 순간 짧은 준비 완료 화음을 얹으면 긴장→해소 대비가 훨씬 쾌적해짐.

### ② BGM · 음악 연동 (`bgmusic.js` · `bgsound.js` · `player.js`)
- **초기 상태 동기화 보완**: `player.js` 가 현재 재생 상태(`{ state, id, members }`)를 `musicpriority.js` 나 전역 헬퍼에 보관하고, `createMusicRim()` 이 마운트 즉시 초기 상태를 읽어 반영하도록 해야 테마 전환/지연 로드 후에도 음악 테두리와 별자리 힌트가 누락되지 않음.
- **배경 보기 중 최소 음악 정보 표시(선택)**: `SPEC.md:439` 대로 배경 보기에서 플레이어 창이 걷히며 재생이 이어지는데, 곡이 바뀔 때 화면 위 `bg-music-rim` 아래에 2.5초만 옅게 `♪ 곡명` 이 스쳐 지나가면(조작 없는 순수 표시) "지금 이 멤버 색 띠가 왜 바뀌었는지" 즉각 이해할 수 있음.
- **솔로 별자리 힌트 가시성**: `bghud.js:232` 의 솔로 곡 힌트 별자리 선 불투명도가 `0.18~0.34` 로 밝은 은하수 바탕(`space-tycho`, `space-wise`) 위에서는 다소 묻힐 수 있음(실기기/밝은 바탕 확인 필요). 멤버 색 별빛 글로우 반경을 조금 키우거나 힌트 중 방위 테이프 마름모에도 멤버 색 테두리를 주면 발견성이 좋아짐.
- **iOS Safari 백그라운드/오프스크린 iframe 재생 유지 여부 확인 필요**: `bgpeek.css:84` 가 `#player-frame` 을 `translate: 0 100dvh; opacity: 0` 으로 화면 밖으로 밀어내는데, iOS Safari/모바일 Chrome이 뷰포트 밖+투명 `opacity: 0` YouTube iframe 의 재생을 일시정지하거나 스로틀링하지 않는지 실기기 확인 필요.

### ③ 화면 연출 (`bgdomegl.js` · `bgpanel.js` · `bgfx.js` · `bghud.js`)
- **방사형 블러(`zoomBlur`) 중심을 실제 진행 방향(`warpDir`)에 맞추고 돔 바닥 제외**: 현재 `zoomBlur()`(`bgdomegl.js:1882`)는 항상 화면 정중앙`(cx, cy)` 기준으로 돔 유리·무대 바닥까지 함께 번지게 함. 진행 방향(`jumpCenter()`) 기준으로 별/하늘만 번지게(셰이더 내부 처리) 바꾸면 3D 공간감과 성능이 동시에 개선됨.
- **딥필드 표식 찾기 전 은은한 천문 단서**: 현재 `drawTarget` `"feat"`(`bghud.js:212-214`)는 찾기 전 아무 표시가 없고 15° 이내 분홍 십자 반짝임만 존재. 표식이 `tol = 5°` 로 좁아 딥필드 사진 속에서 정확히 어느 별/지점인지 알기 어려우므로, 10° 이내로 좁혀지면 미세한 타겟 스캔 링이 옅게 드러나면 조준 답답함이 줄어듦.
- **해금 완료 후 콘솔 비행(`fly`) 착지 반응**: `bgpanel.js:304-315` 의 `fly()` 가 화면 중앙에서 아래(`+0.36 * innerHeight`)로 날아가 사라질 때, 바닥 콘솔(`.bgcs-glow`)이나 하단 `.ufo-call` 이 착지 타이밍(약 1.1초 뒤)에 한 번 밝게 파동 치면 "새 기능이 콘솔에 저장됐다"는 인과가 훨씬 선명해짐.
- **별자리 완성 후 5색 별빛 조명 첫 해금 연출 강화**: 멤버 5명 별자리를 모두 모아 `light`(별빛 조명)를 열었을 때, 현재는 하단 그라데이션 `.bg-starlight` 가 조용히 켜지고 끝남(`bgdomegl.js:2587`). 마지막 5번째 별자리를 잡는 순간 돔 바닥 매립 조명 5개도 잠시 5색 파도로 한 바퀴 훑고 지나가면 수집 보상감이 크게 살아남.
- **지구 보상 YMMT 별자리 첫 1회 보장**: 지구 첫 도착 시 `bgfx.js:143` 이 8~16초 뒤 랜덤 방위(`yawDeg ± 28°`)에 띄우는데, 패널이 닫힌 뒤 첫 1회는 시선 정면 상공(`±10°`)에 비교적 빠르게(3~4초 뒤) 띄워 주면 보상을 놓치지 않음.
