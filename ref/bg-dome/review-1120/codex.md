# UFO 돔 병합 전 독립 검토

검토 대상은 `feat/bg-dome`의 `94a9d95`. `docs/SPEC.md` 「배경 장식」과 `origin/devpapers:ref/bg-dome/HANDOFF.md`를 참고했다. 파일 근거의 `js/`, `css/`, `assets/`는 `src/frontend/` 기준이다.

## 1. 첫 사용자 UX

1. **첫 진입 → 배경 보기.** 새 사용자에게는 기본 배경이 표시되므로 UFO 테마 선택이 선행된다. 돔에서 안내는 1.2초 뒤 나타나는 손 애니메이션이며 15초 뒤 닫히고 확인 여부가 저장된다. 진입하려면 활성 레인의 카드나 헤더가 아닌 부분을 500ms 누른 뒤 위로 48px 이상 빠르게 밀어야 한다. 390px 로컬 시험에서는 화면 가운데 (195, 650)에서 진입하지 못했고, 활성 레인의 유효한 빈 지점 (42, 590)에서 준비 상태와 진입을 확인했다. 안내가 실제로 누를 수 있는 곳을 가리키고, 다시 볼 수 있으면 처음 놓쳐도 복구할 수 있다. 768px 이상에서는 현재 터치 진입 경로가 차단된다. (`js/bgdeco.js:26–33`, `js/bgpeek.js:9–16,27–49,87–149,186–206`)
2. **배경 보기 → 조작 패널.** 진입 직후 패널은 숨겨져 있었다. 패널은 망원이 아닌 상태에서 콘솔에 충분히 가까워져야 열리는데, 벌리기 안내는 약 10초 뒤 사라지고 상호작용 없이도 표시 완료로 저장된다. 패널을 바깥 탭으로 닫은 직후에는 멀어졌다 다시 접근해야 한다. 콘솔 자체에 짧은 접근 힌트를 남기면 진입·재진입 경로를 찾기 쉽다. 패널 개폐와 두 손가락 조작의 실기기 체감은 확인 필요. (`js/bgdomegl.js:2534–2560,2598–2615`)
3. **토성 → 초행성X → 성운.** 화면 중앙으로 토성을 맞추는 디버그 시선으로 HUD의 토성 포커스를 확인했다. 해금 전에는 맥박 표시와 시선 링으로 찾고, 해금 후에는 도형이 콘솔로 날아가며 열린 칸이 빛난다. 시선이 하늘에 있고 콘솔은 바닥에 있어 이 신호를 놓치면 다음 동작을 추론해야 한다. 첫 발견 카드에 콘솔 접근과 열린 칸 이름을 짧게 남겨 두면 발견과 출발이 이어진다. 성운 뒤에는 같은 초행성X 칸의 탭과 1초 길게 누르기가 다른 동작이다. 누름 진행 표시와 기존 칩을 유지하면서 버튼을 짧게 눌렀을 때에도 길게 누르기 안내를 재확인할 수 있으면 좋겠다. 실제 연속 해금은 확인 필요. (`js/bgdomegl.js:1506–1514,1526–1535,2542–2544`, `js/bghud.js:328–347`, `js/bgpanel.js:79–100,122–131,296–320`)
4. **성간 이동 → 첫 워프 → 딥필드.** 5단을 고른 직후에도 목표 속도에 도달하고 좌석벨트 등이 꺼질 때까지 WARP가 비활성이다. 첫 목적지가 없으면 선택창 없이 무작위로 가며, 사진을 기다리는 동안 별도의 출발 준비 화면이 없다. 버튼 주변에 «가속 중 → 워프 준비 → 목적지 준비» 상태를 표시하면 누름이 먹혔는지 알 수 있다. 딥필드는 도착 후 사진 속 표식을 찾아야 목적지로 남는다. 도착 알림과 탐험 완료 토스트는 2.2초이며, 다섯 곳의 진행도와 현재 사진에서 해야 할 일을 워프 목록에서 다시 확인할 수 있게 하면 흐름이 이어진다. (`js/bgwarp.js:34–66`, `js/bgunlock.js:60–97,149–157`, `js/bgdomegl.js:1664–1684,1822–1828`, `js/bgpanel.js:317–320`)
5. **달 궤도 → 지구 → 보상.** 딥필드 다섯 곳을 완료하면 무작위 자리를 달 궤도가 대신하고, 달에서 지구를 찾으면 지구·YMMT·자유 항해가 열린다. 지구 선택은 위치 권한 분기로 이어져 해금 직후 전환이 끊길 수 있다. 진입 전에 위치를 쓰는 이유를 짧게 알리고, 재시도 방법과 보상 목록을 패널에서 다시 볼 수 있으면 좋겠다. YMMT를 처음 한 번 바로 보여 주고 이후에는 가끔 나타나게 하면 해금 직후 보상이 보인다. 위치 승인·거절과 보상의 자연 진행은 실기기 확인 필요. (`js/bgunlock.js:60–97,128–142`, `js/bgdomegl.js:1598,1621–1638,2545–2547`, `js/bgfx.js:45–68,135–170`)

## 2. 프레임 드랍

- **실측 범위.** 로컬 Headless Chromium, SwiftShader 소프트웨어 렌더링, 390×760 CSS px, 기기 DPR 2, 돔 high 강제(DPR 상한 1.5). 예고 데이터만 `fixtures/preview.sample.json`으로 대체하고 외부 요청은 차단했다. 배경 보기 직후 정지 시선의 rAF 간격 6개 평균 **397ms**, 최대 **717ms**, 50ms 초과 **6/6**. 디버그 훅으로 5단을 요청한 직후 6개 평균 **400ms**, 최대 **583ms**, 50ms 초과 **6/6**. 이 값은 창의 rAF 간격이며 GPU 처리 시간과 실제 휴대폰 FPS는 확인 필요. 5단 요청 뒤 워프 버튼은 표시됐으나 측정 종료 시 β=0.9605에서 비활성이었다. 실제 점프와 도착 프레임은 확인 필요. 두 구간 모두 소프트웨어 렌더링에서 이미 크게 느려 가속의 추가 비용을 이 수치로 판별할 수 없다. 토성 포커스 뒤 약 4.8초를 기다려도 진행률은 0.20이었다. 프레임당 dt가 50ms로 제한되고 이를 HUD가 누적하므로 심한 드랍에서 명세상 2초 응시가 실제 시간으로 늘어나는 경로가 있다. (`js/bgdomegl.js:2664–2696,2742,2792`, `js/bghud.js:303–308`, `js/bghudlogic.js:45–66`)
- **추정 · 전환/재투영.** 전환 첫 프레임에 전체 화면을 한 번 더 그리고 `copyTexImage2D`로 복사한다. 하늘 전환에서 이전 장면 재투영과 새 장면 셰이딩이 겹치고, 패널과 카드 배경의 backdrop blur가 합성 비용을 더할 수 있다. 워프도 B용 캡처를 종류 결정 전에 호출하므로 A/C에서 캡처가 필요한지 확인할 가치가 있다. 사진과 무관한 하늘 전환 A/B, 워프 A/B/C를 각각 재서 시작 프레임과 지속 비용을 비교하는 편이 좋다. (`js/bgdomegl.js:1050–1142,1674–1684,2237–2246,2262–2265`, `css/bgpanel.css:138–141,258,388`)
- **추정 · 성간 가속/워프 블러.** WebGL 출력 위에 같은 해상도의 2D 캔버스를 두고 매 갱신에 원본을 확대해 여섯 번 합성한다. low에서도 해상도·빈도만 낮아지고 같은 여섯 번을 수행한다. low에서 샘플 수를 줄이거나 작은 버퍼로 블러를 합성하는 방안을 비교할 수 있다. 절차적 달 월면이 넓게 보이는 구도도 별도 측정이 필요하다. (`js/bgdomegl.js:545–610,1365,1873–1889,2466–2468,2742`)
- **추정 · 딥필드 최초 로드.** 이미지 요청 후 WebGL 텍스처 업로드와 밉맵 생성을 한 콜백에서 처리한 뒤 출발한다. 차가운 캐시에서는 입력 후 대기와 업로드 프레임을 분리해 측정해야 한다. **코드상 실패 처리 결함**도 있다. 실패를 `false`로 반환하지만 워프와 자유 항해가 성공 여부를 확인하지 않고 진행하며, `setDeep`은 텍스처가 없으면 기존 사진을 유지한다. 워프의 해금 처리는 요청 목적지를 사용한다. 실패 Promise도 남아 같은 세션의 재시도가 막힌다. 따라서 실패 시 이전 사진을 보면서 목적지 도착 알림을 받을 수 있다. 프레임 비용과 별개로 실패 시 출발을 중단하고 재시도할 수 있게 하는 편이 좋다. 네트워크 실패 주입 재현은 확인 필요. (`js/bgdomegl.js:1412–1435,1549–1557,1674–1684,1820–1828`)
- **추정 · 자동 등급.** 1.5초를 버리고 2초 분량을 본 뒤 45fps 미만 또는 50ms 초과가 10%를 넘으면 low다. low는 배경 보기 30fps와 DPR 1, 예고보드에서는 정지하지만 전환은 끝까지 그린다. low에서 high 재시험이 워프와 겹치면 해상도 상승과 전환이 겹칠 수 있다. 실기기에서 자동 등급 전환 시각과 점프/사진 업로드를 함께 기록하는 항목이 남았다. (`js/bgtier.js:17–22,32–85`, `js/bgdomegl.js:2638–2672,2742`)

## 3. 효과·연출

- **SE.** 5단 경보와 점프 외에 조작 결과를 알려 주는 짧은 소리가 있으면 좋겠다. 사진 요청이 길어질 때는 입력 수락 신호, 텍스처가 준비된 뒤에는 실제 출발 신호를 구분한다. 탐험 완료와 지구 해금에 서로 다른 짧은 끝음을 쓰면 같은 팡파르가 반복되어도 의미를 구별할 수 있다. 점프 A/B/C는 현재처럼 각 충격 시점에 맞추고, 첫 사용에서도 음원 준비가 되었는지 확인이 필요하다. (`js/bgsound.js:21–43,47–69,92–106`, `js/bgdomegl.js:1674–1684`)
- **화면.** 해금 도형의 이동은 유지하고 콘솔의 열린 칸과 같은 색·아이콘을 발견 카드 끝에 남긴다. 워프 도착 때는 새 장면과 방향 테이프가 안정된 뒤 목적지 이름을 표시하고, 달 궤도 최초 도착에만 월면과 지구가 함께 읽히는 시선 방향을 고려한다. 화면 흔들림과 섬광을 줄인 설정에서도 상태 변화가 글과 아이콘으로 읽히는지는 확인 필요. (`js/bgpanel.js:296–326`, `js/bgdomegl.js:1539–1546,1687–1696,1820–1828`, `js/bgwarp.js:75–116`)
- **BGM 믹스.** 플레이어 재생에 이미 음악 테두리, 솔로 별자리 힌트, 돔 SE 전체 감쇠(0.9→0.35)가 연결돼 있다. 곡이 흐를 때 경보와 충격음은 낮게 두되 좌석벨트 해제음이나 보상 끝음에는 별도 레벨을 적용하는 편이 상태를 읽기 쉽다. 실제 곡과 SE의 겹침 및 음량은 확인 필요. (`js/bgmusic.js:10–24,42–72`, `js/bgsound.js:12–16,47–69,92–106`, `js/bgdomegl.js:1607–1612`)

## 4. 유메미타 플레이어 BGM 후보

현재 연결은 플레이어 상태를 받아 돔을 바꾸는 방향이다. 돔에서 곡을 고르는 기능을 추가한다면 이용자가 직접 누르는 추천 버튼으로 시작하고 재생 중인 곡은 유지하는 편이 좋다. 워프는 3.6~3.9초이고 플레이어는 영상 버퍼링 상태도 발행하므로, 워프 버튼을 누른 순간 곡을 시작해 충격 프레임에 맞추는 방식은 타이밍이 보장되지 않는다. 5단에 오르기 전 또는 탐험 후 감상에 쓰는 게 적합하다. 곡은 목록의 제목·가창자와 연출 맥락으로 골랐다. 음원 버전, 인트로 타이밍, 임베드 재생은 확인 필요. (`js/bgmusic.js:10–21,42–72`, `js/player.js:315–329,402`, `js/bgwarp.js:75–76`)
