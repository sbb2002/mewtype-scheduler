# UFO 테마 첫 접속 체험

`feat/bg-dome` `5599a2e` · 로컬 8141 · 390×844 CSS px 모바일 에뮬레이션. 저장소가 빈 새 세션의 `/src/frontend/?bgdebug`에서 시작했다. `bg=`와 모두 열기는 사용하지 않았다. 예고보드는 저장소의 샘플을 썼고 지구 전환에 서울 좌표와 위치 권한을 에뮬레이션했다. WebGL은 Chrome 헤드리스 SwiftShader였으며 본 항해에서 자동으로 low가 됐다. 본 항해의 에뮬레이션 DPR은 0.6이었다. 아래 시간은 자동화·캡처를 포함한 벽시계 기준이다. 첫 항해는 자유 항해로 달에 돌아온 뒤 막혔고, 같은 해금 상태를 새 로컬 세션에 복원해 남은 체험을 이어갔다. 새 보상은 복원 후 실제 조작으로 얻었다.

테마·기어·패널 버튼은 실제 클릭/길게 누르기, 배경 보기와 핀치는 CDP 터치로 조작했다. 자이로가 없어서 시선에는 `__bgview`를 썼다. 토성에서 정면을 약 2초 보아도 포커스가 잡히지 않아 그 뒤로 `__bgunlock.targets`의 방위·고도를 읽었다. **공략을 본 체험**이다. 대상 방향을 스스로 찾는 데 걸리는 시간은 확인 필요. 핀치가 빗나갔을 때는 현재 줌 목표를 읽어 다음 터치 폭을 정했다.

## 소감

- 들어가기 전에는 햇빛·달빛을 바꾸는 버튼으로만 보였다. 레인이 걷히면서 분홍 하늘과 바닥 콘솔이 한 화면에 드러나는 순간에야 예고보드 뒤에 또 다른 공간이 있다는 느낌이 들었다. 손가락을 벌렸을 때 홀로그램이 앞으로 나타나는 연출도 콘솔을 조작한다는 느낌을 준다. 유효한 빈 곳을 모르거나 손동작에 한 번 실패하면 이 두 장면을 보기 전에 멈추기 쉽겠다.
- 토성은 패널이 이름을 알려 주고, 응시 링이 차면 ‘토성 표식’ 카드와 열린 타일 이름이 남아 첫 보상이 분명했다. 성운 역시 ‘길게 눌러 성간 이동’이라는 다음 행동이 카드에 나왔다. 정면에서 한 번 못 찾았을 때는 HUD 왼쪽 신호만으로 위아래 어느 쪽을 더 찾아야 할지 바로 감이 오지 않았다.
- 하늘이 방사형으로 당겨지고 속도계와 좌석벨트가 함께 바뀌는 첫 가속은 재미있었다. 5단에 손을 댄 뒤 약 12초가 지나야 눌리는 WARP는 첫 회에는 긴장감이 있고, 매 목적지마다 반복하면 기다림이 앞선다. 이름이 다른 성운뿐 아니라 같은 5단 대기와 조작 패널 닫기를 반복한다는 점이 체감 피로의 원인이었다. 워프 뒤 우주가 정지하고 사진 쪽의 작은 표식에 다시 집중하는 전환 자체는 마음에 들었다.
- 달 표면이 크게 깔린 화면에서 지구를 잡자 푸른 링과 귀환 알림이 겹쳤다. 이번 체험에서 ‘찾아 돌아왔다’는 느낌이 가장 선명했다. 지구 밤하늘에 YMMT가 서서히 써지는 모습은 앞선 워프의 강한 섬광과 달라 귀환 뒤 잠시 머무르게 했다. 별빛 조명은 다섯 사람을 다 찾은 보상으로 맞아떨어졌고, 바닥 쪽 색은 켜고 끌 때 차이를 알아보기 쉬웠다.
- 플레이어에서 테마의 목적지와 같은 제목인 **超惑星Xへの旅**를 직접 골라 놓고 돌아오니 예고보드와 돔이 같은 팬 공간이라는 느낌이 났다. 상단 띠가 얇아 분홍 하늘에서는 쉽게 지나칠 수 있었다. 곡 진행과 테두리의 시각 연동을 확인했으며, 실제 기기의 음량 밸런스와 처음 발견할 때의 SE는 확인 필요.

## 새로 발견한 문제

1. **하늘 전환과 워프 뒤 자동으로 열린 조작 패널이 다음 탐색을 막는다.** 앞 검토에서는 패널의 여는 법과 닫은 뒤 재접근을 다뤘다. 이번에는 점프의 도트 애니메이션이 끝난 뒤 기존 줌 0.12에서 조작 패널이 다시 떠서, 도착 토스트의 안내대로 정확한 방향을 바라봐도 HUD 포커스·링이 0이었다. 오리온에서는 이 상태로 12초를 기다렸다가 핀치로 멀어진 뒤 약 2초에 표식을 잡았다. 다른 첫 탐험지에서도 재현했다. 패널 재오픈 판정과 HUD 비활성 조건이 함께 작동한다. 도착한 뒤 첫 시선 탐색이 바로 작동하도록 패널 복귀 타이밍을 바꿀 수 있다. (`src/frontend/js/bgdomegl.js:1777–1785,2547–2552,2579–2591`, `play_codex_08_orion.png`은 패널을 내린 뒤 성공한 장면)
2. **여행을 반복해야 할 때 이미 끝낸 목적지가 다시 나온다.** 소스에서 무작위 후보는 현재 위치만 제외하며 ‘탐험 완료’ 여부는 고려하지 않는다. 네 곳을 완료한 뒤 오리온·게·타란툴라·SMACS 0723을 연속으로 재방문했다. 탐험할 곳이 하나 남았을 때 새 목적지의 확률은 4분의 1이었다. 반복 가속 대기와 겹쳐서 목적지 수집이 특히 늘어지는 지점이다. (`src/frontend/js/bgunlock.js:72–95`)
3. **자유 항해로 달에 돌아온 뒤 기본 우주로 갈 방법이 패널에서 잘 드러나지 않는다.** 지구에서 자유 항해로 달에 돌아온 뒤 초행성X 타일을 눌러도 기본 우주로 바뀌지 않았다. 달 궤도와 딥필드도 내부적으로 `INDOOR_BG === "space"`이고, 같은 타일 클릭은 즉시 반환한다. 기본 우주는 대신 워프 목록에 표시된다. 별자리 찾기처럼 기본 우주로 돌아가야 할 때 이 차이가 특히 크게 느껴진다. (`src/frontend/js/bgdomegl.js:1627–1645,2553–2561`, `src/frontend/js/bgunlock.js:88–95`)

## 확인 범위

실기기 자이로·진동·첫 발견 SE, 위치 권한 팝업·거절, 강제 실패 시 워프의 재시도 동작, 실제 폰 프레임률과 솔로곡 별자리 힌트는 확인 필요. 캡처는 보고서와 같은 폴더에 저장했다.
