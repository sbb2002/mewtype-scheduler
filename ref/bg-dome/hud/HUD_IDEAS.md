# 배경 보기 시선 HUD 구현 아이디어 (2026-11-08)

배경 보기(위로 플릭) 중 폰 화면에 고정되어 시선을 따라다니는 HUD 와, 그 위에 얹는 「대상 찾기 · 해금」 보물찾기 아이디어를 정리한다.
**시안(아티팩트) 단계이며 구현 전이다.** 시안의 수치 · 시각 · 위치는 전부 예시다. 시안 렌더링은 Claude 가 직접 확인하지 못했다(운영자 확인 필요).

용어(이 문서에서 처음 쓰는 것 — `docs/TERMINOLOGY.md` 에 올릴 후보):
- **시선 링** = 시선 중심에 평소엔 숨어 있다가 대상이 범위에 들어오면 나타나 2초 동안 차오르는 얇은 원형 게이지.
- **대상** = 하늘에서 찾을 수 있는 천체(달 · 성운 · 블랙홀 등). 허용 각도 안에 시선이 머물면 「잡힌다」.
- **해금** = 특정 대상을 잡으면 새 목적지(테마)로 워프할 수 있게 열리는 것.
- **시야 보정** = 대상 허용 범위 안에서 드래그 · 센서 입력에 대한 화면 이동량을 줄여 시선이 흔들리지 않게 하는 것.

## 시안 이력

| 시안 | 파일 | 요점 |
|---|---|---|
| A ~ E + F | `hud_concepts_A-F.html` | A 조종석 레티클 · B 시선 링 · C 코너 텔레메트리 · D 방송 신호 레이더 · E 캐노피 계기판. 운영자가 표시 정보는 모두 좋다고 하고 A · B 를 선택 → A+B 혼합 F |
| F2 | `hud_f2.html` | 시선 링이 대상에서만 차오르고 100% 면 정보 카드. 운영자 평가: 「교육용 어플 같다」 |
| F3 | `hud_f3.html` | 정보 카드 폐지. 대상 반응(맥동 · 돔 물들임, 또는 신호 수신) + [워프] · [찍기](셔터 · 앨범) |
| F4 | `hud_f4.html` | 해금 도장 + 3초 이내 자동 워프 + 지구 ↔ 딥필드 이동. 일반 대상은 이름 · 막대 2개 · [찍기] |

## 운영자 확정 · 의견 (2026-11-08)

- 표시 정보 후보는 모두 좋음: 방위(HDG) · 고도(ALT) · 배율 · 중심 거리 r · 현재 하늘 · KST 시각 · 워프 속도 · 기어 · 다음 방송.
  제안 우선순위: 1순위 방위 · 고도 · 배율 / 2순위 현재 하늘 · 시각 / 3순위 방송 정보 / 워프 중에만 속도 · 기어.
- 디자인은 A · B 가 좋음 → 둘을 섞은 **F**(위 방위 테이프 + 가운데 시선 링 + 양옆 고도 · 배율 눈금 + 하단 정보).
- 시선 링 동작: **딥필드 우주의 성운 등을 일정 시간 시야 범위 안에 고정하면 링이 나타나 차오르고, 100% 가 되면 정보를 띄운다.**
  지구에서는 행성 · 위성(타이탄 · 가니메데 등) · 일부 거대 소행성을 포커스하면 나타낸다.
- **정보 팝업(카드)이 교육용 같다 → 손보기로 함**(방향은 미정). 문장형 AI 대사(안 1)는 더 교육용 같다고 반려됨.
- 시야 보정: 포커스되면 일정 시야 범위 안에서 움직임을 둔하게.
- 하단 UI 는 서로 겹치지 않게, 기기 환경에 따라 적절히 배치.
- **보물찾기 · 해금**: 각 배경 테마의 요소를 찾으면 해당 테마로 순간이동(워프)이 해금된다.
  - 지구: 낮에 해 · 달 / 밤에 달 · 별 · 성운(딥필드) · 행성 등. 딥필드 우주: 성운 · 블랙홀 등.
  - (a) 찾은 대상 위치로 포커스 · 확대 = **나침반 요소와 겹쳐 미결, 보류 가능.**
  - (b) 요소를 발견하면 테마로 워프 = 자동으로 기어 5단까지 풀악셀 뒤 성간 이동 연출, **3초 안에 끝낼 것**(F4 시안 2.4초).

## 시안에서 정한 것(구현 때 참고)

- **시선 링**: 평소 숨김. 대상이 허용 각도 안이면 등장 · 조준 표시(분홍 꺾쇠) · 2초에 100% · 이탈하면 3초에 걸쳐 줄어듦(0 이 되면 사라짐). 허용 각도 = 성운 6° · 달 5° · 별 3° · 행성 · 위성 2.5 ~ 3° · 블랙홀 4°.
- **100% 반응(F3 · F4)**: 대상 맥동 + 확산 고리 + 돔 하늘이 대상 색으로 잠깐 물듦(1.6초). 이름 한 단어 + 버튼만. 거리 · 밝기는 숫자 대신 5칸 막대.
- **해금 연출(F4)**: 처음 잡을 때만 「UNLOCKED」 도장(0.55초) + 「→ 목적지 이름」 + [워프]. 다시 잡으면 도장 없이 [워프].
- **워프 시간표(F4, 총 2.4초)**: 0 ~ 1.2초 기어 N → 5(0.24초 간격 · β .30 .60 .80 .90 .99) + 빛줄기 증가 + 흔들림, β ≥ 0.85 에서 붉은 가장자리 · 1.2초 섬광 → 1.25초 하늘 교체 → 급제동(약 1초) 후 도착 문구. 하단 정보(NEXT · SKY · 시계)는 워프 중 기어 레일로 대체(겹침 방지).
- **[찍기](F3 · F4)**: 뷰파인더 프레임이 닫히고 셔터음 + 섬광, 가운데 70° 영역을 잘라 폴라로이드로 앨범에 저장. 기기 저장만 가정.
- **시야 보정**: 대상 범위 안에서 입력 감도 × 0.4. 너무 끈적하면 다른 대상으로 못 벗어나므로 이탈은 쉬워야 한다 — 시안은 범위 안이면 일정 비율, 실제는 이탈 방향 가속 등 조정 필요.

## 구현 아이디어 · 주의

- 기존 모듈과의 접점: 워프 연출 · 기어 · 경보는 `bggear.js` · `bgwarp.js` · `bgdomegl.js` 재사용, 하늘 교체는 「돔 재투영」(`bgdomegl.js`), 홀로그램 틀은 `bgpanel.js` `holoParts`. HUD 는 새 모듈로 두고 순수 계산(허용 각도 판정 · 차오름 · 보정 계수)은 `*.selfcheck.mjs` 로 검증 가능하게 분리하는 것이 이 저장소 관례에 맞다.
- 별자리 · 천문 이벤트 계획(`HANDOFF.md` 「나중에 넣을 기능」)과 같은 기능이다: 시선 머무름 → 이름표, YMMT 별자리 로직 재사용 후보. 착수 조건(기본 구성 완료 뒤)은 그대로.
- **저장**: 해금 · 앨범은 서버 없이 기기 저장(localStorage). 기기를 바꾸면 사라진다 — 사용자 안내 필요.
- **기존 확정 보존**: 조작 패널의 3개 하늘(버츄얼 스페이스 · 초행성X · 지구)은 처음부터 열어 두고, 그 위의 추가 목적지만 해금하는 안을 권했다(운영자 최종 확정 아님 — **확인 필요**).
- **지구 대상의 위치 정확도**: 폰 나침반 오차(수 도)보다 작은 대상(위성 · 소행성)은 허용 각도를 넉넉히 잡아야 한다. 지평선 아래 대상은 해금 불가 + 안내 문구, 낮 전용 요소는 방송 시간대(저녁 · 밤) 접속이 많으면 놓치기 쉬움 → 힌트 · 도감 안내 필요.
- **힌트**: 안내가 전혀 없으면 못 찾는다 — 근처에서 별이 미세하게 떨림 · 약한 진동 같은 신호 후보. 미정.
- **하단 배치**: 좌 · 중 · 우 3칸 슬롯, 워프 기어가 뜨면 NEXT · SKY 접기, 팝업이 뜨면 하단 정보 한 줄 축소. `safe-area-inset-bottom` · 삼성 인터넷 하단바 높이 변화(visualViewport) · 가로 모드 재배치는 시안에 없음 — **미구현**.
- 대상 데이터(거리 · 밝기 · 뜨고 짐)는 시안에서 Claude 가 아는 값으로 적은 예시다 — 실제 쓰려면 천문 데이터로 **검증 필요**. 워프 도착 사진 5장(지구돋이 · 게 · 오리온 · 창조의 기둥 · 타란툴라)과 해금 대상을 대응시키는 안은 제안일 뿐 미확정.
- 성능: 시안은 2D 캔버스 + SVG 다. 운영 돔은 WebGL 이므로 이식 시 별도 비용 확인이 필요하다(GPU · 폰 실측, `HANDOFF.md` 검증 항목).
