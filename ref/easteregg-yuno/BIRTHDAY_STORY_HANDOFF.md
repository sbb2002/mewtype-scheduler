## 2. 최신 사용자 요구 — 전부 유효

1. 노래를 끝까지 듣고 싶게 하는 예고 → 진행 이야기 → 피날레·감사 카드. 사용자가 제안에 동의했고 구간별 상세 설명을 원함.
2. UFO 스캔 때 밑으로 비추는 빛을 자연스럽게 조정.
3. PC에서 잘리는 유노 사인을 PC/모바일 모두 화면에 맞춰 온전히 표시.
4. 우하단 곡 제목의 `BGM` 글자는 삭제. `♪ 곡 제목` 형식.
5. 새 문구/카드도 PC/모바일에서 잘리지 않게 조절. 작은 화면·가로 화면까지 검증.
6. **가장 최근 추가, 아직 미구현**: 노래를 다 들은 보상으로 플레이바를 확장하고 구분선 뒤에 **폭죽·UFO·사인 등 직접 실행 버튼** 제공.
   - 사용자가 자유롭게 눌러볼 수 있도록 **수동 버튼 실행이 최우선**.
   - 수동 동작 중 기존 고정 이벤트가 겹쳐 발생하지 않도록 억제.
   - 마지막 추가 조작 후 **3초 동안 입력이 없으면** 현재 곡 시각의 고정 루틴으로 복귀.
   - 한 번이라도 해제/열었다면 **해당 브라우저에서 기억**해서 이후 방문에도 제공(localStorage 권장).
7. 최신 요청: 세션 한도 대비 handoff를 우선 작성.

사용자는 이전부터 검증 후 머지·배포를 승인해 왔다. 이 WIP는 완성되지 않았으므로 현재 배포하지 않음. 완료 시 세션 내 승인 범위를 고려해 기존 절차를 이어갈 것.

- root main 유지, 별도 worktree에서 작업. 한국어 커밋/설명과 Co-Authored-By: Codex <noreply@openai.com>.
- PR merge commit, 정확한 head/체크 SUCCESS 확인. 버전 태그는 **코드 병합 커밋**에만 주석 태그로 올리고 이름을 지정해 push. `push --tags` 금지.
- 배포 완료 기록은 별도 docs PR에서 tag 표·배포/롤백 확인 기입.
- Vercel root `src/frontend`, main 자동 배포. 루트 `.env`의 VERCEL_TOKEN을 출력하지 말 것.
- 재사용 가능한 read-only helper: 루트 `tools/birthday-continuation/release_status.py`.
- 예전 `finish_*release.py`, `prepare_*release.py`는 특정 버전/해시/브랜치 하드코딩이므로 **그대로 실행 금지**.
- 운영 파일을 새 code merge SHA query로 요청해 로컬 파일과 UTF-8/개행 정규화 비교. READY만으로 끝내지 말 것.
- 미관련 docs PR #122/#124는 그대로 두었음. 병합할 필요 없음.
- 완성 후 자기 worktree만 clean+main에 merged 확인하고 절대 경로가 지정한 worktrees/v4 아래인지 확인한 뒤 제거. root tools/와 다른 worktree는 보존.

## 10. 사용자 추가 코멘트 — 최신 요구로 우선 적용 (미구현)

이 절은 handoff 작성 후 사용자가 추가한 요구다. 앞 절과 충돌하면 이 절을 우선한다. 이번 업데이트는 문서만 수정하며 아래 기능을 구현했다고 해석하면 안 된다.

### 랜덤 이벤트: 유성우

- 단일 유성뿐 아니라 **여러 유성이 아름답게 떨어지는 유성우**를 추가한다.
- 기존 랜덤 이벤트 원칙(고정 연출 구간 제외, 빈 구간에서 적절한 무작위 빈도, 수동 효과 우선)을 그대로 적용한다. 화면 크기에 맞춰 경로·밀도·시차를 조절하고 PC/모바일에서 검증한다.

### 랜덤 이벤트: YMMT 별자리 — 곡당 1회

- **대문자 `YMMT`**를 별자리로 보여준다. 일반 텍스트를 단순히 표시하는 효과가 아니다.
- 각 글자의 꼭지점마다 **푸른색의 밝은 동그라미 별**이 먼저 나타난다.
- 점이 **모두 나타난 뒤**, “짠!” 하는 느낌의 연출로 점들을 **푸른 선**으로 이어 `YMMT`를 완성한다. 글자 사이를 임의의 선으로 연결해 가독성을 해치지 않게 한다.
- 완성된 별자리를 **5초간 유지**하고, 그 뒤 **서서히 사라지게** 한다. 5초는 점 등장/선 연결 시간이 아니라 완성 후 유지 시간이다.
- **곡당 1회**만 발생한다. 무작위 시점이더라도 고정 연출과 겹치지 않고 전체 등장·연결·유지·퇴장 시간이 들어갈 수 있는 빈 구간을 예약한다.
- 탐색/일시정지/반복/곡 교체 시 중복 발생이나 중간 단계 누적이 없게 한다. “곡당 1회”의 재생 회차 처리 기준을 명세·테스트에 명시할 것.
- PC/모바일 화면 안에서 네 글자 전체·점·글로우가 잘리지 않게 축척·여백을 계산한다. 모션 줄이기 처리와 새 이벤트 성능도 검증한다.

### 2곡 완곡 청취 보상: 사이버펑크 제어 바 확장

- 보상 조건은 **두 곡을 모두 완곡 청취**하는 것이다. 단순히 두 번째 곡 끝 시각을 선택하거나 다음 곡을 눌렀다고 해제하면 안 된다.
- 해제 시 **마이크로인터랙션을 고려해 제어 바가 사이버펑크 느낌으로 늘어나며 기능을 확장**한다. 기존의 구분선과 수동 효과 버튼 요구에 추가되는 시각/상호작용 요구다.
- 기존 음악 UI와 어울리는 네온/패널 확장 흐름으로 구현하되, 확장 도중에도 버튼·제목·하단 안내·화면 경계가 겹치거나 잘리지 않게 검증한다. 움직임 줄이기에서는 과한 이동/점멸을 생략한다.
- 한번 해제한 브라우저의 영구 기억, 수동 효과 최우선, 다른 고정 이벤트 억제, 마지막 추가 조작 후 3초 복귀 요구는 계속 유효하다.

### 이전 곡·다음 곡 버튼도 보상으로 해제

- **최초/보상 전 제어 바에는 이전 곡·다음 곡 버튼이 없어야 한다.** 비활성 스타일로 남겨두지 말고 **보이지 않게** 한다. 키보드 포커스에도 잡히지 않게 한다.
- 두 곡 완곡 청취 보상 해제 후 이전/다음 곡을 제공한다. 해제 기억이 있는 브라우저에는 이후 방문에도 제공한다.
- 앞 절의 “기존 재생 버튼 유지”는 재생/일시정지·음소거·손잡이를 가리키며, 이전/다음 버튼을 처음부터 유지하라는 뜻으로 해석하지 말 것.
- 현재 `bdayplayer.js`는 이전/다음 버튼을 항상 만들고 방향키로 선곡할 수 있다. **아직 수정하지 않았다.** 보상 전 키보드/다른 선곡 경로도 같은 해제 상태를 따르도록 정리하고 테스트한다.
- 기존 `verify_birthday_player_ui.py`에는 보상 전에도 `.prev`가 있다는 전제가 있으므로 새 요구에 맞춰 검증을 수정해야 한다.

### 일시정지 아이콘

- 현재 문자 `Ⅱ`가 `II`처럼 보인다. 사용자는 **실제 일시정지 모양**을 원한다.
- 폰트 문자에 의존하지 않는 **동일한 두 개의 세로 막대 형태**(기존 아이콘 방식의 SVG 또는 CSS 도형 등)로 바꾼다. 버튼 크기·정렬·재생 아이콘 전환·접근성 이름을 유지하고 PC/모바일에서 확인한다.

### 유노 멘트와 텍스트 연출

- 멘트는 **유노의 성격을 고려하면서 감성적이고 사용자를 설레게** 작성한다. 현재 `bdaystorylogic.js`의 문구는 확정본이 아니라 **재검토할 초안**이다.
- 유노의 말투/성격에 관한 저장소 자료나 사용자가 제공한 근거를 우선 참고한다. 근거 없이 특정 성격이나 발언을 사실처럼 만들어 넣지 말 것.
- 폰트 선택과 등장 방식도 **본 생일·사이버펑크 테마에 어울리게** 조정한다. 문구만 바꾸는 작업이 아니다.
- 감정을 살리는 시차/빛/서서히 나타남과 퇴장을 고려하되 읽을 시간을 확보하고, PC/모바일에서 긴 한글·줄바꿈·가로 화면·작은 높이까지 잘림 없이 검증한다.
