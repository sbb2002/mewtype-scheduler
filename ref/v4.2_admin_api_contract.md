# v4.2 신곡 · 곡 관리 — 어드민 API 계약 (백엔드 → 화면)

> 2026-10-06 · 백엔드 구현 완료(`src/backend/songs.py` · `handlers._detect_new_songs` · `admin_api.py` · `admin_web.py` · `telegram_app.py` · `writers.py` · `monitor_report.py` · `llm.py`).
> 화면(음반 탭 · 현황 탭 재편 · 작업 탭 · 어드민 조작 라벨)은 **이 문서만 보고 붙일 수 있게** 적었다. JSON 예시는 로컬 저장소 + 가짜 RSS · 가짜 LLM 으로 실제 실행해 얻은 응답이다
> (재현: 스크래치 `dump_api.py` 방식 — `python -m src.backend.admin_api` 통합 self-test 가 같은 흐름을 검증한다).
> 코드 위치: 읽기 · 쓰기 함수 = `admin_api.py` "(v4.2.0) 음반 탭" 블록, 화이트리스트 = `admin_web.py` `read_functions` / `write_functions`.

## 0. 호출 규약

| 종류 | 호출 | 응답 |
|---|---|---|
| 읽기 | `GET /admin/api/<name>` (인자 없음) | **함수 반환 그대로**(dict) — envelope 없음 |
| 쓰기 | `POST /admin/api/<name>` (JSON 바디 = 키워드 인자, `X-CSRF-Token`) | **envelope** `{ "ok": bool, "job_id": null, "result": {...}\|null, "error": str\|null }` |

- 쓰기는 거절도 HTTP 200 + `ok:false` + `error`(한국어 문구)로 온다. 예상 밖 키워드면 400, 예외면 500 `{ok:false,error}`.
- 쓰기 1건 = 작업 탭 「최근 흐름」의 관리 조작 흐름 1줄 + 「내가 한 조작」 이력 1건(`list_history`).
- **시드 전**(data 브랜치에 `songs.json` 없음)에는 모든 쓰기가 `error: "songs.json 이 없습니다 — 시드 전입니다"` 로 거절된다. 화면은 `list_songs().seeded` 로 먼저 분기할 것.
- 프론트 플레이어는 raw CDN 캐시(최대 ~5분) 때문에 어드민 변경이 곧바로 보이지 않을 수 있다(음반 탭은 어드민이 직접 읽으므로 즉시).

## 1. 데이터 모델 — `songs.json` (data 브랜치)

```jsonc
{
  "songs":    [ /* 곡 */ ],
  "rejected": [ /* 삭제 · 반려한 곡 — 재등록 차단 */ ],
  "seen":     [ /* 판단 기록을 이미 남긴 「곡명 중복 건너뜀」 — 화면에 안 보여도 됨 */ ]
}
```

곡:

| 필드 | 뜻 |
|---|---|
| `id` | YouTube 영상 ID(11자) — 고유 키 |
| `title` | 곡명(끝의 「(Cover)」는 뗀 값) |
| `kind` | `"original"` \| `"cover"` (솔로 없음) |
| `who` | 멤버 키(`arale yuno nonoka ritsu miyako`) 또는 `"group"` |
| `date` | `YYYY-MM-DD` — 영상 업로드 시각의 KST 날짜(공식 발매일 아님) |
| `reading` | 가나 독음, 없으면 `""` |
| `added_at?` | 자동/직접 등록 시각(시드 곡은 없음) |
| `manual?` | `true` = 운영자가 직접 추가했거나 사용자 판단으로 (재)등록한 곡 |
| `edited_at?` | 운영자가 마지막으로 수정한 시각 — **있으면 자동 반려가 덮어 지우지 않는다** |
| `needs_reading?` | `true` = LLM 독음 대기(다음 정기 수집이 재시도, tick 당 3건) |
| `reading_manual?` | `true` = 운영자가 정한 독음(LLM 이 덮지 않음). 「독음 다시 만들기」는 이 값을 `false` 로 되돌린다 |

차단(`rejected`) 항목: `{ "id", "name_key", "title", "ts", "by" }` — `by` = `"admin"`(삭제) · `"반려"`(작업 탭 반려).
`name_key` = 곡명의 정규화 키(NFKC · 소문자 · 공백 · 꼬리표 제거). **차단은 영상 ID 와 곡명 키 둘 다로 막는다.**

## 2. 읽기

### `list_songs`
```json
{
  "seeded": true,
  "counts": { "total": 2, "no_reading": 1, "needs_reading": 0, "auto": 0, "manual": 0, "rejected": 0 },
  "songs": [
    { "id": "OLDSONG0003", "title": "既にある曲", "kind": "original", "who": "group", "date": "2026-09-01",
      "reading": "きぞん", "reading_ko": "기존" },
    { "id": "OLDSONG0009", "title": "もう一曲", "kind": "cover", "who": "arale", "date": "2026-09-02", "reading": "", "reading_ko": "" }
  ],
  "rejected": [ { "id": "Fp2a-MhCFVw", "name_key": "夢我夢中", "title": "夢我夢中", "ts": "2026-10-06T06:25:27Z", "by": "반려" } ]
}
```
- `seeded:false` 면 `songs` · `rejected` 는 빈 목록, `counts` 는 0.
- `reading_ko` = 가나 독음의 한글 변환(프론트 플레이어와 같은 규칙) — 수정 창의 「한글 독음 미리보기」용(입력 중 실시간 변환은 화면이 `js/songs.js kanaToHangul` 을 써도 같은 결과).
- `counts.auto` = `added_at` 이 있고 `manual` 이 아닌 곡(자동 등록분) · `no_reading` = 독음이 빈 곡 · `needs_reading` = LLM 대기 곡 · `rejected` = 차단 항목 수.
- `rejected` 는 최신순.

### `songs_status`  — 신곡 감지 현황(음반 탭 상단 카드 · 시드 전 점검)
호출할 때마다 **토픽 채널 RSS 를 지금 조회**(쿼터 0, ~1초)하고 **쓰기 없이** 등록 예정을 계산한다.
```json
{
  "seeded": true, "song_count": 3, "no_reading": 1, "needs_reading": 1, "rejected_count": 0,
  "now": "2026-10-06T06:25:26Z",
  "feeds": [ { "key": "topic", "name": "Mugendai MewType - Topic", "channel_id": "UCeXzCxZsDcaF5xI68fK5owA",
               "ok": true, "entry_count": 15, "latest_published": "2026-09-29T11:04:29+00:00", "latest_title": "これはぼくたちの生存のあらすじ", "error": null } ],
  "preview": {
    "new":     [ { "id": "Fp2a-MhCFVw", "title": "夢我夢中", "kind": "original", "who": "group", "date": "2026-09-27" } ],
    "skipped": [ { "video_id": "DUPLICATE03", "title": "既にある曲 (Cover)", "reason": "name_dup",
                   "dup_of": { "id": "OLDSONG0003", "title": "既にある曲" }, "recorded": false } ]
  },
  "events": [ /* 최근 7일의 flow="song" 이벤트, 최신순 최대 40건 — §5 */ ]
}
```
- `feeds[].ok:false` + `error` = RSS 가 비었거나 조회 실패(이때 `preview` 는 비어 보인다). tick 쪽 실패 이벤트는 시간당 1회뿐이라 **평소 상태는 이 조회로 본다**.
- `preview.new` = **지금 tick 이 돌면 등록할 곡**(시드 전 점검 = 시드 직후 첫 tick 이 등록할 곡). `seeded:false` 면 `preview` 는 항상 빈 목록(비교할 곡 목록이 없음).
- `skipped[].reason`: `name_dup`(곡명이 이미 있음 — `dup_of` 에 같은 곡) · `feat` · `id_dup`(이미 있는 영상) · `rejected`(차단됨). `recorded` = `name_dup` 에 대해 판단 기록(작업 탭)이 이미 남아 있는가.

## 3. 쓰기 (envelope 응답)

모든 쓰기 성공 응답의 `result` 는 `{ "ok": true, "song"?: {...곡...}, ... }`.

| 함수 | 바디 | 성공 `result` | 대표 오류 문구 |
|---|---|---|---|
| `edit_song` | `{ "song_id": "...", "patch": { "title"?, "reading"?, "kind"?, "who"?, "date"? } }` | `{ok, song}` (수정된 곡) | 「목록에 없는 곡입니다」 · 「고칠 항목이 없습니다」 · 「구분은 오리지널 · 커버 중 하나여야 합니다」 · 「부른 사람이 올바르지 않습니다」 · 「곡명이 비어 있습니다」 · 「날짜는 YYYY-MM-DD 형식이어야 합니다」 · 「같은 곡명이 이미 있습니다 (…)」 |
| `delete_song` | `{ "song_id": "..." }` | `{ok, song}` (지운 곡) — **목록에서 빼고 `rejected` 에 추가** | 「목록에 없는 곡입니다」 |
| `unblock_song` | `{ "ident": "영상ID 또는 name_key" }` | `{ok, unblocked:[{…차단 항목…}], song:null}` — 같은 영상 ID · 곡명의 차단을 모두 해제 | 「차단 목록에 없습니다」 |
| `add_song` | `{ "video": "URL 또는 11자 ID", "title"?, "kind"?, "who"?, "date"?, "reading"?, "force"? }` | `{ok, song, filled_by?}` — `filled_by` = `"RSS"` \| `"YouTube API"`(제목 · 날짜를 자동으로 채웠을 때) | 「YouTube URL 또는 영상 ID(11자)를 입력하세요」 · 「영상의 제목 · 날짜를 자동으로 가져오지 못했습니다 — 곡명과 날짜(YYYY-MM-DD)를 직접 입력하세요」 · 「이미 목록에 있는 영상입니다」 · 「같은 곡명이 이미 있습니다 (…) — 그래도 넣으려면 강제로 추가하세요」 |
| `regenerate_song_reading` | `{ "song_id": "..." }` | `{ok, song, reading, reading_ko}` | 「목록에 없는 곡입니다」 · 「독음을 만들지 못했습니다 (LLM 응답 없음 · 키 없음) — 다음 정기 수집에서 다시 시도합니다」(이때 곡은 `needs_reading` 으로 표시됨) |

세부 규칙(화면 문구에 반영):
- **삭제 = 재등록 차단.** RSS 가 계속 읽어도 되살아나지 않는다. 되살리려면 `unblock_song`(또는 `add_song` 이 차단도 함께 푼다). 확인 대화상자에 「삭제하면 같은 곡이 다시 올라와도 등록되지 않습니다」를 보여 줄 것.
- **`unblock_song` 은 곧바로 곡을 등록하지 않는다** — 다음 정기 수집(10분 안)에서 RSS 최근 15건에 그 곡이 아직 있으면 자동 등록된다(없으면 아무 일도 없음 → 바로 넣고 싶으면 `add_song`).
- `edit_song` 에서 `reading` 을 **채워 저장** = 직접 정한 독음(`reading_manual`, LLM 이 덮지 않음). **비워서 저장** = LLM 이 다음 정기 수집에서 다시 씀(`needs_reading`).
- `add_song`: `kind` 를 비우면 제목 끝 「(Cover)」로 판정, `who` 를 비우면 `group`. `title` · `date` 를 둘 다 주면 자동 조회를 건너뛴다. 곡명 중복은 `force:true` 일 때만 추가. 독음을 비우면 LLM 이 쓴다(`needs_reading`).
  자동 조회 순서: ① 토픽 채널 RSS(쿼터 0) ② YouTube API `videos.list`(쿼터 1, 서버에 키가 있을 때).
- `regenerate_song_reading` 은 동기로 LLM 을 부른다(수 초). 버튼은 처리 중 비활성화. **직접 고쳐 둔 독음도 덮는다**(재요청이므로) — 확인 문구 권장.
- 응답에는 `reading_ko` 가 `songs` 행에는 없을 수 있다(`list_songs` 로 다시 읽을 것).

## 4. 작업 탭 — 신곡 판단 기록 (기존 「LLM 판단」 목록에 같이 나옴)

`list_llm_actions().items[]` 에 두 종류가 추가된다(기존 필드 그대로, `by:"rule"` 만 다름 — 규칙이 낸 판단이라 LLM 이 아니다). 기존 화면 용어 「LLM 판단」은 유지.

```json
{ "id": "llm_8538059f07", "ts": "2026-10-06T12:00:00Z", "kind": "song_register", "who": "group", "by": "rule",
  "summary": "신곡 등록 · 夢我夢中 (오리지널)",
  "reason": "곡명 「夢我夢中」이 목록에 없음 · 제목 끝 (Cover) 없음 → original · feat. 아님 · 반려한 곡 아님",
  "input": { "video_id": "Fp2a-MhCFVw", "title": "夢我夢中", "published": "2026-09-27T11:00:19+00:00", "description": "…" },
  "undo": { "type": "remove_song", "id": "Fp2a-MhCFVw", "title": "夢我夢中", "added_at": "2026-10-06T12:00:00Z" },
  "undone": null, "followup": null, "parent_id": null, "flow_id": null }
```
```json
{ "id": "llm_3b08c94f27", "kind": "song_skip", "who": "group", "by": "rule",
  "summary": "곡명 중복 · 등록 안 함 · 既にある曲",
  "reason": "「既にある曲」와 같은 곡명이 이미 있음 (既にある曲 · OLDSONG0003) — 다른 곡이면 강제 등록",
  "input": { "video_id": "DUPLICATE03", "title": "既にある曲 (Cover)", "published": "…", "description": "", "dup_of": { "id": "OLDSONG0003", "title": "既にある曲" } },
  "undo": null, "undone": null, "followup": null }
```

| kind | 의미 | 반려(`undo_llm_action`) | 사용자 판단(`decide_llm_action`) | LLM 재판단(`rejudge_llm_action`) |
|---|---|---|---|---|
| `song_register` | 자동 등록한 곡 1건 | **목록에서 지우고 `rejected` 에 추가**(재등록 차단). 그때 등록한 그대로일 때만 — 운영자가 그 사이 곡을 수정했으면 `ok:false`, error 「반려로 되돌릴 것이 없습니다 — … 등록 뒤 운영자가 수정함 (지우려면 음반 탭에서 삭제)」. 이미 지운 곡이면 「… 이미 목록에 없음」 | 반려 뒤: **다른 값으로 다시 등록**(차단도 풀림) 또는 등록 안 함 | **없음** — 요청하면 `ok:false`, 「신곡 등록은 규칙 기반 판단이라 LLM 재판단이 없습니다 — 사용자 판단으로 다시 등록하세요」 → **버튼을 숨길 것**(`llm_review_options().rejudge === false`) |
| `song_skip` | 곡명 중복으로 등록하지 않은 영상 1건(검토용, 롤백할 변경 없음) | 표시만 반려됨(`result.review_only:true`) | 반려 뒤: **강제 등록**(곡명이 같아도 다른 곡) 또는 그대로 둠 | 없음(위와 같은 오류) |

- 반려 응답(성공): `{ok:true, result:{applied:["지움 + 재등록 차단 夢我夢中"], skipped:[], restored_video_ids:[]}}`. `song_skip` 은 `applied:[]`, `review_only:true`, `skipped:["롤백할 변경 없음 (검토용 판단)"]`.
- 흐름 줄(`jobs_overview().flows`): `kind:"LLM 판단"`, `stages` 의 두 번째 단계 `x` 가 `"규칙"`(신곡) / `"Groq"`(그 밖), 첫 단계 `x` 가 `"RSS"`(신곡). 로컬 러너에서도 신곡 판단은 같이 나온다. `llm[0].kind` 가 `song_register` / `song_skip` 이면 곡 아이콘 등으로 구분 가능.

### `llm_review_options(action_id)` (POST, 신곡 두 종류의 응답)
```json
{ "kind": "song_register", "who": "group", "rejudge": false,
  "input": { "…": "위 input" },
  "defaults": { "id": "Fp2a-MhCFVw", "title": "夢我夢中", "kind": "original", "who": "group", "date": "2026-09-27" },
  "dup_of": null,
  "kinds": [ { "key": "original", "name": "오리지널" }, { "key": "cover", "name": "커버" } ],
  "whos":  [ { "key": "arale", "name": "나카마치 아라레" }, "…", { "key": "group", "name": "그룹" } ],
  "members": [ "…멤버 5명(그룹 없음)…" ] }
```
`song_skip` 이면 `dup_of: {id, title}` 가 채워진다(같은 곡명인 기존 곡 — 팝업에 「이 곡과 같은 곡명」으로 보여 줄 것). `defaults` 는 입력 스냅샷에서 계산한 기본값(제목 꼬리표 제거 · (Cover) 판정 · KST 날짜).

### `decide_llm_action(action_id, decision)` — `decision` 스키마(신곡)
```jsonc
{ "choice": "register" | "skip",   // song_register: "skip" = 등록 안 함(차단 유지). song_skip: register 가 아니면 등록 안 함
  "title"?: "...", "kind"?: "original" | "cover", "who"?: "arale|…|group", "date"?: "YYYY-MM-DD" }  // 비우면 defaults
```
성공: `{ok:true, result:{ok:true, result:"「夢我夢中」 original · group 로 등록", new_ids:["llm_…"]}}` — `new_ids` 는 이어서 생긴 새 판단 기록(`parent_id` 로 연결, `song_register` — 다시 반려 가능).
선행 조건: 먼저 반려(`undone`)해야 하고, 한 기록의 후속은 한 번만(기존 규칙 그대로 — 어기면 「먼저 반려해야 합니다」 / 「이미 재판단 · 사용자 판단을 했거나 …」).

## 5. 모니터 이벤트 — `flow:"song"` (monitoring 브랜치 이벤트 로그 · 리포트)

공통 필드 `ts · flow · result(ok|degraded|err) · who("group") · detail`, 추가 필드 `action · video_id? · title? · kind? · reason? · action_id? · via?`.

| `action` | 언제 | `result` | 추가 필드 |
|---|---|---|---|
| `added` | tick 이 새 곡 등록 | ok | `video_id title kind action_id`(= 판단 기록 id) |
| `skipped` | 곡명 중복으로 등록 안 함(처음 볼 때 1번) | ok | `video_id title reason:"name_dup"` |
| `reading` | LLM 이 독음 작성 | ok | `video_id title` |
| `rss_empty` | RSS 가 비어 있음(조회 실패 가능) — **시간당 1건**(그 시간 첫 tick) | **degraded** | — |
| `edited` `deleted` `added_manual` `unblocked` `reading_regen` | 운영자 조작(`via:"ops"`) | ok | `video_id title` |
| `rejected` | 작업 탭 반려 | ok | `video_id title` (`via:"ops"`) |

```json
{ "ts": "2026-10-06T12:00:00Z", "flow": "song", "result": "ok", "who": "group", "action": "added", "kind": "original",
  "detail": "신곡 등록 · 夢我夢中 · original", "title": "夢我夢中", "video_id": "Fp2a-MhCFVw", "action_id": "llm_8538059f07" }
```
- 보관 · 스냅샷 · 전 기간 리포트는 **현행 이벤트 로그와 같다**(새 정책 없음). 작업 탭 「최근 자동 처리」(오늘 · 어제)는 `_FLOW_KO["song"] = "신곡"` 으로 `신곡 · group · 신곡 등록 · 夢我夢中 · original` 식 한 줄로 나온다.

### 리포트(모니터링) 일 데이터 — `day.song`
`build_day_from_text` 가 하루 dict 에 추가: `song: [ { "t":"11:00", "tone":"ok|degraded|err", "action":"added", "label":"신곡 등록", "title":"新しい曲", "vid":"…", "ops":false, "d":"detail" } ]`.
타임라인에 「🎵 신곡 감지」 점 레인(결과 색) · 하단 원본 이벤트 로그 표 행 · 범례가 추가됨(구현 완료). **옛 스냅샷에는 `song` 키가 없다 — 프론트는 `day.song || []`**(이미 적용, 렌더 + `node --check` 로 검증).
`ops:true` 면 팝업 제목에 「(운영자)」. 트리거 수 · 요약 카운트는 변하지 않는다.

## 6. 「내가 한 조작」 · 최근 흐름 라벨 (화면의 이름 표에 추가)

`list_history()[].action` 값과 흐름 이름(`ADMIN_FLOW_LABELS`, 백엔드가 이미 정의):

| `action` | 한글 라벨 | `target` | `summary` |
|---|---|---|---|
| `edit_song` | 곡 수정 | 영상 ID | 바꾼 필드 목록(쉼표) |
| `delete_song` | 곡 삭제 | 영상 ID | — |
| `add_song` | 곡 직접 추가 | 영상 ID | 곡명 |
| `unblock_song` | 곡 차단 해제 | 영상 ID 또는 name_key | — |
| `regenerate_song_reading` | 독음 다시 만들기 | 영상 ID | 새 독음 |

작업 탭 「최근 자동 처리」의 작업 이름: `song_edit` → 「곡 관리」(`apply._KIND_LABEL` · `admin_api._AUTO_LABEL`). 조작 `ok:false` 는 `error` 에 사유.
`admin.html` 의 조작 이름 표(`undo_llm_action: "↩ LLM 판단 반려"` 가 있는 객체)에 위 5개를 추가하면 된다(화면 담당).

## 7. 화면 구현 시 알아둘 점

1. **시드 전** — `seeded:false` 인 동안 음반 탭은 「시드 필요」 안내 + `songs_status` 의 RSS 상태 · 등록 예정 미리보기만(쓰기 버튼 비활성). 미리보기에 시드 직후 첫 tick 이 등록할 곡이 나온다.
2. **독음 칸** — 목록 행: `reading`(가나) + `reading_ko`, `needs_reading` 이면 「독음 대기」 배지, `reading_manual` 이면 「직접 입력」 배지. 독음 없음 필터는 `reading === ""`.
3. **자동 등록분 표시** — `added_at` 있고 `!manual`(`counts.auto`) — 「자동」 배지. 수정하면 `edited_at` 이 생겨 이후 반려가 막힌다(위 §4) — 수정 저장 때 이 사실을 알릴 필요는 없지만 반려 오류 문구는 그대로 보여 줄 것.
4. **쓰기 직후** `list_songs` 를 다시 읽어 갱신(응답의 `song` 으로 행만 갈아도 됨). 동시에 tick 이 같은 파일을 쓸 수 있어 드물게 「songs.json 쓰기 충돌이 계속됨 — 잠시 뒤 다시 시도하세요」가 올 수 있다.
5. **이력 보관** — 새 보관 정책 없음. `songs_status.events` 는 최근 7일(이벤트 로그 일별 파일), 작업 탭은 오늘 · 어제, 리포트 탭은 전 기간.
6. 용어는 기존 유지(「LLM 판단」 필터 · 「반려」 · 「사용자 판단」) — 신곡 두 종류도 같은 필터에 나온다. 새 용어(「자동 판단」 등)는 만들지 않았다.
