# 리츠 생일 오르기 게임 — 움직임 프로토타입 MVP 명세

작성 2026-11-03 · 상태 = **명세 초안, 미구현** · 대상 = 리츠 생일(02-07) 이스터에그의 첫 시제품

이 문서의 범위는 **움직임의 손맛 하나**다. 그림 · 사이트 이식 · 보상 연결 · 지형 완성본은 범위 밖이다(§9).
도형(원 · 선)만으로 만든 뒤 "이 조작감이면 된다"를 운영자가 판정하면 다음 단계로 간다.

---

## 0. 용어 (이 문서에서 새로 쓰는 말)

| 용어 | 뜻 |
|---|---|
| **몸통** | 플레이어 본체. 다리가 없어 스스로 걷거나 뛰지 못하는 둥근 덩어리. 최종판에서는 리츠(파란 곰)가 된다. |
| **도구** | 몸통이 쥐고 있는 긴 막대. 땅을 짚고 걸고 밀어서 몸통을 옮기는 유일한 수단. 최종판 후보 = 리츠의 기타(넥 쪽을 쥔다) — 운영자 결정 전. |
| **도구 끝** | 도구에서 지형에 닿는 끝부분(작은 원). 이 프로토타입에서 지형과 부딪히는 도구 부위는 여기뿐이다. |
| **목표점** | 사용자가 가리키는 곳(PC = 마우스 커서, 모바일 = 누르고 있는 손가락). 도구 끝이 이 점으로 가려고 한다. |
| **팔 길이** | 몸통 중심에서 도구 끝까지의 거리. 최소 · 최대가 정해져 있다(`L_MIN` · `L_MAX`). |
| **걸기** | 도구 끝을 턱 · 모서리 위에 올려 몸통이 매달리게 하는 것. |
| **튕기기** | 도구 끝이 땅에 닿은 채로 도구를 빨리 휘둘러, 그 반동으로 몸통을 던져 올리는 것. |
| **되돌림 길** | 실수하면 미끄러지거나 떨어져서 출발점(또는 훨씬 아래)으로 돌아가게 만든 지형 구간. |

## 1. 참고한 장르의 움직임 특징

참고 = 『Getting Over It with Bennett Foddy』(이하 「원작」). 아래는 **Claude 가 알고 있는 지식**으로 정리한 것이다. 원작을 이번에 직접 실행해 확인하지는 않았다. 확실하지 않은 항목은 「확인 필요」로 표시했다.

1. **입력은 포인터 하나뿐이다.** 걷기 · 점프 키가 없다. 포인터로 도구를 움직이는 것이 조작의 전부다.
2. **도구 끝은 몸통을 기준으로 포인터를 따라간다.** 포인터를 몸통 아래로 내리면 도구 끝도 몸통 아래로 간다. 몸통이 움직여도 "몸통에서 어느 쪽으로 얼마나"는 그대로 유지된다.
3. **도구 끝이 막히면 몸통이 대신 움직인다.** 이게 핵심이다. 땅에 닿은 도구 끝을 더 아래로 밀면 땅이 도구를 받치고, 대신 몸통이 위로 올라간다. 오른쪽으로 짚고 왼쪽으로 당기면 몸통이 오른쪽으로 끌려간다.
4. **팔 길이에 한계가 있다.** 너무 멀리는 못 뻗고, 몸통 안쪽으로도 못 들어간다. 원작의 도구는 손 안에서 미끄러져 길이가 바뀐다.
5. **걸 수 있다.** 도구 끝을 턱 위에 올리면 몸통이 그 아래에 매달린다. 그 상태로 포인터를 내리면 몸통이 끌려 올라간다.
6. **휘두르면 날아간다.** 도구 끝이 땅에 닿은 채로 빠르게 휘두르면 몸통이 크게 던져진다. 높은 벽을 넘을 때 쓴다.
7. **몸통은 무겁고 잘 미끄러지지 않는다.** 바위 위에서는 거의 멈춰 서 있다. 대신 미끄러운 재질 구간이 있다.
8. **저장 지점이 없다.** 떨어지면 떨어진 곳에서 다시 오른다. 크게 떨어지면 처음 근처까지 돌아간다.
9. **확인 필요**: 원작은 마우스 커서를 숨기고 **마우스를 움직인 양**으로 도구를 움직이는 것으로 알고 있다(화면의 커서 위치가 아니라 이동량). 이번 MVP 는 운영자 지정대로 **커서 · 손가락의 화면 위치**를 쓴다. 이동량 방식은 비교용 선택 항목으로 둔다(§4.3).
10. **확인 필요**: 원작에서 도구 자루(긴 부분)도 지형과 부딪히는지는 정확히 확인하지 못했다. 이번 MVP 는 도구 끝만 부딪힌다(§9).

**가져오지 않는 것**: 원작의 이름, 항아리에 든 남자, 망치 모양, 지형 배치, 화면 모습, 음악 · 내레이션. 조작 방식만 같은 장르로 따르고, 겉모습은 리츠 장면으로 새로 만든다.

## 2. 동작 환경

- PC: 마우스. 커서 위치 = 목표점.
- 모바일: 터치. **누르고 있는 손가락 위치** = 목표점. 손을 떼면 마지막 목표점을 그대로 유지한다(도구가 갑자기 놓이면 바로 떨어지므로).
- 브라우저: 최신 Chrome · Safari · 삼성 인터넷. 외부 라이브러리 없이 **Canvas 2D** + 직접 만든 물리 계산.
  * Canvas = 웹페이지 안의 빈 도화지. JavaScript 로 매 프레임 지우고 다시 그린다(유노 생일 장면과 같은 방식).
- 빌드 없음, 단일 HTML 파일 하나(§8).

## 3. 화면과 좌표

- 세계 좌표 단위 = `u`. 몸통 반지름 `R = 28u` 를 기준으로 모든 크기를 잡는다.
- 화면 배율 `scale` = `min(화면 폭, 화면 높이) × 0.22 / L_MAX`. 즉 최대 팔 길이가 화면 짧은 변의 22% 정도로 보인다. 폰 · PC 모두 같은 비율로 보이게 하려는 것이다.
- 기기 화소 비율(devicePixelRatio)은 최대 2 까지만 반영한다(폰 발열 방지).
- **카메라**: 몸통이 항상 화면의 고정 위치(가로 가운데, 세로 55%)에 오도록 카메라를 몸통에 붙인다.
  - 이유: 목표점을 "포인터 화면 위치 − 몸통 화면 위치"로 계산하기 때문이다. 카메라가 늦게 따라오면 손을 가만히 둬도 도구가 저절로 움직인다.
  - 화면 흔들림이 거슬리면 조정 항목으로 남긴다(§7).

## 4. 입력

### 4.1 목표점 계산 (매 물리 단계마다)

```
off      = 포인터 화면 좌표 − 몸통 화면 좌표        (화면 px → ÷ scale 로 u 로 바꾼다)
len      = clamp(|off|, L_MIN, L_MAX)
want     = off 방향의 단위 벡터 × len               (|off| ≈ 0 이면 직전 방향 유지)
```

`want` = 몸통 중심에서 본 "도구 끝이 있어야 할 자리".

### 4.2 도구 속도 제한

도구 끝은 순간이동하지 않는다. 실제로 쓰는 상대 위치 `d` 는 `want` 쪽으로 **한 단계에 최대 `TOOL_SPEED × dt` 만큼만** 움직인다.

```
d += clampLength(want − d, TOOL_SPEED × dt)
```

이 제한이 튕기기의 세기를 정한다. 너무 크면 몸통이 총알처럼 날아가고, 너무 작으면 튕기기가 안 된다.

### 4.3 입력 방식 (MVP 기본 + 비교용)

| 방식 | 내용 | MVP |
|---|---|---|
| **절대(기본)** | 4.1 그대로. PC 커서 · 모바일 손가락 위치 | 필수 |
| 이동량(비교용) | 포인터를 움직인 양만큼 `want` 를 옮긴다. PC 는 포인터 잠금(Pointer Lock), 모바일은 화면 어디서든 끌기 | 선택. 주소 `?input=rel` |

모바일 절대 방식은 손가락이 몸통 근처를 가린다. 그게 불편한지 운영자가 비교해 보도록 이동량 방식을 함께 둔다.

### 4.4 모바일 처리

- 캔버스 전체에 `touch-action: none` — 스크롤 · 확대 · 당겨서 새로고침을 막는다.
- `pointerdown` · `pointermove` 로 손가락 위치를 받고, `pointerup` · `pointercancel` 이면 마지막 값을 유지한다.
- 손가락이 둘 이상이면 처음 누른 손가락만 쓴다.
- 길게 누르기 메뉴 · 글자 선택이 뜨지 않게 막는다(`user-select: none`, `contextmenu` 막기).

## 5. 물리 (핵심)

### 5.1 고정 시간 간격

- 물리 한 단계 `dt = 1/120 초`. 화면 프레임마다 누적 시간만큼 단계를 돌리고, 한 프레임에 최대 8단계까지만 돌린다(느린 기기에서 계산이 계속 밀리지 않게).
- 탭이 숨겨지면 멈추고, 돌아오면 누적 시간을 버리고 이어간다.

### 5.2 상태

```
몸통: p (위치), v (속도)
도구: d (몸통 기준 도구 끝 상대 위치), 도구 끝 위치 q = p + d
접촉: tipContact (도구 끝이 지형에 닿았는가, 닿은 면의 법선 · 마찰)
```

### 5.3 한 단계의 순서

위치를 먼저 예측하고, 겹침을 밀어내 고친 뒤, 고친 위치에서 속도를 거꾸로 구한다. 이런 방식을 위치 기반 물리(PBD)라고 부르며, 막대로 짚고 밀기처럼 "단단히 붙는" 움직임이 튀지 않고 안정적이다.

```
1. v += GRAVITY × dt                      // 중력은 몸통에만 (도구는 무게 없음)
   v *= exp(−AIR_DRAG × dt)
   p̂ = p + v × dt                         // 몸통 예측 위치

2. d 갱신 (§4.2)
   q̂ = p̂ + d                              // 도구 끝 예측 위치

3. 반복 ITER 회 (기본 4):
   a. 도구 끝 충돌: q̂ 가 지형에 파고들었으면 법선 방향으로 밀어낸 q_c 를 구한다.
      마찰: 직전 단계에도 닿아 있었다면, 면을 따라 미끄러진 거리를
            min(TIP_FRICTION × 파고든 깊이, 미끄러진 거리) 만큼 되돌린다.
            → 살짝 눌러 짚으면 끝이 그 자리에 박혀 있다.
   b. 반동을 몸통에 넘긴다: e = q_c − q̂
      p̂ += e × BODY_SHARE                 // 기본 1.0 = 막힌 만큼 몸통이 전부 움직인다
      q̂ = p̂ + d
   c. 몸통 충돌: 원(반지름 R)과 지형 선분. 파고들면 밀어내고 면 마찰(BODY_FRICTION) 적용.
      몸통이 밀려나 도구 끝이 다시 파고들면 다음 반복에서 a 가 다시 고친다.

4. 몸통이 이번 단계에 움직인 거리를 MAX_BODY_SPEED × dt 이내로 자른다.
   v = (p̂ − p) / dt,  p = p̂               // 고친 위치에서 속도를 구한다
```

### 5.4 이 순서로 원작의 특징이 나오는지

| 특징 | 어떻게 나오나 |
|---|---|
| 도구로 버티고 서기 | 중력으로 몸통이 내려감 → 도구 끝도 내려가 땅에 파고듦 → 밀려 나온 만큼 몸통이 다시 올라감 → 멈춰 있음 |
| 밀어 올리기 | 목표점을 땅속으로 내림 → 도구 끝이 막힘 → 몸통이 그만큼 위로 |
| 걸기 · 매달리기 | 도구 끝을 턱 위에 올리면 몸통 무게가 도구 끝을 턱 쪽으로 누름 → 턱이 받쳐 매달림. 따로 만들 필요 없이 3-a · 3-b 에서 저절로 생긴다 |
| 튕기기 | 도구 끝이 닿은 채 `d` 가 빠르게 돌면 몸통이 한 단계에 크게 밀림 → 4 에서 그 이동이 속도가 됨 → 손을 떼듯 끝이 떨어지면 몸통이 날아감 |
| 미끄러운 구간 | 그 선분의 `TIP_FRICTION` · `BODY_FRICTION` 을 낮춘다 |

### 5.5 지형 충돌

- 지형 = 선분 목록. 선분마다 재질(`rock` · `slick`)을 붙인다. 재질별 마찰은 §7.
- 원(몸통 · 도구 끝) 대 선분 최근접점 계산. 선분 수가 200개 이하라서 전부 검사해도 된다.
- **뚫고 지나가기 방지**: 도구 끝은 한 단계에 "도구 이동 + 몸통 이동"만큼 움직인다. 시작값 기준 13.3u + 11.7u = 25u 이므로, **가장 얇은 벽도 60u 이상**으로 만든다. 조정값을 키우면 이 하한도 같이 키운다(한 단계 최대 이동 × 2 이상). 지형 벽은 선 한 줄이 아니라 **두께 있는 덩어리(닫힌 다각형)**로 만든다.

## 6. 시험 코스 (MVP 지형)

한 화면 높이의 약 4배. 위로 올라갈수록 어렵다. 모든 지형은 회색 다각형, 미끄러운 구간은 파란색으로 구분한다.

| 순서 | 구간 | 확인하려는 동작 |
|---|---|---|
| 1 | 평평한 출발 바닥 + 낮은 계단 2개 | 밀어 올리기 · 기어가기 |
| 2 | 위로 튀어나온 턱(아래가 비어 있음) | 걸기 · 매달려 끌어올리기 |
| 3 | 좁은 굴뚝(양쪽 벽 사이 폭 = 몸통 지름 × 1.6) | 벽 짚고 버티며 오르기 |
| 4 | 미끄러운 비탈 — 실패하면 출발 바닥까지 미끄러져 내려간다 | **되돌림 길** |
| 5 | 몸통보다 높은 벽 하나 | 튕기기로 넘기 |
| 6 | 꼭대기 골인 깃발 영역 | 골인 판정 |

- 골인: 몸통 중심이 골인 영역 안에 1초 머물면 「골인」 문구 + 걸린 시간 · 떨어진 횟수 표시. 보상 연결은 하지 않는다.
- 떨어진 횟수: 한 번에 몸통이 화면 높이 이상 내려가면 1회로 센다.
- 화면 구석에 현재 높이(m 표기, 100u = 1m)와 최고 높이를 작게 표시한다.
- 지형 좌표는 코드 안의 배열 하나로 둔다(수정하기 쉽게).

## 7. 조정값 (시작값 — 운영자가 만져 보고 고친다)

| 이름 | 시작값 | 뜻 |
|---|---|---|
| `R` | 28u | 몸통 반지름 |
| `TIP_R` | 6u | 도구 끝 반지름 |
| `L_MIN` · `L_MAX` | 40u · 150u | 팔 길이 최소 · 최대 |
| `GRAVITY` | 1800 u/s² | 중력 |
| `AIR_DRAG` | 0.15 /s | 공기 저항 |
| `TOOL_SPEED` | 1600 u/s | 도구 끝이 목표점으로 가는 최대 속도 |
| `BODY_SHARE` | 1.0 | 도구 끝이 막힌 만큼 몸통이 움직이는 비율 |
| `MAX_BODY_SPEED` | 1400 u/s | 몸통 최대 속도(튕기기 상한) |
| `TIP_FRICTION` rock · slick | 4.0 · 0.3 | 도구 끝 마찰 |
| `BODY_FRICTION` rock · slick | 0.8 · 0.05 | 몸통 마찰 |
| `ITER` | 4 | 한 단계 안의 충돌 고침 반복 횟수 |

- 주소에 `?debug=1` 을 붙이면 화면 오른쪽에 위 값을 바꾸는 슬라이더를 띄운다. 값은 그 자리에서 바로 반영된다.
- 같은 모드에서 목표점(점선 원) · `want` · 실제 도구 끝 · 접촉 법선을 함께 그린다. 손맛을 고칠 때 무엇이 막혔는지 보이게 하려는 것이다.
- 「값 복사」 버튼: 현재 조정값을 JSON 으로 클립보드에 복사한다. 운영자가 마음에 든 값을 그대로 전달할 수 있게.

## 10. 합격 기준 (Claude 가 직접 확인한 뒤 보고)

구문 검사만으로 통과라고 하지 않는다. Chrome 에서 직접 조작하고, 숫자는 디버그 표시로 읽는다.

1. **버티기**: 도구 끝을 몸통 바로 아래 땅에 대고 손을 멈추면, 몸통이 3초 동안 1u 이상 떨리거나 흘러내리지 않는다.
2. **밀어 올리기**: 계단 1개를 도구로 밀어 올라설 수 있다.
3. **걸기**: 턱에 도구 끝을 걸고 매달린 채 3초 버틴 뒤 끌어 올라갈 수 있다.
4. **튕기기**: 평지에서 휘둘러 몸통 높이의 2배 이상 던질 수 있다. 반대로 손을 천천히 움직일 때는 날아가지 않는다.
5. **되돌림 길**: 미끄러운 비탈에서 실패하면 실제로 출발 바닥까지 미끄러진다.
6. **뚫림 없음**: 도구를 최대 속도로 휘둘러도 도구 끝 · 몸통이 벽을 통과하지 않는다(얇은 벽 포함 20회 시도).
7. **골인**: 처음부터 끝까지 실제로 올라가 골인 문구를 본다(Claude 가 한 번은 직접 깬다).
8. **모바일**: 폰 폭(최소 360px)에서 끌기 중 페이지가 스크롤 · 확대되지 않고, 손을 떼도 도구가 그대로 있다.
9. **성능**: PC Chrome 에서 물리 1프레임 계산 평균 1ms 이하(디버그 표시). 실제 폰 체감은 운영자 확인 항목.
10. **멈춤**: 탭을 숨겼다 돌아오면 몸통이 순간이동하지 않는다.

합격 판정(손맛)은 운영자가 한다. Claude 는 1~10 의 결과와 아쉬운 점을 그대로 보고한다.
