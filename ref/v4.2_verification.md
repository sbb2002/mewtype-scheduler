## 2. 구현 담당 작업이 보고한 검증 (제가 재실행하지 않음)

- **백엔드**: 로컬 저장소 + 가짜 RSS · 가짜 LLM 으로 감지 → 판단 기록 → 반려 → 재감지해도 재등록 안 됨 → 사용자 판단 재등록 → 삭제 · 차단 해제 → 재등록 / 직접 추가 / 수정 / LLM 독음 실패 → 재시도 · 재요청.
- **어드민 화면**: 헤드리스 Chrome(PC 1280 · 모바일 390)에서 탭 7개 · 현황 세부 탭 3개 · 음반 탭 전 조작 · 작업 탭 반려 · 사용자 판단 · 소식 세부 탭 배너, 콘솔 오류 0 · 가로 넘침 없음, 조작 후 저장 데이터 변화까지 확인.
- **리포트**: 신곡 레인 · 이벤트 표 렌더, 옛 스냅샷 호환.

## 3. 남은 검증 · 알려진 문제 (배포 · 시드 전에 처리)

1. **시드 전 미리보기가 비어 있다**(구현 담당 보고 · 계획 R5 와 어긋남): `songs_status` 는 `songs.json` 이 없으면 등록 예정 · 건너뜀을 항상 비워 돌려준다. 시드 직후 첫 tick 이 곡 10개를 즉시 등록하므로 **시드 전 확인 수단이 없다.**
   후보: ① 시드를 어드민 버튼으로 만들고 시드 전에 `assets/songs.json` 기준 미리보기 제공(백엔드 이미지는 `src/frontend/` 가 `.dockerignore` 제외라 `config/` 에 시드 사본이 필요) ② 시드 전에도 빈 목록 기준 dry-run 표시(후보 과다) ③ 운영자가 로컬에서 `find_new_songs` 로 직접 확인. **미결정.**
2. **`telegram_app` self-test 출력의 "fail" 1건** 문구 확인(의도된 시험 로그인지).
3. **실환경 미검증**: Cloud Run 에서의 실제 RSS 조회(이 PC 는 RSS 404) · Groq 독음 실호출 · 어드민 `songs_status` 의 실제 RSS · 시드 전 상태의 모바일 화면 · 로그인 링크(마법 링크) 경로(시험은 세션 쿠키를 직접 심음).
4. **통합 시험 재현**: 구현 담당이 쓴 시험 서버 · 하네스는 스크래치 폴더에만 있고 저장소에 없다. 같은 시험을 반복하려면 로컬 러너(`V4A_RUNTIME=local`) + 가짜 RSS 시드를 다시 만들어야 한다.
5. **목업 미결 질문 4건은 목업 그대로 구현**(독음 생성 중/실패 배지 범위 · 직접 추가 시 곡명 중복은 두 번 확인 · 직접 저장하면 「LLM 작성」 배지 해제 · 모바일 상세는 바닥 시트) — 운영자 확인 필요.
6. `docs/TERMINOLOGY.md` 는 운영자 결정대로 변경하지 않음(작업 탭 필터 「LLM 판단」 유지 — 신곡 판단은 규칙 기반인데 같은 필터에 나온다).
