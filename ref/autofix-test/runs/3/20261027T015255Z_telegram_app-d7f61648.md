### 원인

증명된 부분: `_commit_personal_tweet` 이 tweets.json 을 읽은 뒤 `gh.read_json("tweet_archive.json")` 을 호출한다. GitHub Contents API 응답은 200 이었는데 `content` 필드가 비어 있었고, 그러면 `gh_store.read_json` 이 `RuntimeError("No content in response ...")` 를 던진다. 이 예외는 그 안의 `except (ValueError, KeyError)` 에 걸리지 않고 위로 올라가며, `_commit_personal_tweet` 에는 이 경우를 위한 폴백이 없다. 결국 바깥 `except Exception` 에서 mode="error" 를 반환하고, 그 트윗은 tweets.json 에 쓰이지 않는다.

증명하지 못한 부분: 응답 content 가 왜 비었는지다. 200 인데 content 가 비는 경우로는 ① 파일이 실제로 0바이트인 경우와 ② GitHub Contents API 가 1MB 넘는 파일에 content 를 빈 값으로 주는 경우가 있다. 코드에서 확인되는 사실은 tweet_archive.json 이 개수 상한 없이 계속 붙여 쓰기만 하는 파일(`_archive_push`)이라 언젠가 1MB 를 넘을 수 있다는 것까지다. 실제 파일 크기와 내용은 이 스냅샷으로 확인할 수 없어서 원인을 단정하지 않는다.
