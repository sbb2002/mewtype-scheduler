## A. 하루 구간 04:00 + 내일 구간 (`timetable.js` · `render.js`)

### A1. 순수 함수 (DOM 없음 — selfcheck 대상)
| 함수 | 변경 |
|---|---|
| `DAY_START_HOUR` | 6 → **4**. 주석의 「monitor_log.DAY_START_HOUR 와 같은 하루 경계」 삭제(프론트 전용 값이 됨). |
| `dayWindow(nowMs, offset = 0)` | 반환 `{ ds, de }` 를 `offset * DAY_MS` 만큼 민다. `offset` 0 = 오늘, 1 = 내일. |
| `classify(items, archive, nowMs, order)` | 반환에 `tomorrow` 추가. `live` · `ended` · `upcoming` 은 **오늘 구간** 기준 그대로. `tomorrow` = announced/upcoming/watching 이고 시각이 `[de, de+DAY)` 인 것(`{item,start,end:null}`, 시작순). `later` = `s >= de+DAY` 이거나 `time_tbd` · 시각 없음. |

- 합동 팬아웃(`itemKeys`)은 그대로 — `tomorrow` 도 멤버별로 거른다.
- `ended` 는 `state==="end"`(끝 > `ds`) + 보관함(`preview_archive.json`)에서 `a >= ds` — 04:00~06:00 에 시작한 방송이 새로 포함된다. 보관함은 `build_archive_appends` 가 지우지 않고 계속 붙이므로(확인함) 데이터 쪽 변경은 필요 없다. (1MB 한도 회전 대상인지는 **확인 필요**.)
- `live` 는 날짜 구간과 무관하게 지금 라이브인 것 전부(현행 유지).

### A2. 타임테이블(PC 테이블 보기)
- 상태: `render.js` 모듈 변수 `dayOffset`(0|1). 75초 폴링 · 보기 방식 전환 · 창 크기 변화로 다시 그려도 **유지**.
- `renderBoard`: `dayOffset===1` 이면 `buildTimetable(ctx1)` 에 `ctx1 = { ...ctx, ds: 내일.ds, de: 내일.de, live: [], ended: [], upcoming: ctx.tomorrow, offset: 1 }` 를 넘긴다(블록 배치 `layoutRow` 가 `ctx.ds` 만 쓰므로 그대로 동작).
- **오늘 구간이 끝나는 순간**(`tickTimetable` 이 true — 기준은 항상 오늘의 `__ttDe`): `dayOffset` 이 1 이었다면 **0 으로 되돌린다**(보던 날짜가 그대로 「오늘」이 되므로 화면이 안 바뀐 것처럼 이어진다).
- 머리줄(`buildBoardHead`): 제목 「오늘 예고」 / 내일이면 「내일 예고」. 메타 문구 `mdw(ds) 04:00 ~ 익일 04:00 · 예정 N건 …`. 내일 구간에서는 방송 중 · 종료 건수 문구 없음.
- 내일 구간 화면: **지금 선 · 지난 구간 음영 · 자정 점선(현재 구간 기준) 숨김**, 빈 행 문구 「내일 예정 없음」. 범례는 그대로.
- **시간축**: 04:00 시작 + **4시간 간격**(04·08·12·16·20·00·04). 3시간 간격이면 04·07·10… 처럼 어색해서 바꾼다. 자정 강조(`.is-midnight`)는 `h===18` → **`h===20`**, 마지막 눈금 = 익일 04:00. `css/timetable.css` 의 자정 점선 `.tt__mid`(237행) 위치가 75% 고정이면 `20/24 = 83.33%` 로 고친다(**CSS 확인 필요** — 읽지 않음).
- **일 이동 버튼**: 표 오른쪽 끝에 세로로 긴 `>`(`오늘 구간`) / `<`(`내일 구간`). 기존 가로 넘침 화살표(`.tt__arr`, `wireOverflow`)와 겹치지 않게 **`.tt__sw` 바깥 오른쪽 띠**에 둔다. `aria-label` = 「내일 예고 보기」 / 「오늘 예고 보기」. 키보드 Enter · Space.
- **끌어서 넘기기(PC 마우스 전용)**: 표의 **빈 영역**(블록 `.tt-blk` · 팝업 · 버튼 위가 아닌 곳)에서 `pointerdown` → 가로로 이동한 만큼 `grid` 전체(5행 + 시간축)를 `translateX`로 같이 움직인다. 폭의 25% 이상 끌었거나 빠른 플릭이면 이동 확정, 아니면 제자리로 복귀. 오른쪽→왼쪽 = 내일, 반대 = 오늘. 전환 애니메이션 280ms(`FOLD_MS` 와 같은 값), `prefers-reduced-motion` 이면 애니메이션 없이 바로.
  - 터치(`pointerType !== "mouse"`)는 끌기를 달지 않는다 — 태블릿 폭의 PC 구성에서 가로 넘침의 기본 스크롤과 충돌하므로 버튼으로만.
  - 끌기 중 블록 클릭(카드 팝업)이 오발되지 않게 이동 거리 > 5px 이면 click 을 막는다. 열려 있는 카드 팝업은 이동 시작 시 닫는다(`closeCardPop`).
- (미정 — 결정 1) `>` 버튼에 내일 예정 건수 표시(예: `> 2`). 기본안 = **표시**: 자정 전 「내일 아침 방송이 있다」는 사실을 버튼 클릭 전에 알 수 있어 이번 문제의 직접 해법이다.

### A3. 카드 보기(모바일 카드 · PC 카드 보기 공용 — `buildTodayCards`)
- 한 멤버 카드 묶음 = **종료(필터 적용) → 방송 중 → 오늘 예정 → 내일 구분선 → 내일 예정**. 일 이동 버튼 · 끌기 없음(카드는 다 보여 준다).
- **내일 구분선** = 작은 한 줄 `내일 10/30(금)`(내일 예정이 1건 이상일 때만). 오늘 남은 카드가 0건이고 내일이 있으면 「오늘 남은 예고가 없습니다.」 한 줄 + 구분선 + 내일 카드.
- **종료 카드 제거 규칙**(운영자 지시): 종료된 카드는 **종료 시각(없으면 시작 시각)의 KST 날짜가 오늘 날짜보다 이전이면 없앤다**(= 자정을 넘기면 사라짐). 종료 기준으로 한 이유: 23시에 시작해 01시에 끝난 방송이 끝난 직후에 사라지지 않게. (확정 필요 — 결정 2)
  - 알려진 차이: 00:00~04:00 에는 PC 표(04:00 경계)에는 어제 종료 방송이 남고 카드에는 없다. 실제 화면 보며 판단.
- `bigIdx`(크게 보이는 첫 카드) = 종료가 아닌 첫 카드(오늘 예정이 없으면 내일 첫 카드).
- 머리줄 메타: `예정 N · 내일 M`(내일 0건이면 생략). `todayCard` 의 카운트다운 링(`ringPct` 24시간 기준)은 24시간 넘게 남은 카드에서 빈 링이 된다 — 구현 후 화면 보고 필요하면 보완.

### A4. 「이후 예고」 접힘 버튼
- 대상 = 새 `later`(모레 04:00 이후 · 시각 미정). 건수 0 이면 버튼 · 목록 없음(현행 규칙).
- 문구 「오늘 이후 예고 N건 펼치기/접기」 → **「이후 예고 N건 펼치기/접기」** (`buildFoldButton`).
- 접힘 상태 관리(`board--later-open` 클래스, `toggleLater`)는 그대로.

### B2. 라이브 아바타 효과
- `renderBoard` 가 레인을 다 만든 뒤(**`initMobileCarousel` 이전** — 클론이 클래스를 같이 복제하도록) `ctx.live` 의 각 항목에 대해 `itemKeys(item, order)` 의 멤버(합동 참여자 포함) 레인에 `lane--live` 클래스를 단다. 라이브가 아닌 레인은 클래스 없음(매번 다시 그리므로 따로 제거 불필요).
- CSS: `.lane--live .lane__avatar` → 빨간 테두리 + 은은한 글로우(`box-shadow: 0 0 0 2px var(--color-live), 0 0 10px 2px color-mix(in srgb, var(--color-live) 55%, transparent)`) + 느린 호흡 애니메이션. `prefers-reduced-motion` 이면 애니메이션 없이 정적 테두리.
- 적용 위치(= `.lane__avatar` 하나로 모두 해당): PC 표 왼쪽 칸 · 모바일 레인 머리 · PC 카드 보기 5열 머리. **모바일 하단 멤버 전환 점(`.dot`)** 은 아바타 이미지를 복사해 쓰므로(`render.js:796`) `lane--live` 이면 `dot--live` 를 달아 같은 효과를 준다.
- 갱신 시점: 75초 폴링 재렌더(라이브 시작 · 종료 반영 지연 ≤ 약 75초 — 현행 카드 상태와 같다).
- 범위(결정 3): 기본안 = PC · 모바일 **전부**(한쪽만 하면 초록 링 제거와 어긋남).

## 미결정 / 확인 필요 (기본안으로 표시)
1. `>` 버튼에 내일 건수 표시 — 기본안 **표시**.

3. 라이브 아바타 효과 범위 — 기본안 **PC · 모바일 전부**.
4. 한 PR 로 묶을지(A+B) 나눌지 — 기본안 **한 버전으로 묶되 커밋은 A · B 분리**.
5. 확인 못 한 것: `.tt__mid` CSS 위치, 보관함 1MB 회전 대상 여부, 뱃지 빨강과 `--color-live` 의 색조 구분.
