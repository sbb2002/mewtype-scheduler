예시 (요일은 2026년 기준)
- 10/30(금) 10:00 → 오늘 예고 = 10/30(금) 04:00 ~ 10/31(토) 04:00, 내일 예고 = 10/31(토) 04:00 ~ 11/1(일) 04:00.

용어(새 말 — TERMINOLOGY.md 에 올릴 것)
- **오늘 예고 · 내일 예고** = 위 표의 뜻. 코드에서는 「오늘 구간」 · 「내일 구간」(`dayWindow(now, 0|1)`)으로 부른다.

- **익일 새벽 칸** = 표 오른쪽 끝, 실제 다음 날 00:00 ~ 04:00 에 해당하는 4시간. 표 바탕보다 밝은 톤으로 칠한다(옛 자정 점선 `.tt__mid` 를 대신함).
- **라이브 아바타 효과** = 라이브 중인 멤버의 프로필 이미지(아바타) 둘레에 두르는 빨간 테두리 · 글로우.
- **탭 제목 라이브 표시** = 라이브가 있을 때 브라우저 탭 제목 앞에 붙는 `🔴 LIVE n · `.
- **예고 캐시 보관함 / 예고 일자 보관함** = 기존 용어 「캐시 보관함」 · 「일자 보관함」(TERMINOLOGY 202~203행)에 예고 대상을 더한 것 — `preview_archive.json` / `preview_archive/YYYY-MM-DD.json`.
- 「이후 예고」의 뜻이 바뀐다: 전엔 「오늘 구간 밖 전부」, 이후는 **「내일 예고 밖(그다음 04:00 이후) + 시각 미정」**.

## A. 하루 04:00 + 오늘 · 내일 예고 (`timetable.js` · `render.js` · `main.js` · `css/timetable.css` · `css/theme.css`)

### A1. 순수 함수 (DOM 없음 — selfcheck 대상)
| 함수 | 변경 |
|---|---|
| `DAY_START_HOUR` | 6 → **4**, `export` 한다(A2 의 익일 새벽 칸 위치 계산에 쓴다). 주석 「monitor_log.DAY_START_HOUR 와 같은 하루 경계」 삭제(프론트 전용 값이 됨). |
| `dayWindow(nowMs, offset = 0)` | 반환 `{ ds, de }` = **지금 시각이 들어 있는 04:00 하루**(현행 계산과 같고 경계만 04:00), `offset * DAY_MS` 만큼 민다. `offset` 0 = 오늘 예고, 1 = 내일 예고. |
| `classify(items, archive, nowMs, order)` | 반환에 `tomorrow` 추가. `live` · `ended` · `upcoming` 은 **오늘 예고** 기준 그대로. `tomorrow` = announced/upcoming/watching 이고 시각이 `[de, de+DAY)` 인 것(`{item,start,end:null}`, 시작순). `later` = `s >= de+DAY` 이거나 `time_tbd` · 시각 없음. |

- 합동 팬아웃(`itemKeys`)은 그대로 — `tomorrow` 도 멤버별로 거른다.
- `ended` 규칙은 현행 그대로(경계만 04:00): `state==="end"` 이고 끝(`state_since`) > `ds`, 또는 보관함에서 시작(`actual_start`) ≥ `ds` · 길이 10분~12시간. → 04:00~06:00 에 시작한 방송이 새로 포함된다.
  보관함은 C 이후에도 프론트가 읽는 캐시 보관함에 최근 7일이 남으므로 오늘 예고 분량은 항상 있다.
- `live` 는 날짜 구간과 무관하게 지금 라이브인 것 전부(현행 유지).

### A2. 타임테이블(PC 테이블 보기)
- 상태: `render.js` 모듈 변수 `dayOffset`(0 = 오늘 예고 | 1 = 내일 예고). 75초 폴링 재렌더 · 보기 방식 전환 · 창 크기 변화에도 **유지**, **새로고침하면 0** — 저장하지 않는다(다음 방문에 내일 화면이 먼저 뜨면 헷갈리므로).
- `boardEl.__ttDe` 는 언제나 **오늘 예고의 `de`**(재렌더 판정 기준).
- **04:00 이 되는 순간**(`tickTimetable` 이 true → `main.js` 가 `paintBoard`): `dayOffset` 이 1 이었다면 **0 으로 되돌린다**. 보던 하루가 그대로 오늘 예고가 되므로 화면 내용은 바뀌지 않은 채 이어진다(이때는 넘기기 애니메이션 없음).
- **머리줄**(`buildBoardHead`): 제목 = 「오늘 예고」 / 「내일 예고」. 메타 = `mdw(ds) 04:00 ~ 익일 04:00 · 예정 N건 …`. 내일 예고에서는 방송 중 · 종료 건수 문구 없음.
- **내일 예고 화면**: 지금 선 · 지난 구간 음영(`.tt__past`) 없음, 빈 행 문구 「내일 예정 없음」. 범례는 그대로.
- **시간축**: 04:00 시작 + **4시간 간격**(04 · 08 · 12 · 16 · 20 · 00 · 04). 눈금 반복(현 `h += 3`, 자정 `h === 18`)을 `h += 4`, 자정 = **`h === 24 - DAY_START_HOUR`(=20)**, 마지막 눈금 = 익일 04:00.
  자정 눈금의 글자(`자정 · 익일 10/30(금)`, `.is-midnight` 색)는 그대로 둔다. 칸 세로 눈금선(`.tt__track` 의 `repeating-linear-gradient … calc(100% / 8)`)도 4시간 간격에 맞춰 `calc(100% / 6)`.
- **익일 새벽 칸**(자정 점선 `.tt__mid` 를 대신함, 2026-10-29 운영자 지시):
  - 위치 = 표 오른쪽 끝 `(24 - DAY_START_HOUR) / 24`(=83.33%) ~ 100%, 시간축 아래 모든 행. 오늘 예고 · 내일 예고 둘 다 같은 자리.
  - 그리는 층 = **블록 아래**(각 `.tt__track` 의 배경). 지금 `.tt__ov`(지금 선 · 음영 층)는 블록 위에 덮이므로 거기 두면 블록 색이 바랜다. `.tt__track` 의 `background-image` 에 `linear-gradient(to right, transparent var(--dawn-l), var(--color-dawn) var(--dawn-l))` 를 눈금선과 함께 겹치고, `--dawn-l` 은 `buildTimetable` 이 `DAY_START_HOUR` 로 계산해 그리드에 넣는다(경계를 또 바꿔도 어긋나지 않게).
  - 색 = 표 바탕을 그대로 두고 **한 단계 밝은 톤**. 새 토큰 `--color-dawn`: 어둡게(`layout.css`) 예 `rgba(255, 255, 255, 0.045)`, 밝게(`theme.css`) 는 바탕이 이미 밝으므로 같은 계열의 옅은 색조(예 `rgba(107, 91, 196, 0.05)`). **최종 값은 화면 보고 정한다**(E ④). 경계 쪽에 1px 옅은 선(`inset 1px 0 0`)을 같이 둬서 칸이 시작되는 자리가 보이게 한다 — 모형(안 4)과 같은 표현.
  - `.tt__mid` 요소 · CSS(`timetable.css:237-244`)는 삭제.
- **일 이동 버튼 · 화면 넘기기** = A3.

### A3. 화면 넘기기 — 구조 · 마이크로 인터랙션
모형(안 4)의 ＜ ＞ 는 화면을 즉시 바꿀 뿐이다. 실제 구현은 아래처럼 **표가 옆으로 밀리는 동작**으로 만든다.

**구조**(DOM 변경 → SPEC §9 에 올린다)
- 지금 `.tt__grid` 는 2열 그리드(왼쪽 124px 멤버 칸 `.tt__lane` + 오른쪽 `.tt__axis` · `.tt__track` 이 행마다 번갈아 있음)라, 오른쪽만 밀 수 없다.
- 오른쪽 열을 `.tt__rail`(grid-column 2, 모든 행에 걸침, `overflow: hidden`) 하나로 묶고, 그 안에 `.tt__strip`(폭 200%, `display: flex`) → `.tt__pane` 두 개(오늘 예고 · 내일 예고, 각 폭 50%, 각자 시간축 · 칸 5줄 · 겹침 층)를 둔다. 행 높이는 지금도 고정값(시간축 36px · 칸 78px)이라 왼쪽 멤버 칸과 줄이 맞는다.
- **왼쪽 멤버 칸(아바타 · 이름 · 트윗 뱃지)은 움직이지 않는다** — `tweets.js` 가 붙이는 뱃지(`.tt__who .lane__tw`)와 B2 라이브 아바타 효과가 넘기는 동안에도 그대로 있다. 멤버 칸의 `N건` 은 보고 있는 화면의 건수로 바꾼다.
- 두 화면을 미리 다 그려 두므로 넘길 때 다시 그리지 않는다. `.tt__strip` 의 `transform: translateX(0 | -50%)` 만 바뀐다.
- 가로 넘침(`.tt__scroll`, 1000px 미만 폭)은 지금처럼 바깥에서 스크롤한다.

**일 이동 버튼**
- 자리 = `.tt__sw` 바깥 오른쪽 세로 띠(가로 넘침 화살표 `.tt__arr` 와 겹치지 않게). 버튼 하나로, 오늘 예고에서 `>` · 내일 예고에서 `<`. 바뀔 때 화살표가 **180° 돌아간다**(280ms).
- 오늘 예고에서는 버튼에 **내일 예정 건수**를 작은 알약으로 붙인다(예: `> 2`, 0건이면 숫자 없음) — 자정 전에 「내일 아침 방송이 있다」를 누르기 전에 알 수 있게(이번 패치의 직접 해법). 75초 폴링으로 건수가 바뀌면 알약이 한 번 튄다(`dot--pop` 과 같은 곡선 · 0.38s).
- 마우스 올림 = 바탕 한 단계 밝게 + 화살표가 가리키는 쪽으로 2px. 누름 = `scale(0.94)` 80ms. 포커스 = 사이트 공통 윤곽. `aria-label` = 「내일 예고 보기」 / 「오늘 예고 보기」. `button` 요소라 Enter · Space 는 기본 동작.
- **처음 한 번 알려 주기**: 페이지를 연 동안 1회, **오늘 예고에 남은 예정이 0건이고 내일 예고에 1건 이상**일 때만 버튼이 오른쪽으로 세 번 까딱인다(기존 `.tt__arr.is-nudge` 와 같은 움직임 · 같은 1회 규칙). 이번 문제가 생기는 상황(밤에 오늘 방송이 다 끝났을 때)에서만 눈길을 끈다. 가로 넘침 화살표 까딱임과 겹치면 이 쪽을 먼저, 넘침 화살표는 그다음 렌더로 미룬다.

**넘기는 움직임**
- 버튼으로 넘기기 = `.tt__strip` 이 280ms(`render.js:501 FOLD_MS` 와 같은 길이) 동안 `cubic-bezier(0.2, 0.8, 0.2, 1)`(`tweets.css --ease` 와 같은 곡선)로 미끄러진다.
- 머리줄 제목 · 메타 = 넘기는 방향으로 6px 밀려 나가며 흐려지고 새 글자가 반대쪽에서 들어온다(160ms). 멤버 칸 `N건` 은 숫자만 흐렸다 바뀐다.
- 제목 옆에 **두 점 표시**(오늘 · 내일 중 어디인지). 끄는 동안에는 끈 거리에 맞춰 강조가 옮겨 간다.
- 넘기기 시작할 때 열려 있는 블록 카드 팝업은 닫는다(`closeCardPop`), 넘기는 동안 블록 마우스 올림 팝업은 띄우지 않는다.

**마우스 끌기 (PC 마우스 전용)**
- 표의 **빈 자리**(블록 `.tt-blk` · 팝업 · 버튼 위가 아닌 곳)에서 누르면 시작. 빈 자리 위에서는 커서 `grab`, 끄는 동안 `grabbing`.
- `.tt__strip` 이 마우스를 1:1 로 따라온다. **더 갈 화면이 없는 쪽**(오늘 예고에서 오른쪽으로, 내일 예고에서 왼쪽으로)으로 끌면 고무줄처럼 끈 거리의 30%만, 최대 48px 까지 따라오고 놓으면 되돌아온다(200ms).
- 놓았을 때 레일 폭의 25% 이상 끌었거나 빠르게 튕겼으면(0.5px/ms 이상) 넘기기 확정 → 남은 거리를 위 곡선으로 마저 간다. 아니면 제자리로 200ms.
- 오른쪽 → 왼쪽 = 내일 예고, 반대 = 오늘 예고. 이동 거리 > 5px 이면 끝난 뒤의 click 을 막아 블록 팝업이 잘못 열리지 않게 한다.
- 끄지 않는 경우: 터치(`pointerType !== "mouse"`) — 태블릿 폭 PC 구성에서 가로 스크롤과 부딪히므로 버튼만. 표가 가로로 넘치는 폭(`.tt__sw.is-over`) — 넘침 스크롤과 같은 몸짓이라 버튼만.

**움직임 줄이기**(`prefers-reduced-motion: reduce`)
- 미끄러짐 · 제목 밀림 · 화살표 회전 · 까딱임 · 고무줄 · 알약 튐 모두 없이 즉시 바꾼다. 끌기는 놓을 때만 판정해 즉시 바꾼다.

**키보드**
- 일 이동 버튼만 키보드로 쓴다(표 안 방향키 이동은 만들지 않음 — 키보드 최적화는 보류된 범위, 2026-10-27).

### A4. 카드 보기(모바일 카드 · PC 카드 보기 공용 — `buildTodayCards`)
- 화면 넘기기 · 일 이동 버튼 없음 — 카드는 오늘 · 내일을 한 줄로 다 보여 준다.
- 한 멤버 카드 묶음 = **종료 → 방송 중 → 오늘 예고의 예정 → 내일 구분선 → 내일 예고의 예정**.
- **내일 구분선** = 작은 한 줄 `내일 예고 · 10/31(토) 04:00 ~`(내일 예정이 1건 이상일 때만). 오늘 남은 카드가 0건이고 내일이 있으면 「오늘 남은 예고가 없습니다.」 한 줄 + 구분선 + 내일 카드.
- **종료 카드는 04:00 에 없어진다**(2026-10-29 운영자 코멘트). 카드도 표와 같은 `ctx.ended` 를 쓰므로 따로 거르는 규칙이 없다.
  04:00 에 보드를 다시 그리는 장치는 이미 있다 — `main.js:359` 1분 틱 → `updateCountdowns` → `tickTimetable` 이 `nowMs >= __ttDe` 면 true → `paintBoard`.
  결과: 23시에 시작해 01시에 끝난 방송은 04:00 까지 남는다. 표 · 카드가 같은 시각에 바뀐다.
- `bigIdx`(크게 보이는 첫 카드) = 종료가 아닌 첫 카드(오늘 예정이 없으면 내일 첫 카드).
- 머리줄: 제목 「오늘 예고」 그대로, 메타 `timetable.js:651` 의 `06:00 ~ 익일 06:00` → `04:00 ~ 익일 04:00`, 끝에 `· 내일 M`(0건이면 생략).
- `todayCard` 의 카운트다운 링(`ringPct` 24시간 기준)은 24시간 넘게 남은 내일 카드에서 빈 링이 된다 — 구현 후 화면 보고 필요하면 보완.

### A5. 「이후 예고」 접힘 버튼
- 대상 = 새 `later`(내일 예고 다음 04:00 이후 · 시각 미정). 건수 0 이면 버튼 · 목록 없음(현행 규칙).
- 문구 「오늘 이후 예고 N건 펼치기/접기」 → **「이후 예고 N건 펼치기/접기」** (`buildFoldButton`, `timetable.js:672-673`).
- 접힘 상태 관리(`board--later-open` 클래스, `toggleLater`)는 그대로. 화면 넘기기와 무관(어느 화면에서든 같은 목록).

### A6. 06:00 이 적힌 곳 (전부 고친다)
`timetable.js` 3행(머리 주석) · 21행(`DAY_START_HOUR`) · 76행(`classify` 주석) · 377행(`buildBoardHead` 메타) · 435행(시간축 주석) · 651행(`buildTodayCards` 메타),
`main.js:358` · `render.js:972` 주석, `css/timetable.css:241`(`.tt__mid`, 삭제). `monitor.html:90` 의 06:00 은 모니터링 하루 경계라 **그대로**.
