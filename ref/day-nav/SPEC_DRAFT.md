## A. 하루 구간 04:00 + 내일 구간 (`timetable.js` · `render.js` · `main.js` · `css/timetable.css`)

### A1. 순수 함수 (DOM 없음 — selfcheck 대상)
| 함수 | 변경 |
|---|---|
| `DAY_START_HOUR` | 6 → **4**, `export` 한다(A2 의 자정 위치 계산에 쓴다). 주석 「monitor_log.DAY_START_HOUR 와 같은 하루 경계」 삭제(프론트 전용 값이 됨). |
| `dayWindow(nowMs, offset = 0)` | 반환 `{ ds, de }` 를 `offset * DAY_MS` 만큼 민다. `offset` 0 = 오늘, 1 = 내일. |
| `classify(items, archive, nowMs, order)` | 반환에 `tomorrow` 추가. `live` · `ended` · `upcoming` 은 **오늘 구간** 기준 그대로. `tomorrow` = announced/upcoming/watching 이고 시각이 `[de, de+DAY)` 인 것(`{item,start,end:null}`, 시작순). `later` = `s >= de+DAY` 이거나 `time_tbd` · 시각 없음. |

- 합동 팬아웃(`itemKeys`)은 그대로 — `tomorrow` 도 멤버별로 거른다.
- `ended` 규칙은 현행 그대로(경계만 04:00): `state==="end"` 이고 끝(`state_since`) > `ds`, 또는 보관함에서 시작(`actual_start`) ≥ `ds` · 길이 10분~12시간. → 04:00~06:00 에 시작한 방송이 새로 포함된다.
  보관함은 C 이후에도 프론트가 읽는 캐시 보관함에 최근 7일이 남으므로 오늘 구간 분량은 항상 있다.
- `live` 는 날짜 구간과 무관하게 지금 라이브인 것 전부(현행 유지).

### A2. 타임테이블(PC 테이블 보기)
- 상태: `render.js` 모듈 변수 `dayOffset`(0|1). 75초 폴링 재렌더 · 보기 방식 전환 · 창 크기 변화에도 **유지**, **새로고침하면 0(오늘)** — 모듈 변수라서. 다음 방문에 내일 화면이 먼저 뜨면 헷갈리므로 저장하지 않는다(결정 3).
- `renderBoard`: `dayOffset===1` 이면 `buildTimetable(ctx1)` 에 `ctx1 = { ...ctx, ds: 내일.ds, de: 내일.de, live: [], ended: [], upcoming: ctx.tomorrow, offset: 1 }` 를 넘긴다(블록 배치 `layoutRow` 가 `ctx.ds` 만 쓰므로 그대로 동작).
  `boardEl.__ttDe` 는 언제나 **오늘의 `de`**(재렌더 판정 기준).
- **오늘 구간이 끝나는 순간**(`tickTimetable` 이 true → `main.js` 가 `paintBoard`): `dayOffset` 이 1 이었다면 **0 으로 되돌린다**(보던 날짜가 그대로 「오늘」이 되므로 화면이 안 바뀐 것처럼 이어진다).
- 머리줄(`buildBoardHead`): 제목 「오늘 예고」 / 내일이면 「내일 예고」(00~04시 표기는 결정 2). 메타 문구 `mdw(ds) 04:00 ~ 익일 04:00 · 예정 N건 …`. 내일 구간에서는 방송 중 · 종료 건수 문구 없음.
- 내일 구간 화면: **지금 선 · 지난 구간 음영 숨김**, 빈 행 문구 「내일 예정 없음」. 범례는 그대로. 자정 점선은 내일 구간에서도 보인다(그 날의 자정 위치는 같다).
- **시간축**: 04:00 시작 + **4시간 간격**(04·08·12·16·20·00·04). 3시간 간격이면 04·07·10… 처럼 어색해서 바꾼다. `buildTimetable` 의 눈금 반복(현 `h += 3`, 자정 `h === 18`)을 `h += 4`, 자정 = **`h === 24 - DAY_START_HOUR`(=20)** 으로. 마지막 눈금 = 익일 04:00.
- **자정 점선 `.tt__mid`**: 지금 `timetable.css:241` 이 `left: 75%`(06:00 + 18h) 고정 → CSS 의 `left` 를 지우고 `buildTimetable` 이 `style.left = ((24 - DAY_START_HOUR) / 24 * 100)%`(=83.33%) 를 넣는다(경계를 또 바꿔도 어긋나지 않게).
- **일 이동 버튼**: 표 오른쪽 끝에 세로로 긴 `>`(오늘 구간에서) / `<`(내일 구간에서). 기존 가로 넘침 화살표(`.tt__arr`, `wireOverflow`)와 겹치지 않게 **`.tt__sw` 바깥 오른쪽 띠**에 둔다. `aria-label` = 「내일 예고 보기」 / 「오늘 예고 보기」. `button` 요소라 Enter · Space 는 기본 동작.
  - `>` 버튼에 **내일 예정 건수**를 작게 표시(예: `> 2`, 0건이면 숫자 없음) — 자정 전 「내일 아침 방송이 있다」는 사실을 누르기 전에 알 수 있어 이번 문제의 직접 해법이다(결정 1).
- **끌어서 넘기기(PC 마우스 전용)**: 표의 **빈 영역**(블록 `.tt-blk` · 팝업 · 버튼 위가 아닌 곳)에서 `pointerdown` → 가로로 이동한 만큼 `grid` 전체(5행 + 시간축)를 `translateX` 로 같이 움직인다. 폭의 25% 이상 끌었거나 빠른 플릭이면 이동 확정, 아니면 제자리로 복귀. 오른쪽→왼쪽 = 내일, 반대 = 오늘. 전환 애니메이션 280ms(`render.js:501 FOLD_MS` 와 같은 값), `prefers-reduced-motion` 이면 애니메이션 없이 바로.
  - 터치(`pointerType !== "mouse"`)는 끌기를 달지 않는다 — 태블릿 폭의 PC 구성에서 가로 넘침의 기본 스크롤과 충돌하므로 버튼으로만.
  - 끌기 중 블록 클릭(카드 팝업)이 오발되지 않게 이동 거리 > 5px 이면 click 을 막는다. 열려 있는 카드 팝업은 이동 시작 시 닫는다(`closeCardPop`).
  - 표가 가로로 넘치는 폭(`.tt__sw.is-over`)에서는 마우스 끌기를 끄고 버튼만 쓴다 — 가로 넘침 화살표 · 스크롤과 같은 몸짓이 겹치므로.

### A3. 카드 보기(모바일 카드 · PC 카드 보기 공용 — `buildTodayCards`)
- 한 멤버 카드 묶음 = **종료 → 방송 중 → 오늘 예정 → 내일 구분선 → 내일 예정**. 일 이동 버튼 · 끌기 없음(카드는 다 보여 준다).
- **내일 구분선** = 작은 한 줄 `내일 10/30(금)`(내일 예정이 1건 이상일 때만). 오늘 남은 카드가 0건이고 내일이 있으면 「오늘 남은 예고가 없습니다.」 한 줄 + 구분선 + 내일 카드.
- **종료 카드는 오늘 구간 경계(04:00)에 없어진다**(2026-10-29 운영자 코멘트 — 1판의 「자정에 제거」를 바꿈). 카드도 표와 같은 `ctx.ended` 를 쓰므로 따로 거르는 규칙이 없다.
  - 04:00 에 보드를 다시 그리는 장치는 이미 있다 — `main.js:359` 1분 틱 → `updateCountdowns` → `tickTimetable` 이 `nowMs >= __ttDe` 면 true → `paintBoard`.
    (1판의 자정 규칙은 이 장치가 자정엔 돌지 않아, 데이터가 바뀌기 전까지 카드가 남는 빈틈이 있었다 — `preview.json` 은 실제 변화가 있을 때만 커밋되며 10-28 밤 KST 00:40~06:31 커밋 없음.)
  - 결과: 23시에 시작해 01시에 끝난 방송은 04:00 까지 남는다. 표 · 카드가 같은 시각에 바뀐다.
- `bigIdx`(크게 보이는 첫 카드) = 종료가 아닌 첫 카드(오늘 예정이 없으면 내일 첫 카드).
- 머리줄 메타: `timetable.js:651` 의 `06:00 ~ 익일 06:00` → `04:00 ~ 익일 04:00`, 끝에 `· 내일 M`(0건이면 생략).
- `todayCard` 의 카운트다운 링(`ringPct` 24시간 기준)은 24시간 넘게 남은 내일 카드에서 빈 링이 된다 — 구현 후 화면 보고 필요하면 보완.

### A4. 「이후 예고」 접힘 버튼
- 대상 = 새 `later`(모레 04:00 이후 · 시각 미정). 건수 0 이면 버튼 · 목록 없음(현행 규칙).
- 문구 「오늘 이후 예고 N건 펼치기/접기」 → **「이후 예고 N건 펼치기/접기」** (`buildFoldButton`, `timetable.js:672-673`).
- 접힘 상태 관리(`board--later-open` 클래스, `toggleLater`)는 그대로.

### B2. 라이브 아바타 효과
- `renderBoard` 가 레인을 다 만든 뒤(**`initMobileCarousel` 이전** — 클론이 클래스를 같이 복제하도록) `ctx.live` 의 각 항목에 대해 `itemKeys(item, order)` 의 멤버(합동 참여자 포함) 레인(`.lane[data-channel]`)에 `lane--live` 클래스를 단다. 라이브가 아닌 레인은 클래스 없음(매번 다시 그리므로 따로 제거 불필요).
  - PC 테이블 보기의 `.tt-later` 안 레인(`lane lane--later`)에도 같은 `data-channel` 이 있어 같이 붙는다 — 이후 예고 목록 머리 아바타도 빛나는 게 맞는지 화면에서 확인(아니면 `.tt__lane` · 카드 보기 · 모바일 레인으로 한정, 결정 6).
- CSS: `.lane--live .lane__avatar` → 빨간 테두리 + 은은한 글로우(`box-shadow: 0 0 0 2px var(--color-live), 0 0 10px 2px color-mix(in srgb, var(--color-live) 55%, transparent)`) + 느린 호흡 애니메이션. `prefers-reduced-motion` 이면 애니메이션 없이 정적 테두리.
- 적용 위치(= `.lane__avatar` 하나로 모두 해당): PC 표 왼쪽 칸 · 모바일 레인 머리 · PC 카드 보기 5열 머리.
- **모바일 하단 멤버 전환 점(`.dot`)**: 점은 `initMobileCarousel` 안(`render.js:787` 반복문)에서 진짜 레인을 보고 새로 만든다 → 그 반복문에서 `lane.classList.contains("lane--live")` 이면 `btn.classList.add("dot--live")`. 점 스타일은 `layout.css:428` · `timetable.css:621` 두 곳에 있으니 `dot--live` 는 뒤쪽(`timetable.css`)에 둔다. 켜진 점(`dot--on`) · 튀는 효과(`dot--pop`)와 겹쳐도 보이는지 확인.

### C1. 정리 대상 추가 (`archive_rotate.py`)

## 미결정 / 확인 필요
1. `>` 버튼 내일 건수 — 기본안 **표시**(0건이면 숫자 없음).
2. **00~04시의 「오늘 · 내일」 이름** — 하루를 04:00 ~ 다음 날 04:00 으로 잡으므로, 자정을 넘겨도 04:00 전까지는 화면의 「오늘」이 전날이다.
   - 예: 지금 10월 30일(금) 01:00 → 「오늘 예고」 = 10월 29일 04:00 ~ 10월 30일 04:00(전날 밤 방송), 「내일 예고」 = 10월 30일 04:00 ~ 10월 31일 04:00(10월 30일 방송).
     보는 사람은 달력상 이미 10월 30일이라 「내일」 = 10월 31일을 기대하지만, 누르면 10월 30일 방송이 나온다.
   - 04:00 이후에는 어긋나지 않는다(10월 30일 10:00 → 오늘 = 10월 30일, 내일 = 10월 31일). 월말도 같다(10월 31일 10:00 → 내일 = 11월 1일). 어긋나는 건 매일 00:00~04:00 의 4시간뿐.
   - 기본안 = 이름은 그대로 두고 제목에 날짜를 붙인다(10월 30일 01:00 → 「오늘 예고 10/29(목)」 · 「내일 예고 10/30(금)」). 다른 안 = 00:00~04:00 에만 이름을 「지난 밤 예고」 · 「오늘 예고」로 바꾼다. 운영자 결정.
3. `dayOffset` — 기본안 **재렌더엔 유지 · 새로고침 땐 오늘**(1판 D 항의 「새로고침 후 유지」와 A2 「모듈 변수」가 어긋나던 것을 정리).
4. 버전 묶음 — 이 문서의 세 절(A = 하루 경계 04:00 · 내일 보기, B = 뱃지 · 라이브 아바타 · 탭 제목, C = 예고 보관함 일자 분리)을 한 번호로 낼지.
   - A · B 는 프론트라 `main` 병합 = Vercel 자동 배포. C 는 백엔드라 Cloud Run 두 서비스 재배포 + 데이터 이전 스크립트가 따로 필요하고, 화면에는 변화가 없다.
   - 제안 = **A · B 를 v4.10.0(마이너), C 를 그 뒤 v4.10.1(일반 패치)로 나눈다**(2판 첫 기본안 「한 번호로 묶음」을 바꿈 — 배포 방식 · 성격이 달라서). 운영자 결정.
5. 뱃지 · 라이브 글로우 색 — **구현 후 화면 보고 결정**(운영자 확정, B1 후보 ①~③).
6. 확인 필요: 보관된 예고가 preview 로 돌아오는 경로가 있는지(C1), 라이브 아바타를 `.tt-later` 머리에도 둘지(B2).
