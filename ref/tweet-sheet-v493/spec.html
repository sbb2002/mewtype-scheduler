확정 결정 (운영자, 10-28)

#내용
버전v4.9.3 일반 패치. 10-27 트윗 시트 수정(v4.9.0~v4.9.1)의 연장선으로 본다. 새 요소가 들어가도 이번엔 일반 패치(운영자 판정).
1시트를 처음 열 때, 그리고 연 뒤 각 멤버 탭에 처음 들어갈 때는 항상 피드 맨 아래. 같은 멤버로 다시 돌아오면 보던 자리.
2번역 · 원문 두 면을 겹쳐 밀기로 바꾼다. 두 면을 같은 자리에 겹쳐 두고, 앞 면이 밀려 나가며 흐려지면 뒤 면이 드러나는 방식이다. 시안 그대로 간다.
3번역 면에 사진 · 영상 · 인용 글을 카드와 비슷한 모양으로 그린다. 색 · 톤은 지금 시트(멤버 색)를 그대로 쓰고, 인용 글 번역도 유지한다. 영상만 누르면 그 글이 원문 카드로 넘어가고 같은 영상 칸에 글로우가 1번 깜박인다. 사진은 누르지 않는다(10-28).
영상번역 면에는 썸네일과 ▶만 그린다. 누르면 원문 카드로 넘어간다(아래 「재생」 한계 참고).
법률재검토 결과(10-28) — 직접 그려도 되는 조건: ① X 원문 카드가 함께 있을 것, ② 작성자 이름 · 핸들 · 작성 시각 · 원본 링크가 보일 것(지금 머리 줄 · 시각 줄로 채움), ③ 이미지 · 영상을 우클릭 등으로 내려받지 못하게 할 것. 원문 텍스트는 지금처럼 번역 면에 그리지 않는다(카드에만 있다).
5피드를 위로 올리면 기존 ↓ 동그라미(.tws__fab, 맨 아래로 버튼)를 새 글이 없어도 띄운다.

정해진 것 · 한계

법률 조건 ②는 지금 화면으로 채운다 — 작성자 줄 · 백엔드 변경 없음 (운영자, 10-28)

이름 · 핸들은 시트 머리 줄(#tws-nm 이름 · .tws__hd 「@핸들 · 최근 48시간」)에, 작성 시각 · 원본 링크는 글마다 위 시각 줄(.tws-tw__time · a.tws-tw__open)에 이미 있다. 번역 면에 작성자 줄을 따로 넣지 않는다.

인용 글: 데이터 quote 에는 작성자 정보가 없다(text · media · text_ko 만). 그래도 따로 구현하지 않고 인용 사진 · 영상도 그린다. 백엔드 · 계약 I 는 그대로 둔다.

알림 — 영상 재생은 한 번 더 눌러야 한다

X 카드는 X 사이트의 iframe 이라 우리가 안에서 재생을 시킬 수 없다(확인한 범위에서는 재생 명령을 보낼 길이 없다. 구현 때 X 임베드 메시지를 한 번 더 살펴보고, 길이 있으면 쓴다). 그래서 영상을 누르면 원문 카드로 넘어가면서 「▶ 카드에서 재생」 반짝 표시가 나온다. 재생은 카드 안 ▶를 한 번 누른다. PC 에서는 카드 덮개를 미리 비켜 두어 그 한 번이 바로 카드에 닿게 한다.

1 · 열 때 맨 아래 · 멤버별 위치 기억

지금: _renderFeed(fresh=true) 가 「여기부터 새 글」 선(.tws__new)이 있으면 그 선의 10px 위로, 없으면 맨 아래로 스크롤한다(tweets.js 884행). 운영 사이트에서 아라레 시트를 열어 보면 맨 아래가 아니라 중간(scrollTop 1781 / 높이 4976)에서 시작한다.

바꿈

  • 시트를 열 때(_open) 멤버별 위치 기록 S.pos = {} 를 비운다. 위치는 시트를 닫으면 잊고, 저장하지 않는다.
  • 멤버를 바꿀 때(_switchTo) 떠나는 멤버의 위치를 적는다. 맨 아래(24px 안)였으면 { bottom: true }, 아니면 { id, off } 를 적는다. id = 피드 위 가장자리에 걸친 글의 id, off = 그 글 윗변 − 피드 윗변.
  • _renderFeed(fresh) 의 스크롤 목표: 이 멤버의 S.pos 가 있고 그 글이 아직 목록에 있으면 그 자리로, 아니면 맨 아래. 「여기부터 새 글」 선은 그대로 그리지만 스크롤 목표로는 쓰지 않는다.
  • 「새 글 N개 ↓」 칩(.tws__newchip)의 조건(선이 화면 아래에 있을 때)은 그대로 둔다. 처음 열면 맨 아래라 사실상 뜨지 않는다.
  • 맨 아래 유지: X 카드의 실제 높이가 늦게 와도 기존 _wireEmbedResize 가 처리한다(카드가 커지기 직전에 맨 아래 8px 안이었으면 다시 맨 아래로). 번역 면의 2~4칸 묶음은 16:9 상자라 높이가 폭으로 정해져 그림이 늦게 와도 바뀌지 않는다. 1칸은 원래 비율을 알아야 해서 그림 크기를 받을 때 한 번 바뀔 수 있다(X 카드도 같다). 이때도 맨 아래였으면 맨 아래를 지킨다.
  • 75초 폴링 때 다시 그리는 경우(_renderFeed(false))와 새 글만 끼우는 경우(_patchFeed)는 지금 그대로 둔다(면 · 스크롤 위치 유지).

2 · 두 면 겹쳐 밀기

원인 (운영 사이트 실측, 10-28): 두 면이 가로 스크롤 줄(.tws-tw__track, scroll-snap)에 나란히 있다. 번역 면을 보는 동안 원문 면은 화면 밖이라 브라우저가 X 카드 iframe 을 그리지 않고, 높이 신호(twttr.private.resize)도 오지 않는다. 그래서 두 면 높이가 어림값(estimateCardH)에 머문다. 원문으로 넘기면 그제서야 실제 높이가 와서 글이 커지고 아래 글이 밀려난다. 실측 예: 410 → 647px, 230 → 275px, 반대로 470 → 76px(카드가 거의 빈 경우).

확인한 해법: 두 면을 같은 자리에 겹치고 뒤 면을 투명하게 제자리에 두면, 번역 면을 보는 동안에도 높이 신호가 온다. 노노카 3장 중 2장은 8초 안에 왔다. 대조로 그대로 둔 리츠는 6장 중 0장이었다.

구조

  • .tws-tw__track = display: grid. 두 .tws-tw__face 를 같은 칸(grid-area: 1 / 1)에 둔다. 칸 높이는 두 면 중 큰 쪽이라 두 면 높이가 늘 같다(U3 유지). 이제 실제 카드 높이 기준이다.
  • 앞 면 .is-front, 뒤 면 .is-back = opacity: 0 · pointer-events: none · aria-hidden="true" · inert(키보드가 안 보이는 면으로 들어가지 않게). 확인 필요: inert 를 달아도 X 카드 높이 신호가 오는지. 안 오면 inert 를 빼고 앞 · 뒤 면의 tabindex 만 관리한다.
  • 뒤 면은 옮기지 않는다(옆으로 밀어 내면 다시 화면 밖이 되어 그려지지 않는다). 움직이는 건 앞 면뿐이다.

움직임 (시안과 같게)

  • 전환: 앞 면이 translateX(±40%) 와 투명도 0 으로 300ms 동안 밀려 나간다(곡선 EASE). 뒤 면은 투명도 0 → 1, 크기 0.985 → 1. 끝나면 앞 · 뒤를 바꾼다.
  • 끄는 중: 앞 면이 손을 따라 움직이고 흐려지며, 뒤 면이 드러난다. 문턱(25%)과 끄는 중 점 폭 변화(A2 · 진동)는 지금과 같다. 문턱을 못 넘고 놓으면 앞 면이 제자리로 튕겨 돌아온다(SPRING). 더 갈 면이 없는 쪽으로 끌면 고무줄(A3, 최대 24px)이다.
  • 엿보기(A1): 앞 면을 -24px 밀었다 돌아온다. 지금은 트랙 전체를 민다.
  • 움직임 줄이기: 이동 · 크기 없이 투명도만 바뀐다.

인용한 글
오늘의 방송 스케줄입니다

시안(정적 그림). 번역 본문 → 미디어 격자*(사진 1장 + 영상 1개) → 인용 상자(인용 번역 + 인용 사진) 순으로, X 카드와 같은 순서다. 이름 · 핸들은 시트 머리 줄, 시각 · X 링크는 글 위 시각 줄에 있다.

* 미디어 격자 = 번역 면에 그리는 사진 · 영상 썸네일 칸 묶음(1~4칸).

번역 면 구성 (위 → 아래)

  1. 번역 본문 .tws-ko__txt(그대로).
  2. 미디어 격자 .tws-md(본문 사진 · 영상, media):
    • X 카드 실측 규칙을 그대로 따른다(10-28 측정, 폭 362 · 512 · 548px 에서 같은 규칙). 측정한 운영 예시 글은 사진 1 · 2 · 3 · 4장, 영상 1개, 영상 3 + 사진 1, 인용 사진 2 · 3 · 4장이다.
      • 2 · 3 · 4칸: 묶음 전체가 16:9 상자다(폭으로 높이가 정해짐). 2칸 = 좌우 반반, 3칸 = 왼쪽 큰 칸 + 오른쪽 위아래, 4칸 = 2×2. 사진 · 영상이 섞여도 같은 배치다.
      • 1칸: 원래 비율이다(16:9 영상이면 16:9). 세로로 길면 정사각형으로 가운데를 잘라 보여 준다(실측: 526×900 사진 → 514×514). 데이터에는 크기가 없으므로 new Image() 로 크기만 읽어 비율을 정한다(<img> 를 화면에 두지는 않는다). 읽기 전에는 16:9 자리다. 확인 필요: 아주 가로로 긴 그림(파노라마)의 아래 한계.
      • 칸 사이 2px, 묶음 테두리 1px, 모서리 12px. 영상이 섞인 묶음 하나는 16px 이었다. 확인 필요: 어떤 조건에서 16px 인지.
      • X 는 글 하나에 최대 4개라서 5개 이상은 나오지 않는다(「+N」은 만일을 위한 처리).
      • ▶: X 카드는 파란 원이다. 번역 면은 시트 톤(멤버 색을 어둡게 한 원 + 흰 테두리)을 쓴다(운영자 — 색 · 톤은 시트 유지).
    • 영상 = L._kinds 기준(video_thumb · amplify 포함 URL). 썸네일 위 가운데에 ▶ 원(.tws-md__play)을 둔다.
  3. 인용 상자 .tws-ko__q: 「인용한 글」 라벨 + 인용 번역(그대로). 인용 사진 · 영상은 X 처럼 인용 상자 아래쪽에 가장자리까지 붙여(안쪽 여백 없음, 상자 모서리로 잘림) 같은 규칙의 격자로 그린다. 이름 줄 · 본문만 안쪽 여백(9 · 11px)을 둔다.
  • 본문 사진 · 영상을 그리므로 번역 면 맨 아래의 첨부 줄(본문 몫)은 없앤다. 내용은 위에서부터 채우고 빈자리는 아래로 둔다(margin-top: auto 제거).
  • 그림 크기: URL 에 name=small 을 붙여 요청한다(이미 name= 이 있으면 바꾼다). 확인 필요: pbs.twimg.com 응답 크기 · 화질.
  • 불러오는 시점: X 카드와 같은 관찰(cardIO, 글이 화면 위아래 한 화면 안에 들어올 때)에서 background-image 를 넣는다. 그 전에는 옅은 바탕색 칸이다.

두 면 안 요소 위치 맞추기 (운영자, 10-28 세 번째 답)

  • 번역 면을 X 카드와 같은 뼈대로 그린다. 순서는 머리 줄(아바타 36px · 이름 / @핸들 · 오른쪽 「번역」 표, X 로고 자리) → 본문 → 미디어 격자 → 인용 상자(첫 줄 「인용한 글」 = 카드의 인용 작성자 줄 자리) → 바닥 줄(작성 시각 · X 원문 링크, 카드 바닥 줄 자리)이다. 머리 줄은 법률 조건이 아니라 위치를 맞추려고 둔다.
  • 안쪽 여백 · 간격 · 글자 크기 · 줄 높이 · 미디어 칸 높이 · 모서리는 X 카드 실측 치수를 따른다. 확인 필요: 구현 때 운영 X 카드를 다시 재서 넣는다. 지금 아는 것은 작성자 줄 약 55px, 본문 73px부터(SPEC v4.9.1 덮개 실측)뿐이다. 줄 높이는 정수 px 로 둔다(소수면 반올림으로 0.5px 어긋남, 시제품에서 확인).
  • 본문 · 인용 본문 높이: 번역이 원문보다 짧으면 원문 높이만큼 자리를 잡는다(min-height). 원문 높이는 iframe 안을 잴 수 없으므로, 데이터의 원문(text · quote.text)을 카드와 같은 폭 · 글자 치수의 안 보이는 칸(visibility: hidden · aria-hidden)에 넣어 잰다. 화면에는 그리지 않는다. 번역이 더 길면 그만큼 아래 칸이 내려간다(카드는 줄일 수 없음). X 카드 글꼴(Chirp)이 우리 쪽에 없어 몇 px 차이가 날 수 있다 — 확인 항목.
  • 창 폭이 바뀌면(시트 폭 · PC 팝업 크기) 다시 잰다. 시제품에서 35글 104쌍을 재 보니 차이는 0px이었다(카드를 우리가 그린 흉내라서 얻은 값이고, 실제 X 카드와의 차이는 구현 때 잰다).

메신저처럼 — 시각 한 번만 (운영자, 10-28 네 번째 답 · 제안)

  • 글 위 시각 줄(.tws-tw__meta: 시각 · 사진 수 버튼 · X 링크)을 없앤다. 시각은 말풍선 바닥 줄(카드 바닥 줄 자리)에 한 번만 둔다. 표기는 HH:MM(KST), 올리면 M/D HH:MM · N분 전(title)이다. 게시 시각을 모르면 HH:MM 등록.
  • 날짜가 바뀌는 곳에 날짜 구분선 .tws__day(「10월 28일 (화)」, 가운데 작은 알약)을 둔다. 새 글만 끼울 때(_patchFeed) 날짜가 바뀌면 구분선도 끼운다.
  • 시각 줄에 있던 것의 행방: 사진 수 버튼 → 사진을 그리므로 없앤다. X 링크 → 바닥 줄 「𝕏에서 원문」. 「새 글」 표 → 「여기부터 새 글」 선으로 대신한다. 답글 「이어서 · N분 뒤」 → 바닥 줄 시각 앞 ↩ 아이콘(글타래 세로줄은 그대로).
  • 말풍선: 두 면 모서리 16 · 16 · 16 · 왼쪽 아래 4px(꼬리 느낌, X 카드 감싼 자리도 같은 모양으로 자른다). 글 사이 간격은 16 → 10px.
  • 손가락 밀기 손잡이: 시각 줄이 없어져 원문 면에서 번역으로 돌아올 때는 점 줄만 남는다(X 카드 위는 iframe 이 가져감). 점 줄 높이를 18 → 20px 로 늘리고 원문 면 안내 문구를 「아래 점 줄을 밀면…」로 고친다. 머리 줄 「번역 · 원문」 탭도 그대로 있다.

내려받기 막기 (법률 조건 ③)

  • <img> 를 쓰지 않고 div 의 background-image 로 그린다. 우클릭 메뉴에 「이미지 저장」이 생기지 않는다.
  • 미디어 격자 · 인용 상자에서 contextmenu · dragstart 를 막는다(preventDefault). user-select: none, iOS 길게 누르기 메뉴 끄기(-webkit-touch-callout: none).
  • 한계: 개발자 도구 · 화면 캡처 · 네트워크 탭은 막을 수 없다. 일반 사용자가 쓰는 길만 막는다.

눌렀을 때

  • 사진 칸은 누르지 않는다(운영자, 10-28 — 번역 면에서 보는 것으로 충분, 원문 카드로 넘길 필요 없음). div(role="img", 이름 「사진」), 커서 기본. 우클릭 · 끌기 막기는 그대로다.
  • 영상 칸(▶)만 누를 수 있다(button, 이름 「영상, 원문 카드에서 재생」). 본문 · 인용 글의 영상 모두 해당한다. 누르면 그 글만 원문 면으로 넘어간다(기존 goX). 넘기기 직전에 누른 칸의 자리를 잰다(면 기준 offset, 번역이 원문보다 길어 밀린 만큼은 뺀다). 300ms 뒤 X 카드 위 같은 영상 칸 자리에 글로우를 겹쳐 그린다(누름은 통과, pointer-events: none). 말풍선 · 카드 전체 반짝임은 없다. 시제품에서 차이 0px.
  • X 는 글 하나에 사진 · 영상을 합쳐 최대 4개라 5개 이상은 나오지 않는다(「+N」 칸은 만일을 위한 처리).
  • PC · 마우스: 그 카드의 덮개를 미리 비켜 둔다(.is-live). 다음 누름이 바로 카드의 영상 재생에 닿는다. 마우스가 카드를 벗어나면 지금처럼 다시 덮는다. 카드 안 영상을 우리가 대신 재생시킬 수는 없다(위 「알림」).
  • 움직임 줄이기: 글로우가 천천히 나타났다 사라진다(투명도만).
  • 시각 줄의 사진 · 영상 수 버튼(옛 .tws-tw__media)은 시각 줄과 함께 없앤다(아래 「메신저처럼」).

5 · 위로 올리면 ↓ 동그라미 (맨 아래로 버튼)

지금: ↓ 동그라미(.tws__fab)는 새 글이 화면 아래쪽에 들어왔을 때만 뜬다(_arrive → _fab(n)).

  • 피드가 맨 아래에서 160px 넘게 위에 있으면 새 글이 없어도 뜬다. 숫자와 흔들기는 없고, 이름은 「맨 아래로」다.
  • 기다리는 새 글이 있으면 지금처럼 빨간 숫자 · 2.8초 흔들기 · 「새 글 N개, 맨 아래로」.
  • 누르면 부드럽게 맨 아래로 간다(움직임 줄이기면 바로). 맨 아래 160px 안으로 오면 사라진다(새 글이 있으면 지금처럼 맨 아래 24px 에서 새 글 테두리가 빛나고 사라진다).
  • 판단은 피드 scroll 리스너에서 한 프레임에 한 번(requestAnimationFrame). 「새 글 N개 ↓」 칩과는 지금처럼 동그라미가 먼저 뜬다.
  • 숨어 있을 때는 tabindex=-1, 떠 있을 때는 0(지금 규칙 그대로).

자동: node src/frontend/js/tweetlogic.selfcheck.mjs(기존 47건 + 새 C10~C15), 다른 프론트 selfcheck 5개 그대로 통과.

브라우저(로컬, v4.9.1 때와 같은 방식 — 운영 data 브랜치 tweets.json 을 내려받아 로컬 /data/ 에 두고, 시험 글을 덧붙여 다시 읽기). PC Chrome 과 390px 틀에서 본다.

  1. 열면 맨 아래 · 다른 멤버 처음 = 맨 아래 · 올려 둔 멤버로 돌아오면 같은 자리 · 닫았다 다시 열면 맨 아래.
  2. 번역 면에서 몇 초 뒤 각 글의 X 카드에 data-ready 가 붙는지(높이 신호), 원문으로 넘겨도 글 높이가 그대로인지(전환 전후 offsetHeight 비교).
  3. inert 를 단 뒤 면에서도 높이 신호가 오는지(확인 필요 항목).
  4. 마우스 끌기 · 키보드 ← → · 머리 줄 탭 · 엿보기 · 고무줄 · 트랙패드 가로(가능한 기기에서) · 390px 틀 터치 흉내.
  5. 사진 · 영상 칸: 우클릭 메뉴에 이미지 저장이 없는지, 끌어서 바탕화면으로 안 나가는지, 누르면 원문 + 반짝 1회 + PC 덮개가 비켜 있는지.
  6. ↓ 동그라미: 160px 위 = 숫자 없이 뜸 · 아래로 오면 사라짐 · 새 글 시험 = 숫자 · 흔들기.
  7. 폴링 갱신(_patchFeed) 때 기존 X 카드 iframe · 미디어 칸이 다시 불러와지지 않는지.
  8. 소식 팝업의 X 카드가 그대로 동작하는지.
