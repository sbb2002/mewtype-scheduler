# 자동제어 관리 페이지 (BUS_DASHBOARD) — v4.3-fullauto

> 러너 어드민 페이지(`/admin`)와 **별개의** 페이지. 수신기 프로세스 안에서 별도 포트로 동작하며 어드민 코드(`admin_*.py`, `admin.html`)를 건드리지 않는다.
> 규약·단계 설명은 `docs/BUS_PROTOCOL.md` · `docs/AUTOFIX.md`. 구현: `src/busrx/web.py` + `src/busrx/web_static/{index,login}.html`.

## 접속 · 로그인

- 수신기를 켜면 같이 뜬다: `http://127.0.0.1:8789/` 와 이 PC 의 Tailscale IP(`http://<tailscale-ip>:8789/`). 포트 `RX_WEB_PORT`(기본 8789), 끄기 `RX_WEB=0` 또는 `--no-web`.
- **`ADMIN_SECRET` 이 있어야 켜진다**(없으면 경고만 남기고 안 켬). 로그인 = `/login` 에서 버튼 → **텔레그램 일회용 링크**(5분 · 1회) → 링크를 열면 세션(12시간, HttpOnly + SameSite=Lax 쿠키).
  링크 요청은 20초에 1번. 서명 키는 어드민과 같은 `ADMIN_SECRET` 이지만 용도(`rxlogin`)가 달라 어드민 링크와 서로 통하지 않는다.
- 쓰기 요청은 CSRF 헤더 필수. 응답은 `Cache-Control: no-store` + CSP 헤더. 127.0.0.1 과 Tailscale IP 에만 바인딩(전체 인터페이스 아님).

## 1차 범위 밖 (2차 예정)

## 텔레그램 DM 명령 (수신기 전용 봇)

2026-10-12 운영자 결정(A안): **수신기 전용 봇**을 따로 둔다. 한 봇의 `getUpdates` 는 한 프로그램만 쓸 수 있어(둘이 쓰면 서로 끊고 명령이 유실됨) 러너 봇과 같은 봇으로 명령을 받을 수 없기 때문이다.
러너 봇은 러너 전용으로 그대로 두고, 수신기는 자기 봇으로 **알림 · 보고서 · DM 명령**을 모두 처리한다.

| 명령 | 동작 |
|---|---|
| `/ctl` | 관리 페이지 로그인 링크(5분 · 1회) 전송 |
| `/auto` | 현황 요약: 단계 · 분석 정지 여부 · 발신기/러너 상태 · 오늘 분석/수정 횟수 · 세션/주간 사용량 |
| `/usage` | 소형 호출로 구독 사용량을 새로 조회(사용량을 아주 조금 소모) |
| `/autopause` · `/autoresume` | 수신기 분석 정지 / 재개 (`rx/PAUSE`) |
| `/help` | 명령 목록 |

- 설정(`.env.local`): `RX_TELEGRAM_BOT_TOKEN`(수신기 전용 봇 토큰) · `RX_TELEGRAM_CHAT_ID`(허용 chat id). **둘 다 있어야** 켜지고, 없으면 기존 봇으로 알림만 보내며 명령은 꺼진다.
- 허용된 chat id 의 **개인 대화**에서 온 명령만 처리한다(다른 채팅 · 그룹은 무응답). `/ctl@봇이름` 형태도 인식.
- 안전장치: 시작 때 **webhook 이 걸린 봇이면 폴링을 거부**한다(운영 봇 토큰을 잘못 넣는 사고 방지). 이 봇은 `deleteWebhook` 을 호출하지 않는다. 오프셋은 `rx/tg_offset.txt` 에 저장.
- 구현 `src/busrx/bot.py`(명령 · 폴러), 현황 조립 `src/busrx/status.py`(관리 페이지와 공용). 점검 `python -m src.busrx.selftest_bot`.
- 이 봇으로 수신기 기동 후 알림이 모두 이쪽 대화방으로 온다(러너 알림은 기존 봇 대화방에 그대로).

## 에러 레벨별 자동 대응 정책 (제어 탭)

심각도(CRITICAL~TRACE)마다 **기록 · 동작 · 파이프라인 프리셋 · 쿨다운**을 정한다. 저장하면 `rx/policy.json` 에 쓰이고 **수신기가 다음 에러부터 바로 반영**한다(재시작 불필요). 변경 이력은 `rx/policy_history.jsonl`(누가 · 무엇을), 검증 규칙은 `src/busrx/policy.py`.

| 칸 | 값 |
|---|---|
| 기록 | 켬/끔 — 끄면 `rx/log.jsonl` 에도 남기지 않음 |
| 동작 | **끔**(기록만) · **분석만** · **수정까지** — WARN 이하는 "수정까지" 선택 불가(서버/UI 모두 거부) |
| 파이프라인 | **표준**(충분한 검증) · **긴급**(최소 검증) — "수정까지"일 때만 |
| 쿨다운(분) | 같은 시그니처를 다시 처리하기까지의 간격 |

기본값(운영자 정의): CRITICAL = 수정 · 긴급 · 5분 / ERROR = 수정 · 표준 · 60분 / WARN · INFO · DEBUG · TRACE = 끔(기록만). `RX_STAGE=1` 이면 "수정까지"도 분석만 한다. `기본값으로` 버튼으로 초기화.
CRITICAL 을 끄거나 WARN 이하를 분석으로 올리면 화면에 경고(사용량 증가 등)가 뜬다. 정책 파일이 손상되면 기본값으로 안전하게 복구한다.

### 파이프라인 프리셋

| 프리셋 | 구성 |
|---|---|
| **표준** | 분석 → 명세서 → 구현 → 가드 → 문법·self-test(변경 모듈 + 핵심 모듈) → **검증 → 독립 검토** → 커밋 → 보호 확인 → 적용 → 재시작 → 건강 확인 |
| **긴급** | 위에서 **검증 · 독립 검토를 건너뛰고**, self-test 는 변경 모듈만. **가드(금지 자원 확인)와 보호 대상 불변 확인은 그대로** |

가드 · 보호 확인은 모든 프리셋에서 고정이며 화면에서 끌 수 없다. (블록을 직접 끼워 맞추는 "조립" 화면은 다음 단계 — 현재는 프리셋 2종 선택.)

### 수정 탭: 파이프라인 실행 기록

실행마다 `rx/runs/*.json` 에 단계별 기록(`id · name · status(ok/fail/skipped/stop/held) · 소요 · 모델 · 비용 · 메모`)이 남고, 수정 탭 상단에 **블록이 이어진 도식**으로 표시된다(통과 초록 · 실패 빨강 · 건너뜀 점선 · 보류/중단 주황). 블록을 누르면 그 단계의 결과가 아래에 나온다.
텔레그램 `/auto` 에도 정책 한 줄(`정책: CRITICAL 수정(긴급) · ERROR 수정(표준) · WARN 끔`)이 나온다.
점검: `python -m src.busrx.selftest_policy`(정책 · API) · `selftest_fix`(S13 긴급 프리셋).

## 조립 탭 — 파이프라인 레고식 조립 (4단계)

관리 페이지의 **조립** 탭에서 자동 수정 파이프라인을 블록으로 끼워 맞춘다(규칙 · 블록 목록 `docs/AUTOFIX.md` §9, 구현 `src/busrx/pipelines.py`).

- 상단 선택 상자: 내장 프리셋(표준 · 긴급, 읽기 전용)과 사용자 정의 목록(정책이 쓰는 중이면 어느 레벨인지 표시). `표준에서 새로 만들기` · `복제` · `삭제`.
- 편집 영역: 이름 · id 입력, **블록이 이어진 도식**(🔒 잠금 블록 / 선택 블록 / 꺼진 블록은 점선), 블록을 누르면 설정 패널이 열린다.
  - 선택 블록(검증 · 독립 검토 · 적용 · 재시작): 끄기/켜기 · ▲▼ 이동 · 빼기, 빠진 블록은 `+ 블록` 칩으로 다시 추가.
  - 설정: 수정 라운드(0~3) · 모델 · 비용 상한 · 테스트의 핵심 모듈 포함 여부. 잠금 블록은 이동 · 끄기 · 빼기 버튼 자체가 없다.
- **실시간 규칙 검증**: 바꿀 때마다 서버(`POST /api/pipelines/validate`)가 같은 규칙으로 검사해 ✓/✗ 를 보여 주고, 위반이면 저장 버튼이 꺼진다(예: 검토를 커밋 뒤로 옮기면 즉시 오류). 검증 · 검토를 모두 뺀 조립이나 적용만 있고 재시작이 없는 조립은 경고(⚠️/ℹ️)를 띄운다.
- 저장: `POST /api/pipelines`(CSRF + 확인 창). 서버가 저장 때 한 번 더 검증하고, 내장 id 덮어쓰기 · 가드 없는 조립은 거부한다. 저장한 파이프라인은 **제어 탭의 레벨별 정책**에서 고르면 다음 에러부터 쓰인다.
- 삭제: 정책이 쓰는 중이면 409 + 어느 레벨인지 안내(제어 탭에서 다른 파이프라인으로 바꾼 뒤 삭제).

### 초기화 버튼

| 위치 | 버튼 | 효과 |
|---|---|---|
| 조립 탭 | **편집 취소(원래대로)** | 저장된 상태로(새 파이프라인이면 표준 상태로) 편집 내용을 되돌림 — 서버에 아무것도 쓰지 않음 |
| 조립 탭 | **사용자 정의 전부 삭제(내장만 남김)** | `rx/pipelines.json` 삭제 → 내장 프리셋(표준 · 긴급)만 남음. 이력 `rx/pipelines_history.jsonl` |
| 제어 탭 | **기본값으로**(정책 카드) | 레벨별 정책을 기본값으로 |
| 제어 탭 | **정책 + 파이프라인 전체 초기화** | 위 둘을 한 번에(확인 창 2번). 수신기 정지(PAUSE) · 발신 레벨 같은 일시 설정은 건드리지 않음 |

삭제된 파이프라인을 정책이 가리키고 있으면 그 레벨은 **기본 프리셋**(CRITICAL 긴급 · ERROR 표준)으로 안전하게 돌아간다(정책 캐시가 파이프라인 파일 변경도 감지). API: `POST /api/reset {what: policy | pipelines | all}`.
점검: `python -m src.busrx.selftest_builder`(조립 API · 초기화 · 정책 연동).
