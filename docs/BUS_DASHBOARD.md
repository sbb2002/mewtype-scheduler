# 자동제어 관리 페이지 (BUS_DASHBOARD) — v4.3-fullauto

> 러너 어드민 페이지(`/admin`)와 **별개의** 페이지. 수신기 프로세스 안에서 별도 포트로 동작하며 어드민 코드(`admin_*.py`, `admin.html`)를 건드리지 않는다.
> 규약·단계 설명은 `docs/BUS_PROTOCOL.md` · `docs/AUTOFIX.md`. 구현: `src/busrx/web.py` + `src/busrx/web_static/{index,login}.html`.

## 접속 · 로그인

- 수신기를 켜면 같이 뜬다: `http://127.0.0.1:8789/` 와 이 PC 의 Tailscale IP(`http://<tailscale-ip>:8789/`). 포트 `RX_WEB_PORT`(기본 8789), 끄기 `RX_WEB=0` 또는 `--no-web`.
- **`ADMIN_SECRET` 이 있어야 켜진다**(없으면 경고만 남기고 안 켬). 로그인 = `/login` 에서 버튼 → **텔레그램 일회용 링크**(5분 · 1회) → 링크를 열면 세션(12시간, HttpOnly + SameSite=Lax 쿠키).
  링크 요청은 20초에 1번. 서명 키는 어드민과 같은 `ADMIN_SECRET` 이지만 용도(`rxlogin`)가 달라 어드민 링크와 서로 통하지 않는다.
- 쓰기 요청은 CSRF 헤더 필수. 응답은 `Cache-Control: no-store` + CSP 헤더. 127.0.0.1 과 Tailscale IP 에만 바인딩(전체 인터페이스 아님).

### 동작 주기

모드가 자동 · 반자동일 때 수신기가 에러를 처리하는 시점. 정책 파일(`rx/policy.json`)의 `cycle` 값 `event` | `h1` | `h3`.

- **이벤트 발생 시마다**(기본): 에러가 도착하는 대로 분석 · 수정(같은 종류는 쿨다운 안에서 1회).
- **1시간마다 · 3시간마다**: CRITICAL 이 아닌 에러는 `err/hold`(보류 폴더)에 모았다가 KST 정시(3시간은 0 · 3 · 6 … 시)에 같은 종류(시그니처)끼리 묶어 한 번씩 처리. **CRITICAL 은 주기와 관계없이 즉시 처리**하고 쿨다운도 그대로 적용한다. 묶음 주기에서는 쿨다운을 쓰지 않는다(CRITICAL 제외 — 정책 표의 쿨다운 칸이 비활성).
- 주기를 바꾸면 다음 정시부터 적용(묶음 → 이벤트마다로 바꾸면 쌓인 것을 즉시 처리).
- **묶음 대기 중 모드 변경**: 대기 건이 있으면 `/api/mode` 가 409(`needs_queue`)를 돌려주고 화면이 팝업을 띄운다 — **예**(먼저 처리하고 변경) · **아니오**(버리고 변경) · **취소**(팝업만 닫음). 텔레그램 `/automode` 는 대기 건이 있으면 관리 페이지에서 바꾸도록 안내한다.
- 모드 `끔`에서는 보류도 분석도 하지 않고 기록만 한다.

### 발신 레벨 (정책 표의 "발신" 열)

CRITICAL · ERROR 는 항상 발신(고정). WARN · INFO · DEBUG 를 체크하면 그 레벨까지 발신(위 레벨은 함께 켜짐). INFO · DEBUG 는 양이 많아 **임시 발신**(15분 · 1시간 · 4시간 뒤 자동 해제)이 기본이고 **항상 유지**(`ttl_sec: 0`)도 고를 수 있다 — 항상 유지는 발신기 메모리에만 있어 러너를 재시작하면 `MEW_BUS_LEVEL`(기본 WARN)로 돌아간다. 저장 시 제어 봉투(`set_level`)로 전달된다.

수정 일일 상한은 없다(오늘 수정 시도 횟수는 Overview 에 기록만 표시). 분석 일일 상한(`RX_DAILY_CALLS`, 기본 20)은 그대로.

모든 쓰기는 확인 창을 거친다. 발신기 제어는 `mew.ctl/1` 봉투를 `ctl/inbox` 에 쓰는 방식이라 발신기가 최대 5초 안에 처리하고 결과가 `최근 제어 결과`에 나타난다.

## 에러 레벨별 자동 대응 정책 (제어 탭)

심각도(CRITICAL~DEBUG)마다 **기록 · 동작 · 파이프라인 프리셋 · 쿨다운**을 정한다. 저장하면 `rx/policy.json` 에 쓰이고 **수신기가 다음 에러부터 바로 반영**한다(재시작 불필요). 변경 이력은 `rx/policy_history.jsonl`(누가 · 무엇을), 검증 규칙은 `src/busrx/policy.py`.

| 칸 | 값 |
|---|---|
| 기록 | 켬/끔 — 끄면 `rx/log.jsonl` 에도 남기지 않음 |
| 동작 | **끔**(기록만) · **분석만** · **수정까지** — 모든 레벨에서 선택 가능(WARN 이하는 외부 요인 에러에도 수정을 시도하므로 화면에 경고) |
| 파이프라인 | **표준**(충분한 검증) · **긴급**(최소 검증) — "수정까지"일 때만 |
| 쿨다운(분) | 같은 시그니처를 다시 처리하기까지의 간격 |

기본값(운영자 정의): CRITICAL = 수정 · 긴급 · 5분 / ERROR = 수정 · 표준 · 60분 / WARN · INFO · DEBUG = 끔(기록만). `RX_STAGE=1` 이면 "수정까지"도 분석만 한다. `기본값으로` 버튼으로 초기화.
CRITICAL 을 끄거나 WARN 이하를 분석으로 올리면 화면에 경고(사용량 증가 등)가 뜬다. 정책 파일이 손상되면 기본값으로 안전하게 복구한다.

### 파이프라인 프리셋

| 프리셋 | 구성 |
|---|---|
| **표준** | 분석 → 명세서 → 구현 → 가드 → 문법·self-test(변경 모듈 + 핵심 모듈) → **검증 → 독립 검토** → 커밋 → 보호 확인 → 적용 → 재시작 → 건강 확인 |
| **긴급** | 위에서 **검증 · 독립 검토를 건너뛰고**, self-test 는 변경 모듈만. **가드(금지 자원 확인)와 보호 대상 불변 확인은 그대로** |

가드 · 보호 확인은 모든 프리셋에서 고정이며 화면에서 끌 수 없다. (블록을 직접 끼워 맞추는 "조립" 화면은 다음 단계 — 현재는 프리셋 2종 선택.)

## 조립 탭 — 파이프라인 레고식 조립 (4단계)

관리 페이지의 **조립** 탭에서 자동 수정 파이프라인을 블록으로 끼워 맞춘다(규칙 · 블록 목록 `docs/AUTOFIX.md` §9, 구현 `src/busrx/pipelines.py`).

- 상단 선택 상자: 내장 프리셋(표준 · 긴급, 읽기 전용)과 사용자 정의 목록(정책이 쓰는 중이면 어느 레벨인지 표시). `표준에서 새로 만들기` · `복제` · `삭제`.
- 편집 영역: 이름 · id 입력, **블록이 이어진 도식**(🔒 잠금 블록 / 선택 블록 / 꺼진 블록은 점선), 블록을 누르면 설정 패널이 열린다.
  - 선택 블록(검증 · 독립 검토 · 적용 · 재시작): 끄기/켜기 · ▲▼ 이동 · 빼기, 빠진 블록은 `+ 블록` 칩으로 다시 추가.
  - 설정: 수정 라운드(0~3) · 모델 · 비용 상한 · 테스트의 핵심 모듈 포함 여부. 잠금 블록은 이동 · 끄기 · 빼기 버튼 자체가 없다.
- **실시간 규칙 검증**: 바꿀 때마다 서버(`POST /api/pipelines/validate`)가 같은 규칙으로 검사해 ✓/✗ 를 보여 주고, 위반이면 저장 버튼이 꺼진다(예: 검토를 커밋 뒤로 옮기면 즉시 오류). 검증 · 검토를 모두 뺀 조립이나 적용만 있고 재시작이 없는 조립은 경고(⚠️/ℹ️)를 띄운다.
- 저장: `POST /api/pipelines`(CSRF + 확인 창). 서버가 저장 때 한 번 더 검증하고, 내장 id 덮어쓰기 · 가드 없는 조립은 거부한다. 저장한 파이프라인은 **제어 탭의 레벨별 정책**에서 고르면 다음 에러부터 쓰인다.
- 삭제: 정책이 쓰는 중이면 409 + 어느 레벨인지 안내(제어 탭에서 다른 파이프라인으로 바꾼 뒤 삭제).

### 초기화 버튼

| 위치 | 버튼 | 효과 |
|---|---|---|
| 조립 탭 | **편집 취소(원래대로)** | 저장된 상태로(새 파이프라인이면 표준 상태로) 편집 내용을 되돌림 — 서버에 아무것도 쓰지 않음 |
| 조립 탭 | **사용자 정의 전부 삭제(내장만 남김)** | `rx/pipelines.json` 삭제 → 내장 프리셋(표준 · 긴급)만 남음. 이력 `rx/pipelines_history.jsonl` |
| 제어 탭 | **기본값으로**(정책 카드) | 레벨별 정책을 기본값으로 |
| 제어 탭 | **정책 + 파이프라인 전체 초기화** | 위 둘을 한 번에(확인 창 2번). 수신기 정지(PAUSE) · 발신 레벨 같은 일시 설정은 건드리지 않음 |

삭제된 파이프라인을 정책이 가리키고 있으면 그 레벨은 **기본 프리셋**(CRITICAL 긴급 · ERROR 표준)으로 안전하게 돌아간다(정책 캐시가 파이프라인 파일 변경도 감지). API: `POST /api/reset {what: policy | pipelines | all}`.
점검: `python -m src.busrx.selftest_builder`(조립 API · 초기화 · 정책 연동).

## 동작 모드: 자동 · 반자동 · 끔 (제어 탭 최상단)

자동제어가 에러에 반응하는 **전체 스위치**(2026-10-12 운영자 요청). 저장: `rx/policy.json` 의 `mode`(정책과 같은 파일, 변경 이력은 `policy_history.jsonl`). 텔레그램 `/automode [auto|semi|off]` 로도 바꿀 수 있고 `/auto` 현황에 표시된다. 에러 레벨별 세부 동작(정책 표)은 모드와 별개로 적용된다.

| 모드 | 동작 |
|---|---|
| **자동**(기본) | 지금까지와 같음 — 정책에 따라 분석 → 명세서 → 구현 → … → 적용 · 재시작을 전부 자동으로 |
| **반자동** | 분석 후 **패치 계획안**(에러 요약 + 계획 요약 + 계획 파일)만 만들고 **사람의 결정을 기다림** — 승인 탭에서 **승인 / 반려(재계획) / 거절** |
| **끔** | 자동제어가 동작하지 않음 — 에러는 `rx/log.jsonl` 에 기록만(claude 호출 · 보고 없음). 텔레그램 알림(발신기 소실 · 복구 포함)도 보내지 않음. 소실이 이어지면 모드를 다시 켠 뒤 알림. 이 페이지 · 텔레그램 명령은 계속 동작 |

수신기 분석 정지(`rx/PAUSE`)는 별도의 **긴급 임시 정지**로 그대로 남아 있다(모드와 무관하게 둘 중 하나라도 켜져 있으면 분석하지 않음). 정책 `전체 초기화`는 모드도 자동으로 되돌린다.

### 승인 탭 (반자동)

- 헤더에 모드가 표시되고, **승인 대기 건수**가 탭 배지로 뜬다. 텔레그램에는 계획안이 만들어질 때 **캡션 + 계획 파일(`plan_<시그니처>_rev<N>.md`)** 이 온다.
- 카드 내용: ① **에러 요약**(메시지 · 누적 · 시간 · 발생 커밋) ② **원인 분석**(Sonnet) ③ **패치 계획 요약**(제목 · 파일별 변경 · 테스트 계획 · 위험, 재계획이면 반영한 반려 사유) ④ `계획 파일 보기`(마크다운 전문) ⑤ 결정 이력.
- **승인**: 승인된 계획으로 파이프라인(구현 → 가드 → 테스트 → 검증 → 검토 → 커밋 → 보호 확인 → 적용 · 재시작)을 실행한다 — **명세서를 다시 작성하지 않는다**. 완료되면 평소와 같은 텔레그램 보고서가 온다.
  계획을 만든 뒤 코드가 바뀌었으면 카드에 경고가 뜨고, 승인하면 **현재 코드 기준**으로 실행된다(결과에 `stale_base` 기록).
- **반려(재계획)**: 사유(3자 이상)를 적으면 Sonnet 이 이전 계획 + 사유를 반영해 계획을 **다시 작성**한다(새 판 rev N+1, 이전 판은 보존, 최대 5회). 다시 승인 대기로 돌아온다.
- **거절**: 아무 변경도 하지 않고 종료. 같은 에러는 쿨다운 동안 다시 제안하지 않는다.
- 수정 대상이 아닌 에러(외부 서비스 오류 등)는 계획안을 만들지 않고 분석 보고만 한다. 정책이 "분석만"이면 반자동이어도 계획안은 없다.
- 승인 후 적용이 보류되면(미커밋 변경과 겹침 등) 계획안 상태는 `실패`가 아니라 **`적용 보류(held)`** 이고 수정 브랜치는 보존된다.
- 계획안 파일: `rx/proposals/<id>.json` + `<id>/plan_rev<N>.md`. 처리 중 수신기가 꺼지면 다음 기동 때 `interrupted` 로 표시. 분석 · 수정 파이프라인은 한 번에 하나만 돈다(승인 실행 중에는 새 에러 처리가 대기).
- 점검: `python -m src.busrx.selftest_semi`(모드 · 계획 · 승인/반려/거절 · 중복 클릭 · 코드가 바뀐 뒤 승인 · 재계획 상한 · 복구 · API · `/automode`).
