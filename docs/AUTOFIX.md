# 자동 수정 (AUTOFIX) — 수신기 2단계, test-fullauto-hotfix

> 브랜치 `test-fullauto-hotfix` 전용 실험 (2026-10-12 운영자 결정). `main` · 운영에는 반영되지 않았다.
> 1단계(분석 · 보고)는 `docs/BUS_PROTOCOL.md` §11-1, 이 문서는 **2단계(수정안 작성 → 검증 → 로컬 브랜치 커밋 → 러너 적용 · 재시작)**.

| 항목 | 결정 |
|---|---|
| 모델 배정 | **코드 수정 · 구현 = Haiku 5.5** (`claude-haiku-5-5`). **분석 · 명세서 작성 · 검증 · 이중 검토 = Sonnet 5.5** (`claude-sonnet-5-5`) |

| 자동 병합 | 불필요 (main 병합 없음) |
| 러너 재시작 | 패치 적용 후 **자동으로** 진행 |

## 2. 파이프라인 (확정된 원인에 대해서만)

```
분석(Sonnet) ─ confirmed ─▶ 명세서(Sonnet) ─ fixable ─▶ 워크트리 생성(auto/<시그니처>-<n>)
   ─▶ 구현(Haiku) ─▶ 기계 검사(가드 · 문법 · self-test 전후 비교)
   ─▶ 검증(Sonnet) ─▶ 이중 검토(Sonnet, 새 맥락)  ──(문제 있으면 Haiku 수정 라운드 1회)──▶
   로컬 브랜치 커밋(수신기가 직접) ─▶ 보호 대상 불변 확인 ─▶ 러너 작업 브랜치에 ff-only 적용
   ─▶ 러너 재시작 ─▶ 건강 확인 ─ 실패 시 ─▶ 자동 git revert + 재시작
```

- 분석이 `unknown`/`ignored` 이거나 명세서가 `fixable=false`(외부 서비스 일시 오류 등)이면 **코드를 고치지 않고** 그 사유를 보고한다.
- 하루 수정 시도 상한은 없다(2026-10-13 운영자 결정 — 시도 횟수는 기록만). 수정 호출은 Pro 사용 한도를 소모한다.
- 구현(Haiku)은 **셸 도구가 없다**(`Read,Grep,Glob,Edit,Write` + `acceptEdits`). git · 테스트 실행은 수신기가 한다. Haiku 는 git 을 쓰지 못한다.
- 검증 · 검토는 읽기 전용(`Read,Grep,Glob`). 검토자는 명세서 · 검증 결과를 보지 않고 원인 분석과 diff 만 본다.
- 수정 라운드는 1회: 문법 오류 · self-test 회귀 · 검증/검토 반려는 지적 사항을 Haiku 에 되돌려 다시 시도하고, 그래도 안 되면 폐기한다.
  **금지 자원 위반 · 검토자의 운영 자원 접촉 지적은 수정 라운드 없이 즉시 폐기**한다.

## 2-1. 프리셋 · 단계 기록

프리셋(`PRESETS`): **표준** = 검증 + 독립 검토 포함 / **긴급** = 검증 · 검토 생략 + 변경 모듈 self-test 만(가드 · 보호 확인은 항상 유지). 어떤 프리셋을 쓸지는 에러 레벨별 정책이 정한다(`docs/BUS_DASHBOARD.md`). 각 실행의 단계별 기록(`steps`)은 `rx/runs/` 와 보고 봉투에 저장된다.

3. **금지 자원이 추가되는 줄**(추가된 줄만 검사) — 위반이면 즉시 폐기:

   `['git', 'push']` 같은 인자 리스트 형태 포함) · 텔레그램 봇 토큰 형태 · chat id 리터럴 · 운영 헬스체크 · main/data 브랜치 직접 지정 ·
   현재 환경의 비밀값/chat id 값이 코드에 들어간 경우.
4. **디스클레이머**: 디스클레이머 · 면책 · 법률 문구가 든 줄의 **삭제**는 위반.
5. **보호 대상 불변**(수정 전 · 후 스냅샷 비교): 로컬 `main` · `data` 브랜치 ref, **모든 원격 추적 ref**(푸시했다면 바뀐다), `origin` URL 등 remote 설정,
   `.env` · `.env.local` 내용. 하나라도 달라지면 위반.
6. **자체 검증**: 변경된 `.py` 문법 검사(`.pyc` 를 만들지 않음) + 변경 모듈과 핵심 모듈(`preview` · `statemachine` · `preview_build` · `xtweet` · `xrelay` · `notices`)의
   self-test 를 **변경 전 스냅샷과 변경 후 워크트리에서 각각** 돌려 비교. 변경 전엔 통과했는데 후에 실패하면 회귀(수정 라운드 대상). 변경 무관 기존 실패는 건수로만 표시.
   테스트 실행 환경에는 비밀 환경 변수를 넘기지 않는다.
7. **새 외부 의존성 금지(2026-10-13)**: 수정이 기준 코드(`src/` · `config/` · `deploy/` 스냅샷)에 **없던 외부 호스트**(다른 API 공급자 주소)나 **없던 환경변수 이름**(새 API 키)을 추가하면 위반으로 즉시 폐기한다(`guard.external_additions`). 주석만 있는 줄과 `example.com` 류는 제외. 공급자 교체 · 새 키 도입은 코드 수정이 아니라 사람의 결정이기 때문이다.

8. 텔레그램 보고에 **"금지 자원 확인: 통과/실패 (확인 항목 목록)"** 이 항상 들어간다.

## 4. 적용과 재시작

- 적용 = 러너가 쓰는 작업 폴더(`RX_RUNNER_DIR`, 기본 이 저장소)의 **작업 브랜치(`RX_APPLY_BRANCH`, 기본 `test-fullauto-hotfix`)에 `git merge --ff-only auto/…`**.
  main · data 에는 절대 하지 않는다. 원격 푸시도 하지 않는다.
- 다음이면 **적용을 보류**하고 브랜치만 남긴다(보고서에 사유): 현재 브랜치가 작업 브랜치가 아님 · HEAD 가 수정 base 와 다름 · **미커밋 변경이 수정 파일과 겹침** · ff 불가.
  `RX_APPLY_LOCAL=0` 이면 항상 로컬 브랜치 커밋까지만.
- 재시작(`src/busrx/restart.py`): `_local/ops/runner.json` 의 pid 가 실제로 `local_runner` 를 실행 중일 때만 종료(`taskkill /T /F`) 후 같은 명령을 분리된 프로세스로 재기동.
  러너가 안 떠 있었으면 재시작하지 않고 "적용만"으로 보고. 재시작 뒤 출력은 `<러너 폴더>/_runner.log`.
  **원래 터미널 창에서 보던 러너 출력은 재시작 후 그 창에서 더 이상 안 나온다**(로그 파일로 이동).
- 건강 확인: `/healthz-local` ok + 발신기 hb 가 재시작 이후로 갱신. 실패하면 **자동 `git revert --no-edit HEAD` 후 재시작** — 결과를 보고한다.
- 재시작 중에는 "발신기 소실" 알림을 4분간 억제한다. 큐 작업은 디스크에 있어 재시작해도 이어진다.

## 7. 점검

`python -m src.busrx.selftest`(1단계) · `python -m src.busrx.selftest_fix`(2단계: 임시 git 저장소 + 가짜 claude · 가짜 재시작으로 S1~S12 · 가드 단위) · `python -m src.bus.conform`.

## 8. 구독 사용량 표시 (2026-10-12 운영자 요청)

텔레그램 보고마다 `── 사용량(구독) ──` 구간을 붙인다: **세션(5시간)** 사용률 · 남음 · 초기화 시각(KST) · **이번 처리에서 늘어난 %p**, **주간(7일)** 사용률 · 남음 · 초기화 시각.
- 출처: `claude -p --output-format stream-json --verbose` 가 호출마다 내보내는 `rate_limit_event` 의 `unifiedWindows.five_hour / seven_day` (`utilization` 0~1, `resetsAt` epoch).
  구독(claude.ai 로그인) 인증일 때만 있고, 없으면 "사용량 정보 없음"으로 표시.
- 한계: 사용률은 **같은 계정의 다른 세션(사람이 쓰는 Claude Code 포함) 사용분을 포함한 값**이고 1%p 단위로 갱신되어, 작은 처리는 +0~1%p 로 보인다.
  "이번 처리" 증가분은 직전 보고 이후(15분 이내, 같은 5시간 창)의 값을 기준선으로 하고 없으면 이번 처리의 첫 이벤트를 기준으로 한다.

## 9. 블록 기반 파이프라인 엔진 (3단계, 2026-10-12)

자동 수정 파이프라인은 코드에 고정된 흐름이 아니라 **블록의 순서 있는 목록**이다(`src/busrx/pipelines.py`). 엔진(`autofix.py`)이 목록대로 블록을 실행하고, 같은 목록이 단계 기록 · 화면 도식의 기준이 된다.

| 블록 | 시점 | 잠금 | 조절 가능한 값 |
|---|---|---|---|
| 명세서(Sonnet) | 사전 | 🔒 | 모델 · 예산 |
| 수정 브랜치 · 워크트리 | 사전 | 🔒 | — |
| 구현(Haiku) | 반복 | 🔒 | **수정 라운드 수**(0~3), 모델 · 예산 |
| **가드: 금지 자원 확인** | 반복 | 🔒 | — |
| 문법 · self-test | 반복 | 🔒 | 핵심 모듈 포함 여부(`core`) |
| 검증(Sonnet) | 반복 | 선택 | 켜기/끄기 · 순서 · 모델 · 예산 |
| 독립 검토(Sonnet) | 반복 | 선택 | 켜기/끄기 · 순서 · 모델 · 예산 |
| 로컬 브랜치 커밋 | 사후 | 🔒 | — |
| **보호 대상 불변 확인** | 사후 | 🔒 | — |
| 러너 브랜치에 적용 | 사후 | 선택 | 켜기/끄기 |
| 러너 재시작 + 건강 확인(실패 시 자동 revert) | 사후 | 선택 | 켜기/끄기 (적용이 꺼지면 켤 수 없음) |

- **잠금 블록**은 빼거나 끌 수 없고 서로의 순서도 바꿀 수 없다 — 운영 자원 보호(가드 · 보호 확인)와 안전한 커밋 절차를 설정으로 약화시킬 수 없다.
- 선택 블록 규칙: 검증 · 독립 검토는 `문법 · self-test` 뒤 `커밋` 앞에서 서로 순서를 바꿀 수 있고, 적용은 보호 확인 뒤, 재시작은 적용 뒤.
- 구현 → 가드 → 테스트 → (검증 · 검토) 는 **한 사이클**이다. 가드의 hard 위반(금지 자원 · 경로 · 비밀값 · 디스클레이머, 검토자의 운영 자원 접촉 지적)은 라운드 없이 폐기하고,
  그 외 문제는 `max_revisions` 만큼 구현으로 되돌아가 고친다.
- 내장 프리셋: **표준**(검증 · 검토 켜짐, 핵심 모듈 테스트, 수정 라운드 1회) · **긴급**(검증 · 검토 끔, 변경 모듈 테스트만). 사용자 정의 파이프라인은 `rx/pipelines.json` 에 저장하고
  (`pipelines.save_custom` — 저장 · 로드 때마다 같은 검증을 통과해야 하며 손으로 고쳐 가드를 뺀 항목은 **로드 시 무시**), 레벨별 정책(`policy.json`)의 `preset` 에 id 로 지정한다.
  정책이 가리키던 파이프라인이 사라지면 표준으로 안전하게 대체된다.
- 점검: `python -m src.busrx.selftest_pipeline`(규칙 · 저장 · 정책 연동 48개) · `selftest_fix` S14~S18(조립된 순서 · 수정 라운드 수 · 적용/재시작 끄기 · 가드 유지).

### 9-1. 실제 모델 검증 (2026-10-12)

임시 git 저장소(운영 · 러너와 무관, 적용 · 재시작 없음)에 `average` 의 off-by-one 버그를 심고 **실제 Sonnet 5.5 / Haiku 5.5** 로 표준 파이프라인을 처음 끝까지 돌렸다:
명세서(Sonnet 11초) → 구현(Haiku 6.5초, 한 줄 수정 + self-test 추가) → 가드 통과 → self-test 1/1 → 검증 승인 → 독립 검토 승인 → 로컬 커밋 → 보호 확인 통과. 총 약 1분, API 환산 약 $0.15.
이 시험은 임시 저장소의 단일 파일 단순 버그 1건이다 — 실제 운영 코드 · 다중 파일 · 어려운 버그에서의 정확도는 `docs/AUTOFIX_FAULT_INJECTION.md` 의 결함 주입 시험으로 측정해야 한다.

## 10. 동작 모드 (2026-10-12)

`자동`(기본) / `반자동` / `끔` — 상세 `docs/BUS_DASHBOARD.md`. 반자동은 분석 후 **패치 계획안**(`AutoFix.plan()` — 명세서 블록만 실행, 코드는 건드리지 않음)을 만들고,
사람이 승인하면 **같은 계획으로** `AutoFix.run(..., plan=...)` 이 사전 블록의 명세서를 건너뛰고 구현부터 진행한다(승인된 계획 rev 가 단계 기록에 남음).
반려는 `replan` 호출(이전 계획 + 사유 → 새 판)이고 거절은 아무것도 하지 않는다. 가드 · 보호 확인 등 잠금 블록은 모드와 무관하게 항상 동작한다.


## 11. 사람 조치 필요 (2026-10-13 운영자 지시)

외부 서비스(LLM · YouTube · GitHub · 텔레그램 등 **모든 외부 API**)의 **인증 · 결제/요금제 · 쿼터 · 계정 · 정책 변경 · 엔드포인트/모델 폐지**가 원인인 에러는
코드를 고쳐 풀 문제가 아니라 사람이 정할 문제(키 갱신 · 요금제 선택 · 공급자 교체 · 새 토큰 발급)다. 자동 패치는 이를 이렇게 다룬다.

1. **분석기 판정**: 분석 결과에 `needs_human`(bool) · `human_action`(사람이 할 일)이 있다(`receiver.RESULT_SCHEMA`, 둘 다 선택 필드). 지침 10번이
   위 원인이면 `needs_human=true` 로 하고 **공급자를 바꾸는 코드를 제안하지 말라**고 요구한다. 코드 버그 · 일시 장애는 `false`.
2. **수정 단계를 시작하지 않는다**: `needs_human` 이면 명세서 · 구현 · 계획안(반자동) 없이 끝낸다. 보고서에 「🙋 사람이 결정할 일」 항목, 실행 기록에
   `사람 조치 필요` 단계(`held`)가 남는다. 명세서 지침도 `needs_human` 이면 `fixable=false` 를 요구한다(이중 방어).
3. **표시 · 알림**: `state.meta[sig].human = {since, until_epoch, reason, action}` 로 표시하고 **텔레그램에 1회** 알린다(`🙋 사람 조치 필요 …`).
4. **재분석 중단**: 표시가 살아 있는 동안 같은 에러는 분석 · 수정하지 않고 로그에만 `사람 조치 필요 — 재분석 생략` 으로 남긴다(구독 사용량 보호,
   수정 일일 상한이 없으므로 반복 시도를 막는 장치). 표시는 `RX_HUMAN_TTL`(기본 86400초) 뒤 만료되어 같은 에러가 계속되면 한 번 다시 분석한다.
5. **해제**: 관리 페이지 Control 탭의 「조치 완료 — 다시 감시」(`POST /api/human_clear`) — 쿨다운도 초기화한다.
   운영자가 직접 누르는 **수동 분석 · 수정**은 표시 중에도 막지 않는다.
6. 방어선 정리: ① 분석 지침 ② 명세서 지침 ③ 수정 구현 지침(새 호스트 · 환경변수 금지) ④ 가드(`external_additions`) — 하나가 뚫려도 다음이 잡는다.

시험: `python -m src.busrx.selftest_human`(가짜 claude, 가드 · 상태 · API · 화면) · `python -m src.busrx.live_human_check`(진짜 claude 로 외부 API 장애별 반응 —
결과는 `docs/AUTOFIX_HUMAN_ACTION_TEST_2026-10-13.md`).

## 12. 사람 개입 최소화 — 민감 경로 · 사람 요청 · 데이터 이전 (2026-10-27 운영자 지시, 시험 S-O 후속)

동작 모드의 뜻(운영자): **자동** = 정말 필요한 경우(혼자 진행할 수 없는 것)를 빼면 사람이 손대지 않는다 · **반자동** = 분석 후 패치가 필요하면 그때마다 허가 ·
**끔(수동)** = 에러 알림만(경우에 따라 분석 보고서까지). 시험 S-O(devpapers `ref/autofix-test/result_2026-10-27.md`)에서 원인을 확정하고도
근본 수정 위치가 금지 경로라 `not_fixable` 로 멈춘 것을 계기로, 자동 · 반자동에서 할 수 있는 범위를 넓혔다.

1. **가드 3단계**(`guard.py`): 절대 금지 = `src/bus/` · `src/busrx/`(자기 자신) · 운영 자원 문자열 · 비밀값 · 원격 git · 디스클레이머 · 보호 ref(그대로 폐기) /
   **사람 요청** = 새 외부 호스트 · 새 환경변수(폐기 + 요청) / **민감 경로** = `SENSITIVE_PATHS`(저장 계층 `storage` · `gh_store` · `local_store`,
   `tasks` · `oidc` · `config` · `writeclient` · `local_runner` · `tg_poll` · `notify`, `docs/`, `scripts/`) — `RX_SENSITIVE=1` 이면 자동 허용.
   `src/frontend/` · `config/` · `deploy/` 는 여전히 범위 밖.
2. **민감 경로를 고친 수정의 조건**: 바꾼 모듈 self-test(전후 비교) + **검증 · 검토를 끌 수 없다**(긴급 프리셋에서도 실행, 검토자에게 호출부 · 데이터 형식 호환 확인 지시) +
   보고서 · 계획안에 「⚠️ 민감 경로 수정」 표시(반자동은 이 표시를 보고 허가).
3. **명세서 세 갈래**(`SPEC_SCHEMA`): `fixable=true` 진행 / `fixable=false · needs_human=true` **사람 요청**(`human_need` — 자격 증명 · 결제 · 계정 · 공급자 선택 ·
   외부 서비스 설정처럼 혼자 할 수 없는 것만) / 그 밖 `not_fixable`. 사유 원문은 자르지 않고 보고서 · `rx/fix/<sig>/SPEC.md` 에 남긴다(단계 기록만 300자).
   사람 요청이면 「사람 조치 필요」 표시 · 텔레그램 알림(§11 과 같은 경로, 반자동 계획 단계 포함).
4. **운영 값은 스스로 정한다**: 보존 기간 · 임계값 등은 묻지 않고 기존 관례에서 보수적인 값을 정해 `auto_decisions` 에 「값 — 근거」로 — 보고서 「자동 결정한 값」(사후 보고).
5. **땜질 금지**(민감 규칙 `RULES_SENSITIVE`): 에러 삼키기 · 데이터 버리기 · 증상만 가리기로 끝내지 않는다. 검증 · 검토도 땜질이면 반려.
6. **데이터 이전**: 저장된 데이터를 옮겨야 하면 명세서 `migration.script`(`scripts/…`) — 계약 `python <스크립트> --data <data 폴더> --ops <ops 폴더>`,
   파일 직접 읽기 · 쓰기(네트워크 금지), 멱등, 잃은 항목 · 중복이면 0 이 아닌 종료 코드. 수신기가
   ① 테스트 단계에서 `RX_DATA_DIR` **복사본**(`rx/fix/<sig>/data_try`)에 돌려 보고(실패 = 수정 라운드) ② 적용(ff) 직후 **백업**(`rx/fix/data_backup_<버전>`)을 뜨고 실제 데이터에 실행,
   실패하면 데이터 복원 + 패치 revert(`reverted`). `RX_DATA_DIR` 이 없으면(운영처럼) 코드는 브랜치에 두고 적용을 보류, 이전 실행을 사람에게 요청한다.
7. **분석 규칙**: `unknown` 이면 cause 와 따로 `hypothesis`(유력 가설) · `how_to_confirm`(확인 방법)을 받아 보고서에 싣는다. 지침 10번의 사람 조치는
   혼자 못 하는 것만 — 운영 값 · 저장 계층 · 계약 문서 · 데이터 이전은 사람 조치가 아니다.
8. **기타**: 단계 이름에 실제 모델(`명세서(Opus)` 등, `claude.model_label`) · claude 서브프로세스에 `CLAUDE_*` 세션 변수를 넘기지 않음(`CLAUDE_CONFIG_DIR` · `ANTHROPIC_*` 만 —
   수신기를 Claude 세션 셸에서 띄우면 `CLAUDE_EFFORT` 등이 새어 effort 가 바뀔 수 있었다).
9. self-test: `python -m src.busrx.selftest_sensitive`.
