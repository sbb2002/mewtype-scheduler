# VERSION_vT — 테스트판(브랜치 `v4.3-fullauto`) 버전 기록

이 파일은 **테스트판 전용**이다. 배포판 기록 `docs/VERSION.md` 와 번호 체계 · 파일이 별개이고, main 에 병합할 때 이 파일은 가져가지 않는다.

**번호 규칙 (2026-10-13 운영자 지시)**: `vT1.0.0` 에서 시작하고 프로젝트의 기존 규칙(`CLAUDE.md` 「버전 번호 올리는 기준」)대로 올린다.
- **핫픽스**(새 요소가 아닌 버그 수정) = 패치 번호 Z 만 올린다 → `vT1.0.1`, `vT1.0.2` …
- **기능**(새 요소) = 마이너 Y 를 올린다 → `vT1.1.0`. 사람이 직접 올린다.
- 알파벳 접미사는 패치 분기가 생길 때만.
- **자동 대응이 만든 수정은 핫픽스다.** 수신기가 **커밋까지 간 수정만** 번호를 쓰고(폐기 · 실패한 시도는 번호 없음 — 기록은 수신기 `rx/runs/` 에만),
  패치 커밋 바로 뒤에 `docs(vT…): 버전 기록` 커밋으로 이 파일 맨 위에 항목을 추가한다(`src/busrx/testver.py`). 구현 모델은 이 파일을 수정할 수 없다(가드가 `docs/` 금지).
- 최신 번호는 이 파일 맨 위 `## vT…` 제목이다(저장소가 진실 소스).
- **`vT1.0.0` = 옛 테스트판 표기 `v4.3.x` 에 대응한다**(브랜치 이름 `v4.3-fullauto`의 `v4.3`). 옛 표기 `v4.3.<n>`(수신기가 시도마다 올리던 순번)은 폐기한다.
  이미 만들어진 `v4.3.9`(RSS 재시도, 커밋 `1ab981c`)는 **vT1.0.0 에 포함**된 것으로 본다.
- **배포판과의 관계**: 테스트판은 배포판 main 의 **v4.2.3**(2026-10-09) 위에서 갈라졌다. 번호 `vT…` 는 배포판 번호(`v4.2.x` …)와 별개이며 서로 대응하지 않는다 —
  `vT1.0.0` 은 "배포판 v4.2.3 + 에러 버스 · 자동 대응 실험 일체"다. (작성 시점의 배포판은 백엔드 v4.2.0 부근 · main v4.2.3.)
