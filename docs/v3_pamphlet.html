탭을 누르면 그 신호가 어디를 거쳐 사이트에 닿는지 표시됩니다.

개인 트윗 예고 판정 (v3.6)

위 "개인 트윗" 탭의 상세 — 업스트림이 중계한 원문 한 장이 preview.json에 반영되거나, 소식(notice)으로 새거나, 조용히 버려지는 전체 판정 경로. 2026-09-16 설계 검토 산출물, 8개 탭 = 8가지 트윗 유형.

이전 (텍스트 정규식 전용)

키워드 정규식 配信 등 + 날짜/시각 정규식만으로 등록 여부를 결정. 후기 트윗 속 무관한 숫자(9/24 출시일, 2時間 플레이시간)가 날짜·시각으로 오합성돼도 못 걸러냄 — 아라레 오탐 실사례.

이후

URL이 있으면 YouTube API로 먼저 사실관계를 확정. 유튜브 아닌 URL은 추적 불가능하므로 소식으로 이관. URL이 없을 때만 정규식으로 후보를 뽑고, 등록 직전 LLM에게 "이게 진짜 예고냐"고 마지막으로 되묻는다.

예시 트윗

등록됨 (preview.json) 미등록 · 조용히 종료 소식으로 이관 (notices.json) 외부 API/LLM 호출 (점선)

소식(notice) 판정 (v3 · v3.7 의미 중복 게이트)

자동 인입(/ingest 웹훅 → _maybe_auto_notice)과 수동 /notice 마법사 둘 다 이 경로로 모인다. url/title 정확일치로 걸러진 뒤에도 "문구만 다른 진짜 중복"이 남는 문제를 2026-09-17 LLM 게이트로 보강 — 탭 5·6이 그 부분.

예시

notices.json 반영 (added/updated/recap) 미반영 · dup/skip/형식아님 외부 LLM 호출 (점선, v3.7 duplicate_notice)

개인 트윗 인입 경로

/ingest 웹훅이 도착했을 때 제목(android.title)으로 먼저 갈래를 나누는 바깥쪽 흐름 — 예고 판정 자체의 상세(URL 유무 3갈래)는 위 "개인 트윗 예고 판정" 섹션을 그대로 가리킨다(중복 구현 안 함).

예시

tweets.json 스레드 저장 저장 없이 종료(ECHO) 또는 다른 트리로 위임
