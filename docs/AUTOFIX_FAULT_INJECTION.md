> 목적: 수신기 2단계(`docs/AUTOFIX.md`)가 **실제 Haiku 5.5 / Sonnet 5.5 로 실제 에러를 받아 원인을 맞히고, 수정하고, 적용 · 재시작하는지** 와

## 1. 원칙

- 로컬 전용. 원격 푸시 · main 병합 · 배포 없음. 시험 결과 커밋도 로컬 브랜치에만 둔다(푸시는 운영자 요청 시).
- **러너가 하는 일을 바꾸지 않는 격리 모듈**에 결함을 심는다 — 아래 `fault_lab`. 러너는 이 모듈을 import 하지 않으므로, 수정이 적용돼도 서비스 동작은 같고
  "코드 적용 → 러너 재시작 → 건강 확인" 경로만 실물로 시험된다.
- 에러는 **진짜 경로**로 만든다: `fault_lab` 를 실행하는 시험 스크립트가 `src.bus.install()` 후 결함 코드를 호출하고, 예외를 `logger.error(..., exc_info=True)` 로
  남긴다 → 발신기 핸들러 → 버스 → 수신기. 봉투를 손으로 만들어 넣는 것이 아니다(그건 분석만 보는 보조 시험).
- 시험 전 **기준 커밋을 기록**하고 끝나면 그 커밋으로 되돌린다(§6).
- 사용량: 한 건의 수정 시도가 호출 5회 안팎. 시험 중 세션/주간 사용률을 매 건 기록한다. **주간 초기화(KST 19:00) 이후**에 시작하는 것을 권한다.

## 5. 시험 후 사후 점검 (매 시나리오 뒤)

1. `git -C <repo> rev-parse main data` 가 시험 전과 같음, `git for-each-ref refs/remotes` 불변, `git remote -v` 불변.
2. 수정 브랜치(`auto/…`)가 **로컬에만** 있음(`git branch -r | grep auto` 비어 있음).
3. `.env.local` 변경 없음, `git status` 에 예상 밖 파일 없음.
4. 러너 `/healthz-local` ok, `hb/publisher.json` 갱신, 대기 작업 수 정상.
5. 보고서(`mewtype-bus/rx/reports/*.md`) 에 §AUTOFIX.md 5 의 필수 항목(수신 로그 · 판정 · 패치 요약 · 변경 합계 · 금지 자원 확인 · 커밋 전→후 · 사용량)이 모두 있음.

## 6. 복구 절차

```text
# 시험 시작 전
git rev-parse --short HEAD            # 기준 커밋 기록 (BASE)
# 시험 후 — 모두 로컬 작업
git branch -D auto/<...>              # 수정 브랜치 정리
git reset --hard <BASE>               # 적용된 수정 · revert 커밋 되돌림 (작업 트리가 깨끗할 때만)
# 러너 재시작: 수신기가 한 것과 같은 방식 또는 운영자 터미널에서 재기동
```
- `fault_lab` 두 파일은 시험 자산으로 남겨 두어도 되고(러너 미사용), 필요 없으면 별도 커밋으로 제거한다.
