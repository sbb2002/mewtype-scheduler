# 버전 태그 대조표

버전 태그(`vX.Y.Z`)가 어느 커밋 · 어느 브랜치에서 왔는지 대조하는 표. 규칙은 `main` 의 `docs/VERSION.md` 「버전 태그」와
`CLAUDE.md` 「주의점」 **버전 올릴 때 할 일**이 기준이고, 이 문서는 그 기록이다(2026-10-20 작성 — v1.0.0 · v3.0.0 ~ v3.1.2 는 기존 태그,
나머지 120개는 이날 소급).

- **들어온 브랜치**: 병합 커밋이면 커밋 제목의 브랜치 이름, 브랜치 안 커밋이면 그 커밋을 `main` 에 들인 병합의 브랜치, `main` 직접 커밋이면 `main`.
  원격 브랜치가 지워졌어도 병합 커밋 제목에 이름이 남아 있어 대조된다(「원격 브랜치」 칸 = 2026-10-20 현재 origin 에 남아 있는지).
- **진입 방식**: 병합 커밋 = 브랜치 병합 / main 직접 커밋 = 브랜치 없이 main 에 바로 커밋(v3.1 ~ v3.4 무렵에 많음) /
  브랜치 안 커밋 = 한 병합에 두 버전이 섞여 앞 버전을 브랜치 안 커밋에 붙인 것.
- **판단 메모**: 커밋 제목의 번호와 다르게 붙였거나 고른 이유가 있는 것. 빈칸은 병합 커밋 제목의 번호 그대로.
- 태그가 없는 버전: v1.1 · v1.2(기존 `v1.0.0` 태그와 시간 순서가 꼬임), v3.8.2(`main` 에 안 들어간 보류 브랜치).
- 다시 만들 때: 태그만 있으면 언제든 같은 대조가 나온다 — `git describe --tags <커밋>`(커밋 → 버전),
  `git log -1 --format=%s <태그>^{commit}`(태그 → 병합 제목의 브랜치), `git tag --merged origin/<브랜치>`(브랜치에 든 태그).
