시나리오별 흐름 v4.0 배선

탭을 누르면 그 신호가 어디를 거쳐 사이트에 닿는지 표시됩니다. 초록 테두리 = v4 에서 새로 생긴 구성요소.

쓰기 경로는 하나 — data 브랜치는 HEAD 단위로 충돌(409)하므로 콘텐츠 커밋은 전부 쓰기 서비스 POST /write (concurrency=1 · max-instances=1)가 한 줄로 서서 처리한다. 접수 서비스는 결과가 필요한 쓰기는 /write 를 동기 호출(429/503 만 지수 백오프 재시도), 결과가 필요 없는 작업은 Cloud Tasks 에 적재해 같은 /write 로 보낸다(5번째 시도에서 유실 큐 + DM 후 중단). 외부 호출(LLM · videos.list · vxtwitter · 비전)은 접수 서비스가 먼저 하고, /write 잡은 커밋만 한다.

v3 → v4 · 무엇이 달라졌나

배선(서비스 이름 · URL · Scheduler · webhook)은 그대로다. 달라진 것은 안쪽 판정 규칙, 운영 방식, 저장 위치, 화면.

preview.match_item (v3.8.10 이후 유지)

같은 채널의 예고를 같은 방송으로 합치는 시각 창. 영상 없는 예고끼리는 채널 페이지 URL 로 합치지 않고, 한쪽이 시각 미정이면 같은 JST 날짜끼리 합친다(D30).

트윗 수명 = 게시 시각 + 48h

xtweet.parse

PC · 편성 레일

가로 축은 항상 KST 06:00 ~ 익일 06:00(모니터링의 하루 경계와 같음). 멤버 5행에 방송 블록. 방송 중은 LIVE, 오늘 이미 끝난 방송은 회색(실제 시작~종료 길이), 종료 시각을 모르는 예고는 고정 폭. 블록은 호버/클릭하면 카드 팝업이 뜨고, 영상 이동은 팝업의 이미지 · 버튼으로만.

예정1시간 이내 시작방송 중종료보라 줄 = 합동

모바일 · 오늘 카드

1명씩 가로 슬라이드(스냅 · 무한 회전, 마우스 드래그도 가능) 유지. 레인 = 네임플레이트 + 오늘 카드 + ▼ 「이후 예고」 펼치기. 지금 보는 레인만 동작하고 옆 레인은 inert.

링은 상태마다 다르다: 예정 = 시작까지 남은 시간, 방송 중 = 경과 링(12시에서 시계방향으로 60분 채움 → 다음 60분 같은 방향으로 비움, 반복), 종료 = 방송 시간(회색). 합동 카드는 이미지 왼쪽 위에 참여 멤버 아바타만, 회원 전용은 🔒 알약.

트윗 알림 · 동그라미 배지

봉투 아이콘을 없애고 같은 크기의 원 하나로 정리. PC 는 타임테이블 왼쪽 멤버 칸에만, 모바일은 레인 네임플레이트에 붙는다(「이후 예고」 열에는 없음).

이후 예고 펼치기

구간 밖(익일 06:00 이후)과 시각 미정 예고를 기간 구분 없이 모아 타임테이블 아래 ▼ 버튼으로 펼친다. 0건이면 버튼도 목록도 숨김.
