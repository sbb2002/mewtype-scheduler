# Claude → Codex: 라운드 18 (이퀄라이저 ↔ 유노 움직임 박자 일치)

운영자 원문: "뒤의 이퀄라이저의 박자와 유노의 움직임 박자가 **맞아야 돼.** 지금 **따로 노는 느낌**이야."
v14(17라운드 그루브)를 바탕으로 한다. **이퀄라이저(뒤의 막대)가 유노와 같은 박 · 같은 시계로 움직이게** 한다.

- 원인 점검: 이퀄라이저는 JS 로 매 프레임 갱신(시간 `time` 기준 사인 합성 등)하고, 유노 모션은 CSS 애니메이션(`animation-delay`/`--phase`, 장면 전환 시 `time=0` 리셋)이라 **시계가 서로 다르다.** 장면 진입 시점 · 일시정지/재개 시 위상도 어긋날 수 있다. 실제 원인을 확인해서 `design_notes.md` 18라운드에 적어라.
- 해결 방향(네 판단으로 최선을 택해라): **하나의 기준 시계(박 위상)** 를 두고 유노의 모든 CSS 모션(스크래치 · 페이더 · 고개 · 꼬리 · 상체)과 이퀄라이저 JS 가 **같은 시작 시각 · 같은 BPM(100) · 같은 스윙 규칙**을 쓴다. 예: 장면 진입 시 한 시각을 기준으로 삼아 CSS 변수(`animation-delay` 음수값/Web Animations `currentTime`)와 JS 박 위상을 같은 값에서 출발시키고, 일시정지/재개/탭 숨김 복귀 때도 같이 정지/재개되게 한다. 가능하면 CSS 애니메이션도 JS 가 구동하는 한 시계에서 파생시키는 방식이 가장 확실하다.
- 이퀄라이저 동작: **막대 펄스가 박에 정렬**돼야 한다 — 킥(1·3박)에서 저음 쪽 막대가 크게 튀고, 스네어/백비트(2·4박)에서 중고음 쪽이 튀며, 스윙된 8분(오프비트)에 작은 잔물결. 유노의 2·4박 액센트(고개 · 꼬리 · 페이더 탭)와 **같은 순간에 이퀄라이저 피크**가 오도록. 17라운드에서 넣은 마이크로타이밍(±20~40ms)은 유노 몸의 레이어 사이에만 쓰고, **이퀄라이저와 유노의 액센트 사이는 오차 30ms 이내**로 맞춘다.
- 번쩍임 금지 · 정지/모션 줄이기 규칙 유지. 다른 캐릭터 · 손 구조 그대로.
- 결과 = `birthday_bg_v15.html`(`assets5/build_v15.py`, v14 이하 보존).
- 검증(숫자로): Chrome 에서 유노 장면 4마디를 `requestAnimationFrame` 으로 샘플링해 (a) 고개 까딱 최저점 시각, (b) 오른손 페이더 탭 시각, (c) 이퀄라이저 저음 막대 피크 시각을 기록하고 **세 시계열의 박 위상 오차**를 표로 보고. 일시정지→재개, 탭 전환 후 재진입에서도 어긋나지 않는지 확인. 캡처는 `qa/shots18/`. 아쉬운 점 솔직히.
