# Birthday worlds v3 — 라운드 5: 생성 일러스트 레이어 리깅

2026-10-30. 이번 산출물은 birthday_bg_v3.html이다. birthday_bg_v2.html은 수정하지 않았다. 작업 시작 때 기록한 SHA-256과 현재 값이 동일하다. 이전 SVG 캐릭터 구현은 v3에서 제거했고, 배경과 라면 봉지·조작 UI는 v2를 바탕으로 유지했다.

## 결과 파일

- birthday_bg_v3.html: 외부 리소스가 없는 단일 HTML. 캐릭터 7종의 투명 WebP를 base64 data URI로 포함한다. 현재 1,376,306바이트(약 1.38MB, 1.31MiB)로 12MB 이하.
- assets5/preview.html: 생성 일러스트 조립과 움직임을 한 번에 확인하는 검토용 갤러리.
- assets5/character_lineup.png: 일곱 캐릭터의 조립 미리보기 모음.
- assets5/{이름}_atlas.png: 이미지 생성 원본.
- assets5/{이름}_{부위}.png: 실제 투명 배경의 분리 PNG.
- assets5/{이름}_assembled_preview.png: 조립 상태 PNG.
- assets5/{이름}_prompt.txt: 도구에 전달한 전체 프롬프트. 7종 모두 보관했다.
- assets5/rigs.json: 레이어별 좌표·크기·발 기준점·귀 회전 중심.
- assets5/validation.json: 최종 브라우저·파일 검증 결과.

assets5의 검토용 원본과 PNG를 모두 합친 용량은 단일 HTML 크기 제한과 별개다. 최종 HTML은 이 폴더 없이도 이미지가 표시된다. 갤러리의 마루군 원본 비교 사진만 ../refs4 로컬 파일을 참조하며, 생일 HTML에는 그 사진을 넣지 않았다.

## 생성 방법과 입력 이미지 역할

기본 내장 image_gen 도구를 사용했다. CLI/API 우회, API 키, 다른 모델로의 전환은 사용하지 않았다. 각 캐릭터별로 한 번씩 총 7회의 투명 배경 이미지 생성을 실행했다. 생성 결과는 기본 생성 폴더에서 assets5로 복사했다.

아라레 한 종으로 생성 → alpha 검사 → PNG 분리 → 조립 → Chrome 화면 표시까지 먼저 완성하고, 그 방식을 나머지 캐릭터에 적용했다.

공통 프롬프트는 얇고 약간 유기적인 색 외곽선, 파스텔 셀 채색, 작은 몸·큰 머리, 분홍 볼, 원본 캐릭터 정체성 유지, 3D/인형/기하학적 클립아트 제외를 명시했다. 정사각형 3×3 투명 아틀라스에 별도 부위를 배치하고 글자·격자·지면 그림자를 그리지 않도록 요청했다.

기본 슬롯은 첫 줄: 뜬 눈 머리 / 같은 윤곽의 감은 눈 머리 / 몸통과 발. 둘째 줄: 왼쪽 귀 / 오른쪽 귀 / 꼬리. 셋째 줄: 왼팔 / 오른팔 / 소품이다. 오리는 귀 대신 날개, 셋째 줄은 두 발과 머리 깃털로 요청했다. 정확한 문장과 개별 디자인 조건은 각 prompt.txt가 원문이다.

생성 원본은 모두 실제 RGBA 투명 배경이었다. 마루군은 분홍 털, 길게 처진 귀, 귀의 금색 별, 가슴의 금색 별 목걸이, 손의 분홍 별, 짙은 붉은 갈색 눈, 혀를 내민 입으로 새로 생성했다. 보라 강아지 대체 도안은 사용하지 않는다.

## 부위 분리 방식

공식 참고 이미지의 픽셀을 잘라 사용하지 않았다. 새로 생성된 래스터 일러스트의 픽셀만 사용한다. PNG를 다시 SVG 도형으로 그리거나 눈·별 장식을 코드 도형으로 대체하지 않았다.

1. 생성 PNG의 alpha > 48 영역에서 연결 성분을 찾았다.
2. 큰 성분을 3×3 위치에 따라 분류하고, 아주 작은 떨어진 노이즈를 제외했다.
3. 원본 RGBA를 유지한 채 투명 마스크와 크롭만 적용해 부위 PNG를 저장했다.
4. 모델이 지시와 달리 아라레·유노·미야코의 머리에 귀를 붙여 그렸다. 이 세 종은 생성 머리 픽셀에 마스크를 적용해 귀를 별도 레이어로 분리했다. 머리 쪽에 약 5px의 겹침을 두어 작은 회전 때 틈이 벌어지는 현상을 줄였다.
5. 리츠·노노카·마루군은 별도로 생성된 귀를 머리와 조립했다. 리츠 귀가 떠 보인 첫 조립을 확인하고 귀를 아래로 내려 겹쳤다.
6. 뜬 눈·감은 눈 머리는 같은 캔버스 크기로 정렬했다. 눈 깜빡임은 두 생성 이미지의 교체다. 눈꺼풀이나 표정을 벡터로 덧그리지 않았다.
7. 몸통에도 꼬리가 중복 생성된 경우 오른쪽 중복 부분을 마스크/크롭하고 별도 꼬리를 배치했다.
8. 기타 목을 잡는 팔, 건반 위의 두 팔, 마이크·헤드셋의 위치를 조립 미리보기와 실제 장면에서 조정했다.
9. WebP quality=91, method=4, alpha 유지로 압축한 뒤 HTML에 직접 포함했다.

사용한 Python은 요청된 PNG 분리·투명 마스크·리사이즈·압축·조립을 수행한다. 일러스트를 새로 그리는 역할은 하지 않는다.

## 페이지에서 움직이는 방식

기존 배경은 SVG다. 캐릭터 위치는 기존 SVG의 좌표·패럴랙스를 유지하기 위해 foreignObject를 위치 컨테이너로 사용하고, 그 안은 실제 HTML div와 img 레이어다. 캐릭터를 구성하는 SVG path·ellipse·circle는 없다. SVG 지면 그림자와 배경 소품은 별개다.

- 몸통: 6초 주기의 아주 작은 호흡.
- 머리: 11초 주기의 약 1도 갸웃.
- 귀: 9초 주기, 최대 약 3도.
- 꼬리: 8초 주기, 약 3도.
- 팔/날개: 6초 주기, 약 2도. 기타 앞발의 작은 움직임으로 스트럼 인상을 준다.
- 눈: 7.6초 주기로 열린 머리와 감긴 머리 생성 프레임을 짧게 교체한다.
- 같은 장면의 세 캐릭터가 동시에 호흡하고 눈을 감지 않도록 호흡·머리·눈의 위상을 조금 다르게 줬다.
- 유노 앞팔은 데크 뒤에 가려지지 않도록 같은 래스터 앞팔을 전경에 한 번 더 배치했다. 본체와 같은 호흡 위상을 사용한다.
- 마이크·기타·건반은 별도 생성 PNG다. 헤드셋은 머리 내부 레이어라 머리와 함께 기울어진다. 마루군의 별은 생성된 귀·몸·팔의 일러스트 픽셀에 포함되어 있다.
- 오리는 귀가 없으므로 날개·꼬리·발을 분리하고 날개를 천천히 움직인다.

이는 2D 컷아웃 리깅이다. 생성 일러스트가 변형·회전하는 방식이며, 골격 기반 메시 변형이나 관절 각도별 새 프레임을 대량 생성한 애니메이션은 아니다. 실제 악기 운지의 정확한 재현은 하지 않았다.

## 배경·기능 유지

노란 초원과 라면 봉지 / 붉은 유노 아웃런과 이퀄라이저 / 푸른 구름 호수와 음식·별 궤적 / 보라 달빛 정원 / 분홍 음악방을 유지했다. 새 캐릭터가 그려진 뒤에도 접촉 그림자와 레이어별 작은 패럴랙스가 적용된다. 세 친구의 크기는 각 생성 부위의 캔버스가 커져 미야코 1.35, 오리 0.8, 마루군 0.85로 조정했다.

신라면 벡터·blur 0.75, 유노 격자의 느린 속도, 리츠의 5.2초 궤적, 폭죽·움직임 멈춤·배경 끄기·탭·키보드 UI를 유지한다. 시스템 모션 줄이기는 모든 그림 리깅·JS 프레임·패럴랙스·폭죽을 정지한다. 감은 눈 프레임이 아닌 뜬 눈 정지 장면으로 표시한다. 숨김 탭에서는 CSS와 RAF를 모두 멈추고 경과 시간을 보충하지 않는다.

## 검증

- Chrome에서 다섯 장면의 모든 래스터 img가 정상 로드됨을 확인했다. 모든 캐릭터 img src는 data:image/webp;base64다.
- 머리 transform이 실제 시간 경과에 따라 변하는 것을 확인했다.
- 아라레의 감은 눈 프레임에서 열린 눈 opacity=0, 감은 눈 opacity=1을 확인했다. 귀 최대 회전 프레임도 렌더해 접합부를 검토했다.
- 미야코 오른쪽에 새 분홍 마루군이 표시되는 실제 장면을 확인했다.
- 일시정지 시 CSS paused, RAF 정지, 폭죽 버튼 비활성화. 배경 끄기 시 숨김. 합성 visibility 이벤트에서 RAF 정지.
- 모션 줄이기 시 animation 0개, 열린 눈 opacity=1 / 감은 눈 opacity=0.
- 리츠 궤적 주기 5.2초, 폭죽 렌더 후 3초 이내 소거.
- 320 / 375 / 414 / 768px 가로 넘침 없음. 375px의 다섯 장면 렌더도 확인했다.
- 런타임 예외 0건, 외부 네트워크 요청 0건. v2 SHA-256 동일.
- HTML 1,376,306바이트로 12MB 미만. assets5/validation.json에 자세한 결과를 저장했다.
- 실제 Claude 아티팩트와 Safari, 저사양 휴대폰의 FPS·발열은 아직 확인하지 않았다. 숨김 탭 검사는 합성 이벤트이며 실제 모바일 앱의 백그라운드 전환과는 구분한다.

## 남은 차이·막힌 점

안전 정책 거부나 도구 실패로 막힌 부분은 없었다. 다만 생성 도구가 부위 분리 지시를 완전히 따르지는 않아 귀 마스크와 중복 꼬리 정리가 필요했다.

원본과 완전히 같다고 주장하지 않는다. 직접 생성한 그림이라 다음 차이가 남는다.

- 아라레: 참고보다 외곽선이 조금 굵고, 표정·소매·넥타이 세부가 다르다.
- 유노: 두 톤 머리와 점퍼 라펠은 가까워졌지만 귀 윤곽·머리 곡선·헤드셋 크기가 정확히 같지는 않다.
- 리츠: 귀 안쪽을 분홍으로, 목 장식을 푸른 리본으로 생성했다. 작은 원본에서 확인되지 않은 의상·기타 세부는 생성 해석이다.
- 미야코: 원본의 거친 보라 머리 방향은 반영했지만 눈·입과 털 다발은 다르며, 본래 루프보다 더 귀엽고 풍성하다.
- 노노카: 원본과 의상·기타 형태가 완전히 같지 않다. 토끼 귀와 프릴은 이전 SVG보다 참고에 가까운 생성 결과다.
- 마루군: 분홍 털과 모든 주요 별 장식을 반영했으나 털 곡선·별의 정확한 위치·귀 길이는 원본과 다르다. 분홍 캐릭터인 점은 교정했다.
- 오리: 공식 참고가 없으므로 같은 화풍의 창작 동물이다.
- 열린/감긴 머리는 별도 생성 프레임이므로 교체 시 윤곽이 미세하게 달라질 수 있다. 작은 움직임을 넘어서 관절을 크게 꺾으면 컷아웃 접합부가 드러날 수 있어 회전 폭을 제한했다.

## 재생성 없이 조립을 다시 빌드할 때

원본 아틀라스와 전체 프롬프트는 assets5에 보존되어 있다. 리츠 이후 부위 추출은 extract_atlases.py, 마스크·리깅 좌표는 prepare_parts.py, WebP 내장 HTML 빌드는 build_v3.py다. 아라레는 초기 파이프라인에서 추출한 원본 부위 PNG를 함께 보관한다.

명령 순서:
1. python assets5/extract_atlases.py
2. python assets5/prepare_parts.py
3. python assets5/build_v3.py
4. node assets5/validate_v3.cjs

이미지 생성 자체를 다시 실행하는 명령은 포함하지 않았다. 생성은 내장 도구로 수행했으며 각 prompt.txt와 atlas.png가 기록이다.
