# 리츠 생일 오르기 게임 — 움직임 시제품 · 레벨 편집기

명세 = devpapers `ref/ritsu-climb/MVP_SPEC.md` (구현 결과 §12, 편집기 §13, 물리 v2 · 고급 설정 §15). **main 병합 · 배포 대상 아님.**
도형(원 · 선)만으로 만든 시험판이다. 그림(스킨) · 보상 · 사이트 이식은 아직 없다.

## 파일

| 파일 | 내용 |
|---|---|
| `climb-logic.js` | 물리 계산 · 레벨 검사(DOM 없음). 게임 · 편집기 · 검증이 모두 이 파일을 쓴다 |
| `proto.html` | 게임(PC 마우스 · 폰 터치) |
| `editor.html` | 레벨 편집기(PC 전용) — 지형 · 미끄러운 면 · 출발점 · 골인 영역을 그린다 |
| `levels/*.json` | 레벨 파일. `sample.json` = 기본 코스와 같은 내용, `curve-demo.json` = 곡선 지형 예시(아치 · 원 바위 · 휜 미끄럼 비탈 — 모양 예시이고 완주는 확인하지 않았다) |
| `sim.cjs` | Node 검증 — `node sim.cjs`(문법 · 기본 코스 검사 + 합격 기준 1~11), `node sim.cjs route route.json`(봇 조작 기록) |
| `route.json` | 검증 봇의 기본 코스 완주 조작. `?replay=1` 이 재생한다. 기본 코스 · 물리를 바꾸면 위 명령으로 다시 만든다. 봇은 도구 가속도 60000(사실상 즉시)으로 돈다 — 기본 가속도용 봇 조작은 아직 없다 |

## 여는 법

```bash
cd easteregg/ritsu-climb
python -m http.server 8110 --bind 0.0.0.0
# 게임    http://localhost:8110/proto.html       (폰: http://<PC 의 Tailscale 주소>:8110/proto.html)
# 편집기  http://localhost:8110/editor.html
```
이 PC 방화벽은 8081~8112 포트만 열려 있다. 편집기의 「시험 플레이」는 게임과 **같은 주소(같은 서버)** 에서 열어야 레벨이 넘어간다.

게임 주소 뒤에 붙이는 것:

| 붙임 | 효과 |
|---|---|
| `?level=이름.json` | `levels/` 폴더의 레벨로 시작 |
| `?test=1` | 편집기 「시험 플레이」가 넘긴 레벨로 시작(편집기가 알아서 연다) |
| `?debug=1` | 조정값 슬라이더(화면 확대 포함, 이 탭에만 적용) · 팔 길이 원 · 목표점 · 접촉 방향 · 물리 계산 시간 · 한 단계 조각 수. 폰은 「조정」 버튼으로 연다 |
| `?view=pc` · `?view=mobile` | 화면 확대를 PC 값 · 폰 값으로 강제(평소엔 터치가 주 입력이면 폰) |
| `?input=rel` | 이동량 방식 — 포인터를 움직인 양만큼 도구가 움직인다 |
| `?replay=1` | 검증 봇의 기본 코스 완주 재생(약 48초) |

## 게임 조작

- PC: 마우스를 움직이면 도구 끝이 커서 쪽으로 간다(누를 필요 없음). 폰: 누른 채 움직이면 손가락 쪽으로 간다. 손을 떼도 유지.
- 끝을 땅에 **눌러 짚어야** 붙는다. 짚은 채 반대로 당기면 몸이 끌려가고, 빠르게 휘두르면 튕겨 오른다.
- 지형 맨 아래보다 15m 넘게 떨어지면 출발점에서 다시 시작한다(떨어짐 1회).

## 레벨 만들기 (편집기)

1. `editor.html` 을 연다. 처음엔 기본 코스가 열려 있다(「새로」 = 바닥 하나만 있는 빈 레벨, 두 번 눌러야 바뀐다).
2. 도구로 그린다 — 사각형(R) · 다각형(P) · 원(C) · 재질 칠하기(M) · 출발점(S) · 골인 영역(G) · 선택(V). 조작은 편집기 오른쪽 「조작」 칸.
   **회전**: 선택한 지형 위쪽의 둥근 손잡이를 끌어 돌린다(격자 맞춤 켜짐 = 15° 씩, Alt = 자유롭게). Q · E = 15° 씩, Shift+Q · E = 1° 씩, 버튼도 있다. 축 = 지형을 감싸는 사각형 가운데, 곡선 조절점도 같이 돈다. 돌린 좌표는 0.1u 로 반올림(격자에는 안 맞춘다).
   **곡선**: 선택 도구로 지형을 고르면 변마다 가운데에 주황 원(손잡이)이 생긴다. 끌면 그 변이 그 점을 지나는 곡선으로 휘고, 더블클릭하면 다시 곧게. 곡선 변을 더블클릭하면 모양 그대로 꼭짓점이 하나 생긴다.
3. 오른쪽 「검사」가 문제를 알려 준다. 누르면 그 자리로 화면이 간다.
   - **두께 60u 미만**(주의, 빨간 원) — 도구 끝이 뚫을 수 있다.
   - **꼬인 다각형 · 납작한 다각형**(오류) — 충돌이 틀어진다.
   - 출발점이 지형과 겹침 · 골인 영역 없음 · 골인 영역이 몸통보다 좁음(주의).
4. 「시험 플레이」(T) — 새 탭에서 바로 해 본다. 고치고 다시 누르면 그 탭이 새 레벨로 다시 열린다.
   **고급 설정**(오른쪽 칸 접힌 상자) — 이 레벨의 조작감 · 화면 확대. 레벨 파일에 저장되고 게임이 그 레벨을 열 때 적용된다.
   - 조작감: 도구 가속도 · 도구 최고 속도 · 몸통 최고 속도 · 순간이동으로 볼 거리 · 순간이동 때 따라가는 속도
   - 화면 확대: PC · 폰 따로 「화면 짧은 변에 보이는 길이(u)」. 클수록 넓게 보인다. 폰은 손가락 위치로 조작하므로 넓게 볼수록 더 민감해진다
   - 「출발점에서 보이는 화면 크기 미리보기」 = PC 1280×800 · 폰 390×844 기준 화면 테두리
   - 슬라이더는 어떤 값이어도 뚫림이 없도록 물리가 알아서 잘게 나눠 계산한다(아래 「물리 v2」)
5. 「파일로 저장」 → 저장 창에서 이 폴더의 `levels/` 를 고르면 바로 `proto.html?level=그파일.json` 으로 열린다. 작업 중인 레벨은 브라우저에 자동 저장된다(다른 브라우저 · PC 로 옮기려면 파일로).
   **저장 · 불러오기 위치는 같다**(Chrome · Edge) — 두 창이 마지막으로 저장하거나 불러온 폴더를 함께 기억해 늘 거기서 열린다(브라우저를 껐다 켜도 유지). 처음 한 번만 `levels/` 를 찾아 들어가면 된다. Firefox · Safari 는 저장 = 내려받기 폴더, 불러오기 = 브라우저 기본 창.

### 레벨은 어디에 남나

| 곳 | 무엇 | 사라지는 경우 |
|---|---|---|
| 브라우저 저장소 `climb-editor-level` | 편집 중인 레벨(바꿀 때마다 자동 저장) | 브라우저 사이트 데이터 삭제 · 다른 브라우저 · 다른 PC · **다른 주소/포트**(localhost:8110 과 127.0.0.1:8110 도 서로 다른 저장소) |
| 브라우저 저장소 `climb-editor-test` | 「시험 플레이」 때 게임에 넘긴 사본 | 다음 「시험 플레이」 때 덮어쓴다 |
| 저장 창에서 고른 폴더의 `이름.json` | 「파일로 저장」한 파일(Firefox · Safari 는 내려받기 폴더) | 직접 지우기 전까지 |
| `levels/이름.json` (+ git 커밋) | 게임이 `?level=` 로 여는 파일, 저장소에 남는 정본 | — |

반영 순서: 편집기에서 그림 → 「시험 플레이」로 바로 확인 → 「파일로 저장」(저장 창에서 `levels/`) → `proto.html?level=이름.json` 으로 확인 → 커밋.
게임의 기본 코스(주소에 아무것도 안 붙였을 때)는 `climb-logic.js` 의 `COURSE` 이고, 파일을 넣는 것만으로는 바뀌지 않는다.

길이 단위 u: 몸통 반지름 28u, 팔 길이 40~150u, 100u = 1m. 「커서에 몸통 · 팔 길이 원」을 켜면 닿는 거리를 보며 그릴 수 있다.

## 레벨 파일 형식

```json
{
  "version": 1,
  "name": "레벨 이름",
  "start": [-450, -28],
  "goal": { "x0": -700, "y0": -1230, "x1": -380, "y1": -1100 },
  "polys": [
    { "mat": "rock", "pts": [[-700, 0], [700, 0], [700, 400], [-700, 400]] },
    { "mat": "rock", "edgeMat": { "2": "slick" }, "pts": [[380, -400], [610, -400], [610, -1000], [380, -1100]] },
    { "mat": "rock", "curve": { "0": [0, -400] }, "pts": [[-450, 0], [450, 0], [450, 60], [-450, 60]] }
  ]
}
```
- 좌표는 u, **y 는 아래가 +** (화면과 같은 방향). 출발 바닥 윗면을 y 0 으로 두면 높이 표시가 맞다.
- `start` = 몸통 중심. `goal` = 몸통 중심이 1초 머물면 골인인 사각형(없으면 `null`).
- `polys` = 닫힌 다각형(꼭짓점 순서대로, 마지막 → 첫 점이 자동으로 이어진다). `mat` = `rock`(바위) · `slick`(미끄러움).
  `edgeMat` = 그 다각형에서 재질이 다른 변 — 키 `"i"` = 꼭짓점 i → i+1 변.
  `curve` = 휜 변 — 키 `"i"` 의 값 `[cx, cy]` = 꼭짓점 i → i+1 을 잇는 2차 베지어 곡선의 조절점(곡선은 조절점 쪽으로 휘고, 가운데 점 = 양 끝 가운데와 조절점의 중간).
  게임은 곡선을 약 12u 길이의 짧은 변들로 쪼개 충돌시킨다(`climb-logic.js flattenPoly`). 위 예시의 마지막 지형 = 윗변이 꼭대기 y -200 까지 솟은 아치.
- `view`(없으면 기본) = `{ "pc": 680, "mobile": 680 }` — 화면 짧은 변에 보이는 세계 길이(u), 300~2000. 680 = 예전 배율(팔 최대 길이가 짧은 변의 22%).
- `physics`(없으면 기본) = 처음 값과 다른 조정값만. 쓸 수 있는 이름과 범위는 `climb-logic.js LEVEL_PHYSICS` — `TOOL_ACCEL` 2000~60000 · `TOOL_SPEED` 400~4000 · `MAX_BODY_SPEED` 400~3000 · `JUMP_DIST` 40~600 · `REPOSITION_SPEED` 200~4000. 범위 밖은 잘라 읽고, 목록에 없는 이름은 버린다.
- 그림은 넣지 않는다. 스킨은 나중에 이 지형 데이터 위에 씌운다.

## 물리 v2 (2026-11-03)

| 바뀐 것 | 내용 | 처음 값 |
|---|---|---|
| 도구 가속도 | 도구 끝이 목표로 갈 때 순간 최고 속도가 아니라 가속해서 오르고, 목표 가까이서 같은 가속도로 줄여 멈춘다. 끝이 막혀 못 움직이면 그만큼 기세를 잃는다 | `TOOL_ACCEL` 16000 u/s²(0.1초에 최고 속도) |
| 속도 제한 | 도구 최고 속도 · 몸통 최고 속도(전과 같음) | 1600 · 1400 u/s |
| 목표점 순간이동 제한 | 목표가 한 번에 `JUMP_DIST` 넘게 바뀌면(폰에서 다른 곳을 새로 누름 · 커서가 튐) 그 자리로 바로 가지 않고 `REPOSITION_SPEED` 로 따라간다. 이어서 빠르게 휘두르는 동작에는 걸리지 않는다 | 120u · 500 u/s |
| 뚫림 방지 | 한 계산 단계에 도구 끝이 25u(가장 얇은 지형 60u 의 절반 아래) 넘게 움직일 수 있으면 그 단계를 잘게 나눠 계산한다. 처음 값에서는 나누지 않는다 | — |

- 처음 값들은 Claude 가 정한 시작값이다. 원작의 실제 수치는 확인하지 못했다 — 운영자가 편집기 고급 설정으로 맞춘다.
- 도구 자루(막대)는 지금도 지형과 부딪히지 않는다(운영자 결정 2026-11-03 — 끝 · 몸통만).
